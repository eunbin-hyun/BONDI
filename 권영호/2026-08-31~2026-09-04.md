# 1부. 자료 서버 계획서

## 1.1 문제 — 목록이 없으면 "없는 것"을 못 찾는다

팀 3D 자료가 Drive에 zip으로 쌓여 있다. 겪은 불편을 먼저 적고 시작했다.

| 문제 | 구체적인 상황 |
|---|---|
| 뭐가 들었는지 모른다 | `bon004740_restored.zip` 185MB를 통째로 받아 풀어야 OBJ인지 PLY인지 안다 |
| 하나만 필요해도 전부 받는다 | PLY 하나가 필요한데 OBJ·8K 텍스처·STL까지 온다 |
| 누가 어떻게 만들었는지 없다 | `_restored`가 어떤 방식의 결과인지 파일명만으로는 모른다 |
| 비교가 번거롭다 | 원본·복원본 비교하려면 zip 두 개를 받아 각각 푼다 |
| 누락을 눈치채지 못한다 | `duk003312_restored.zip`은 있는데 원본 `duk003312.zip`이 없다 |

마지막이 핵심이었다. **목록이 없으면 "없는 것"을 발견할 수 없다.** 저장소 문제가 아니라 카탈로그 문제다.

## 1.3 artifact → variant → file

가장 오래 고민한 부분이다. "폴더 하나 = 자료 하나"로 평평하게 두면 원본과 복원본을 나란히 비교할 수 없다.

| 층위 | 뜻 | 예 |
|---|---|---|
| **artifact (유물)** | 하나의 실물 유물 | `bon004740`, `RR_07_01_EA_028` |
| **variant (변형)** | 그 유물의 한 버전 | `source`, `restored`, `pointr_restored` |
| **file (파일)** | 변형 안의 개별 파일 | `digital_obj/bon004740-000-30000.obj` |

**원본과 복원본을 같은 artifact 아래 다른 variant로 둔 것**이 핵심이다. 이렇게 하면 비교 화면이 별도 기능이 아니라 데이터 구조에서 자동으로 나온다. 별개 항목으로 뒀다면 둘을 잇는 관계 테이블을 따로 만들어야 했다.

# 2부. 서버 설치 구성 — Nginx·systemd

## 2.1 스택 선택

| 후보 | 채택 | 이유 |
|---|---|---|
| Docker Compose | ✗ | 서버 한 대, 서비스 한 개. 빌드·레지스트리 비용이 이득보다 크다 |
| Nginx + systemd | ✔ | 정적 파일은 Nginx가 압도적으로 빠르고 프로세스 관리는 systemd로 충분 |
| PostgreSQL | ✗ | 유물 수십~수백 개, 동시 쓰기 사실상 없음 |
| SQLite (WAL) | ✔ | 파일 하나. 백업이 `cp` |
| Node/Vite 빌드 | ✗ | 빌드 산출물을 올리는 단계가 늘어난다 |

**"서버 한 대 · 사용자 여덟 명 · 쓰기 거의 없음"이면 대부분의 인프라 도구는 순손실**이다. 도구를 고를 때 규모를 먼저 적어야 한다.

## 2.2 역할 분담 — 무엇을 Nginx가, 무엇을 앱이

```text
브라우저
  ├─ GET /                  → Nginx → web/index.html
  ├─ GET /files/<...>.obj   → Nginx 직접 (앱을 거치지 않는다)
  ├─ GET /preview/<...>.glb → Nginx 직접
  └─ GET /api/artifacts?q=  → Nginx → proxy_pass 127.0.0.1:8000 → FastAPI → SQLite
```

**62MB짜리 OBJ가 앱 프로세스를 통과하지 않게 하는 것**이 핵심이다. FastAPI `FileResponse`로도 동작하지만 uvicorn 워커가 전송 시간 내내 묶인다.

## 2.3 조용히 깨지는 설정 두 가지

### `alias` 안의 중첩 `location`은 `add_header`를 상속하지 않는다

Nginx의 `add_header`는 **하위 블록에 `add_header`가 하나라도 있으면 상위 것을 전부 버린다.** 상속이 아니라 교체다.

```nginx
location /files/ {
    alias /srv/catalog/files/;
    autoindex on;
    gzip_static on;
    add_header Access-Control-Allow-Origin *;

    location ~* \.(obj|mtl|ply|stl|las)$ {
        add_header Content-Disposition 'attachment';
        add_header Access-Control-Allow-Origin *;   # ← 다시 적어야 한다
        gzip_static on;                             # ← 이것도 다시
    }
}
```

바깥에 적었으니 되겠지 하고 넘어가면 CORS가 조용히 깨진다.

### `gzip_static`은 `.gz`의 mtime을 본다

`.gz`가 원본보다 오래되면 **무시한다.** 원본을 다시 만들면 `.gz`도 반드시 다시 만든다.

둘 다 **오류를 내지 않고 그냥 동작하지 않는다.** 그래서 설정마다 확인 명령을 문서에 같이 적어뒀다.

```bash
curl -sI http://j15c201.p.ssafy.io/files/<경로>.obj | grep -i "access-control\|content-encoding"
```

## 2.4 압축 대상 판정 — 확장자만으로는 부족하다

PLY와 STL은 같은 확장자로 ASCII·바이너리가 둘 다 존재한다.

| 확장자 | 압축 | 판정 |
|---|---|---|
| `.obj` `.mtl` `.json` | ✔ | 항상 텍스트 |
| `.ply` | 조건부 | 첫 300바이트에 `format ascii` |
| `.stl` | 조건부 | `solid`로 시작하고 **크기 ≠ 84 + 50×삼각형수** |
| `.las` | ✔ | 1.5~2배 줄어든다 |
| `.jpg` `.png` `.glb` | ✗ | 이미 압축됨 |

바이너리 STL은 80바이트 헤더 + 4바이트 삼각형 수 + 삼각형당 50바이트로 **크기가 정확히 결정**되므로 계산값과 비교하면 된다. 바이너리 STL도 헤더가 우연히 `solid`로 시작할 수 있어 문자열 검사만으로는 틀린다.

```python
def is_ascii_stl(path):
    with path.open("rb") as f:
        if f.read(5) != b"solid":
            return False
        f.seek(80)
        n = int.from_bytes(f.read(4), "little")
    return path.stat().st_size != 84 + 50 * n
```

## 2.5 그 밖에 정리한 것

- `.glb`는 Nginx 기본 MIME에 없다 → `types { model/gltf-binary glb; }` 추가.
- `Content-Disposition: attachment`를 걸어도 **뷰어의 `fetch()`는 영향을 받지 않는다.** 이 헤더는 최상위 내비게이션에만 작용한다.
- `autoindex`는 보통 끄는 설정이지만 **의도적으로 켰다**(AS-04). 켜는 게 맞는 상황이 있다는 것과 그 판단을 문서에 남기는 것이 중요하다.
- systemd `ExecStart`는 **절대경로**여야 한다. systemd는 로그인 셸이 아니라 `PATH`에 `~/.local/bin`이 없다.
- `enable --now`가 `enable` + `start`다. `enable`만 하면 지금 안 뜨고, `start`만 하면 재부팅 후 안 뜬다.
- ufw 작업 전 **SSH 세션을 2개 이상** 열어둔다. **22번은 건드리지 않는다.**
- 로컬에 rsync가 없어 `tar | ssh` 파이프로 투입한다. 증분이 필요해지는 시점에 WSL을 도입한다.

# 3부. 데이터 정리 — 신원 확정과 정규화

## 3.1 문제 — 파일이 자기가 뭔지 모른다

```text
bon004740.zip   bon004740_restored.zip   duk003312_restored.zip   lkh000002.zip
```

`bon004740`이 무슨 유물인지 파일 어디에도 없다. **자산 서버를 만들어도 이름을 모르면 검색이 안 된다.** 접두어부터 해석했다.

| 접두어 | 뜻 | 접두어 | 뜻 |
|---|---|---|---|
| `bon` | 본관 | `ssu` | 신수 |
| `duk` | 덕수 | `lkh` | 이건희 |
| `don` | 동원 | `gae` | 개인 |
| `goj` | 고적 | `kno` | 경주 |

**소장품 등록번호**였다. 그러면 박물관 공개목록과 맞출 수 있다.

## 3.2 박물관 3D 목록 스크래핑

```text
목록  ?cp=<페이지>&pageSize=12
상세  ?schM=view&searchId=search&relicId=<id>
영문  /ENG/contents/E0403000000.do?schM=relic_represent_view&relicId=<id>
```

`pageSize`를 100으로 올려도 **서버가 12로 고정**한다. 파라미터를 준다고 서버가 따르는 건 아니다. `cp=1..12`로 순회해 130건을 얻었다.

**정규식으로 `<li>`를 자르려다 실패했다.**

```python
re.findall(r'<li class="card threeddata">(.*?)</li>', t, re.S)   # 틀림
```

카드 안에 `<li>`가 중첩되어 **첫 안쪽 `</li>`에서 잘렸다.** 정규식은 중첩 구조를 못 센다. 문자열 분할로 바꿨다.

```python
for c in t.split('<li class="card threeddata">')[1:]:
    rid = re.search(r"relicId=(\d+)", c)
    nm  = re.search(r'class="tit">(.*?)</strong>', c, re.S)
    img = re.search(r"/relic_image/[^\"]*/([a-z]{2,4}\d{3,6})[-_ ]", c)
```

소장품번호는 본문이 아니라 **썸네일 이미지 경로**에서 뽑았다. 목록에 번호가 노출되지 않았기 때문이다.

## 3.3 영문명 — 한글을 잃지 않는 방법

번역기 대신 **박물관 영문 페이지의 공식 표기**를 가져왔다.

| 영문명 출처 | 건수 |
|---|---:|
| 박물관 공식 영문 표기 | 97 |
| 한글명에서 직접 지정 | 3 |
| 영문 페이지 없음 | 29 |

동시에 얻은 `Designation`(지정문화재) 78건이 결정적이었다. **국보 78호와 83호 반가사유상은 영문명이 둘 다 "Pensive Bodhisattva"**라 슬러그가 충돌한다. 지정번호를 꼬리표로 붙여 갈랐다.

```text
bon002789_pensive-bodhisattva-nt78    금동 반가 사유상   (국보 78)
duk003312_pensive-bodhisattva-nt83    금동 반가사유상    (국보 83)
```

한글 식별은 **세 겹**으로 남겼다.

```text
① 폴더 안 `_금동 반가 사유상.md`   ← 탐색기에서 폴더 열면 바로 보인다
② `_meta.json` 의 name_ko          ← 프로그램이 읽는다
③ 루트 INDEX.md / INDEX.csv        ← 142건을 한 표로 훑는다
```

**사람이 보는 곳·기계가 읽는 곳·전체를 훑는 곳을 각각 따로 두는 것**이 요령이었다.

## 3.4 압축 해제에서 만난 것들

**zip 엔트리명이 CP949.** 한국에서 만든 zip은 UTF-8 플래그(`0x800`)가 없어 Python이 CP437로 디코딩해 한글이 깨진다.

```python
if not (i.flag_bits & 0x800):
    n = i.filename.encode("cp437").decode("cp949")
```

**zip 안에 zip.** 일부는 `디지털콘텐츠_OBJ/<번호>.zip`으로 한 겹 더 압축돼 있었다. 크기만 보고 넘어갔으면 OBJ가 통째로 빠졌을 것이다.

**MTL의 절대경로가 깨져 있다.** 제작 PC 경로가 그대로 굳었다.

```mtl
map_Kd ./:/2023년도 국립박물관 소장품 3D 데이터 구축/.../bon004740.jpg
```

`map_*`·`bump`·`disp`·`decal`·`norm`·`refl`을 전부 찾아 파일명만 남겼다. **`norm`을 첫 시도에서 빠뜨려** 노멀맵만 깨졌었다. OBJ의 `mtllib`도 옛 이름을 가리켜 같이 재작성했다.

**유물명에 줄바꿈이 들어 있다.** `청자인형\n\n사람모양청자` 같은 항목에서 `open()`이 `OSError [Errno 22]`로 죽었다. **외부에서 온 문자열은 파일명으로 쓰기 전에 반드시 정제한다.**

```python
safe = re.sub(r'[\\/:*?"<>|\r\n\t]', " ", kn)
safe = re.sub(r"\s+", " ", safe).strip()[:80] or meta["artifact_id"]
```

# 4부. Unreal MCP — 에디터 제어와 절차적 메시 생성

## 4.1 설정

UE 5.8에는 `ModelContextProtocol` 플러그인이 **내장**되어 있다(Experimental).

```json
{ "Name": "ModelContextProtocol", "Enabled": true,
  "SupportedTargetPlatforms": [ "Win64" ] },
{ "Name": "AllToolsets", "Enabled": true }
```

`SupportedTargetPlatforms`를 Win64로 제한한 이유는 **Android 패키징에 딸려 들어가지 않게** 하기 위해서다.

```ini
; Config/DefaultEditorPerProjectUserSettings.ini
[/Script/ModelContextProtocolEngine.ModelContextProtocolSettings]
bAutoStartServer=True
ServerPortNumber=8000
ServerUrlPath=/mcp
```

`Saved/` 아래 ini에 쓰면 **에디터가 종료할 때 덮어쓴다.** `Config/Default*`에 둬야 유지된다. 에디터 재시작 + 클라이언트 세션 재시작을 **둘 다** 해야 붙는다.

## 4.4 절차적 지형

처음 산은 Cone 액터라 누가 봐도 모형이었다. 하이트필드를 계산해 메시로 바꿨다.

| 요소 | 역할 |
|---|---|
| **value noise + fBm** | 옥타브 5, lacunarity 2.03. 완만한 기복 |
| **ridged multifractal** | `n = 1 - abs(2n-1)`, 제곱. **능선**을 만든다. 없으면 둥근 언덕만 나온다 |
| **도메인 워핑** | 좌표를 노이즈로 밀어 격자 흔적을 지운다 |
| **radial window** | 산자락을 지면에서 닫는다 |
| **고도·경사 분류** | 면마다 rock / forest를 나눠 OBJ 2개로 내보내고 다른 재질을 입힌다 |

암릉과 육산의 차이는 fBm과 ridged의 **혼합 비율 하나**로 조절했다 — 북한산은 암릉 쪽, 남산은 육산 쪽.

**가장자리에서 고생했다.** 산을 평지에 얹으니 밑동에 검은 얼룩이 남았다(z-fighting). 창 함수로 눌러 **지면 아래로 가라앉히니** 해결됐다.

```python
win = 1.0 - smoothstep(0.70, 0.90, r)
z   = zs[i][j] * k * win - 30.0 * smoothstep(0.76, 0.94, r)
```

즉 **가장자리를 0으로 만드는 것으로는 부족하고 음수로 내려야 한다.**

![남산 능선과 N서울타워 — ridged multifractal 지형](./images/2026-09-04-unreal-namsan.png)

남산은 정상에 **반경 62m 평탄면**을 넣었다. 그러지 않으면 뾰족한 봉우리 위에 N서울타워를 세울 자리가 없다. 지형 생성기에 "구조물이 설 자리"를 파라미터로 넣어야 한다.

## 4.5 함정 세 가지 (직접 당함)

1. **`set_actor_transform`에 `location`만 넘기면 scale이 1로 리셋된다.** 문서는 "미지정 필드는 변경하지 않는다"고 하지만 실제로는 초기화된다. N서울타워 21개 부재가 전부 1m로 쪼그라들었다. → 이동만 할 때도 `get_actor_transform`으로 기존 scale을 읽어 함께 넘긴다.
2. **`import_file`은 동명 에셋을 덮어쓰지 않는다**(`already exists`). → 참조 액터 제거 → `AssetTools.delete` → 재임포트 → 재배치.
3. **스크립트 문자열이 길면 MCP 입력 JSON 파싱이 깨진다.** 9KB 근처에서 실패했다 → 작업을 나눠 보낸다.

`CaptureViewport` 응답은 base64 PNG라 1~2MB다. 파일로 저장해 디코딩해야 하고, `annotations` 필드는 기본값이 없어 생략할 수 없다.

# 5. 이번 기간의 결론

**설계에서 배운 것은 기술이 아니라 순서였다.**

1. 겪은 불편을 먼저 적는다 (요구사항을 상상하지 않는다)
2. 결정을 번호로 못박고 **그 결정이 없앤 작업량**을 함께 적는다
3. 완료 기준을 구현 전에 쓴다
4. 범위 경계를 문서에 적어 스스로를 막는다

**자산 정리는 파일을 옮기는 일이 아니라 신원을 확정하는 일이었다.** 파일 자체에는 정보가 거의 없어서 외부 권위 있는 목록과 맞춰야 이름이 생긴다. 영문으로 정규화하되 한글을 잃지 않는 경로를 세 겹으로 남겨야 실제로 쓸 수 있다. 그리고 **참조를 고치면 참조를 검사한다.**

**엔진 쪽에서는 "문서와 실제 동작이 다를 수 있다"가 가장 큰 수확이었다.** 팀 제약 목록의 "임포트 불가"가 사실과 달랐고, `set_actor_transform`도 문서와 반대로 동작했다. **제약 목록은 한 번 적으면 재검증되지 않는다**는 걸 확인했다.

세 부분이 이렇게 이어진다.

```text
자료 서버 설계 (1~2부) ─┐
                        ├→ 정규화된 자산이 서버에 올라가고
자산 정규화 (3부)      ─┘   그중 복원본을 엔진으로 임포트한다 (4부)
```
