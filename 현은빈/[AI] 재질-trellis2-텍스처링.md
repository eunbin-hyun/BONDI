## 0. 한 줄 요약

**형상 축과 재질 축을 분리하면 TRELLIS 를 안전하게 다시 쓸 수 있다.**
SLAT 주입([slat-임계-실험.md](%5BAI%5D%20slat-%EC%9E%84%EA%B3%84-%EC%8B%A4%ED%97%98.md))은 형상을 생성하게 두어서 조각났다.
여기서는 **완성된 메시를 주고 속성만 받는다.** 정점 거리 중앙·p95 가 정확히 `0.00e+00` 이다.

그리고 재는 과정에서 지표가 두 번 뒤집혔다.

1. **단일 고주파 값은 틀린 지표다.** 1024 가 512 를 이기는데 눈 판정은 512 였다.
   파워 스펙트럼 **대역 거리**로 바꾸니 순위가 눈과 같아졌다
2. **색 평균을 맞추는 연산이 질감을 망친다.** RGB 채널 이득은 편차까지 곱해서
   `a` 채널 질감 거리를 9배로 키웠다. **Lab 평균 평행이동(v32)** 이 답이다

---


**왜.** 형상은 v24 로 끝났는데 **재질이 최근접 복사**라 채움면에 얼룩이 남는다
(`채움색-최근접-vs-LaMa.png`). 그리고 SLAT 형상 경로를 닫으면서
[slat-임계-실험.md](%5BAI%5D%20slat-%EC%9E%84%EA%B3%84-%EC%8B%A4%ED%97%98.md) §6 에
*"남는 여지는 재질 하나"* 라고 적었다. 그 하나다.

**결정적으로, 이건 SLAT 주입과 다르다** — 형상에 일절 개입하지 않는다.
coords 를 손으로 짓지 않고 **완성된 메시를 주므로** 조각남도,
[재구성 문서](%5BAI%5D%20trellis2-%EB%B3%B5%EC%9B%90-%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8-%EC%9E%AC%EA%B5%AC%EC%84%B1.md) §7.7 의 양자화 인공물도 없다.

## 1. 근거 — 공식 파이프라인이 정확히 이 용도다

배포본 `texturing_pipeline.json` 이 있다.

```json
"name": "Trellis2TexturingPipeline",
"models": {
    "shape_slat_encoder": "ckpts/shape_enc_next_dc_f16c32_fp16",
    "tex_slat_decoder":   "ckpts/tex_dec_next_dc_f16c32_fp16",
    "tex_slat_flow_model_512": "ckpts/slat_flow_imgshape2tex_dit_1_3B_512_bf16"
}
```

**shape flow model 이 없다.** 형상을 생성하지 않고 주어진 것을 인코딩만 한다.
`shape_enc`·`tex_enc` 가중치도 캐시에 이미 있다.

**빠진 것은 클래스 파일 하나다.** `pipelines/__init__.py` 가 `Trellis2ImageToTexturePipeline` 을
등록하는데 `trellis2_image_to_tex.py` 가 이 포크에 없다(`__pycache__` 에도 없다).
부품은 전부 있으므로 밖에서 조립한다.

| 부품 | 위치 |
| --- | --- |
| 메시 → dual grid | `o_voxel.convert.mesh_to_flexible_dual_grid` |
| dual grid → shape SLAT | `FlexiDualGridVaeEncoder` (코드·레지스트리·가중치 전부) |
| shape SLAT → tex SLAT | `pipe.sample_tex_slat` |
| tex SLAT → PBR | `pipe.decode_tex_slat` |
| 메시 + 속성 → GLB | `to_glb(vertices, faces, attr_volume, coords)` |

**무엇을 바꾸나.** 새 스크립트 `restore/texture_from_mesh.py`. `trellis2/` 는 안 건드린다.

```text
v24 완형 메시 (region_carried + region_filled)
  ↓ mesh_to_flexible_dual_grid(grid_size=512, aabb=[-0.5, 0.5])
coords · dual_vertices · intersected
  ↓ FlexiDualGridVaeEncoder            (입력 6채널 = dual vertex 3 + intersected 3)
shape SLAT (32ch, 16배 다운샘플 → 32³)
  ↓ sample_tex_slat(cond=사진, shape_slat)
tex SLAT
  ↓ decode_tex_slat → base_color / roughness / metallic / opacity 속성 볼륨
  ↓ to_glb(vertices=v24 정점, faces=v24 면, attr_volume=새 속성)
```

**마지막 줄이 요점이다 — 디코딩된 메시는 버리고 속성만 취한다.**
인코딩→디코딩은 VAE 왕복이라 형상이 뭉개지는데, v24 의 이면각 0.948° 와
carried 차이 `0.00e+00` 을 잃을 이유가 없다. `export()` 가 이미 쓰는 `to_glb` 가
메시와 속성 볼륨을 **따로** 받으므로 가능하다.

## 2. provenance 가 오히려 깨끗해진다

| | 근거 | 표기 |
| --- | --- | --- |
| 형상 | 회전대칭 + 이중조화 (수학) | `"회전대칭 가정"` |
| **재질** | **TRELLIS 생성** | `"AI 추정"` |

두 축이 **분리되어 기록**된다. 지금은 재질도 관측 색의 최근접 복사라 근거가 뒤섞여 있다.

## 3. 규약 (확인 완료)

- `mesh_to_flexible_dual_grid` 의 `dual_vertices` 는 **[0,1] 정규화 공간의 절대 좌표**다.
  인코더는 **복셀 내 로컬 [0,1]** 을 기대하므로 `dv * RES - voxel_indices` 로 바꿔 넣는다
  (`o-voxel/examples/mesh2ovox.py` 와 같은 규약. 정렬도 `encode_seq` 기준으로 맞춘다)
- 인코더 출력은 `sample_shape_slat` 반환값과 **같은 공간**(역정규화)이다.
  `sample_tex_slat` 이 내부에서 `(shape_slat - mean)/std` 를 하므로 **그대로 넣는다**
- 인코더 입력은 **fp32**. `convert_to_fp16` 이 `blocks`·`to_latent` 만 바꾼다
- `sample_posterior=False` → 사후분포 평균. 결정론적이라 재현된다

## 4. 걸린 것 — flex_gemm 저VRAM 경로 버그

v24 메시는 512³ 에서 **복셀 2,998,178 개**가 나온다.
`conv_flex_gemm.sparse_conv3d_forward` 는 neighbor map 이 256MB 를 넘으면
(여기서는 `2,998,178 × 27 × 4 = 324MB`) feats 를 CPU 로 피신시킨다.

```python
x.feats = torch.empty(0, dtype=x.feats.dtype, device='cpu')     # 1D 로 교체
neighbor_cache = SubMConv3dFunction._compute_neighbor_cache(
    x.coords, torch.Size([*x.shape, *x.spatial_shape]), ...)     # 여기서 shape 재계산
```

`_shape` 가 아직 None 이면 `__cal_shape` 가 **비워진 1D feats** 로 재계산해 `(1,)` 만 내놓고,
spatial 3개와 합쳐도 4개라 `N, C, W, H, D = shape` 가 터진다.
작은 메시(1.2만 복셀)로는 이 경로를 안 타서 성공한다.

**회피 — 입력에서 `.shape` 를 한 번 호출해 `_shape` 를 확정한다.**
`replace` 가 `_shape` 를 전파하므로 conv 내부에서 재계산이 일어나지 않는다.
`trellis2/` 를 고치지 않는다.

## 5. 실측 — 1단계(encode) 통과 (2026-09-11)

```text
메시  region_carried(149,150면) + region_filled(62,188면) · 정점 128,741 · 면 211,338
dual grid  4.9s · 복셀 2,998,178 · intersected 축별 [0.354 0.311 0.337]
encode     3.2s · shape SLAT (5455, 32) · latent 32³
           feats mean -0.2578 std 6.2734     (latent_A: mean -0.0298 std 5.3698)
```

**latent_A 와 같은 공간이다.** 복셀이 4,079 → 5,455 로 는 것은 채움이 더해졌기 때문이라 맞는 방향이다.

왕복 오차 (encode → decode, 표면 대 표면 최근접)

| | 중앙 | p95 | 최대 |
| --- | ---: | ---: | ---: |
| 원본 → 복원 | 0.00476 | 0.00878 | 0.01464 |
| 복원 → 원본 | 0.00502 | 0.00999 | 0.01946 |

```text
bbox  원본 [0.9017 1.0000 0.9104]  →  복원 [0.9016 0.9997 0.9105]
```

**bbox 가 소수점 셋째 자리까지 보존된다.** 표면 편차 중앙은 bbox 의 **0.476%**,
즉 512³ 복셀 **2.4개** 거리다. 속성 볼륨도 같은 512³ 격자에 사니 대부분 같은 복셀이나
바로 옆 복셀에서 색을 얻게 된다 — 국소적으로 매끈한 색에는 충분하지만
**파단선·투창 테두리에서는 번질 수 있다.** 거기는 눈으로 확인할 것.

복원 메시는 정점 3,001,566 · 삼각형 5,979,272 로 **원본의 28배**다.
디코딩 메시를 버리고 속성만 취한다는 설계가 맞다는 뜻이기도 하다.

> **판정: 경로가 성립한다.** 2단계(texture)로 간다.

## 6. 걸린 것 2 — 좌표계가 둘이다 (Y-up / Z-up)

**`o_voxel.postprocess.to_glb` 는 `Trimesh` 를 반환하고, 그 안에서 Z-up → Y-up 을 넣는다.**
상자로 격리해 확인했다.

```text
입력 extents [0.2, 0.6, 0.4]  →  to_glb 반환 [0.2, 0.4, 0.6]      (x,y,z) → (x, z, -y)
```

그래서 파이프라인에 좌표계가 둘이다.

| | 좌표계 |
| --- | --- |
| TRELLIS 내부 — 디코더 출력, **속성 볼륨 coords** | **Z-up** |
| `to_glb` 출력 = `A_normal.glb`, v24 | **Y-up** |

v24(Y-up)를 그대로 넣어 두 곳이 어긋났다.

1. `to_glb` 에서 **이중 변환** — 출력 bbox 가 `[0.9036, 1.0021, 0.9123]` → `[0.9036, 0.9123, 1.0021]`
2. **인코더에도 Y-up 을 넣었다.** 사진 조건(cond)은 방향을 전제하므로
   **잠재값이 90° 어긋난 채로 만들어졌다** — 1 보다 이쪽이 문제다. 눈에 안 보인다

```python
YUP2ZUP = np.array([[1, 0, 0], [0, 0, -1], [0, 1, 0]])   # (x,y,z) → (x,-z,y)
```

det=+1 인 회전이라 면 winding 이 유지된다. encode·texture·roundtrip 세 곳에 모두 적용했다.
검산 — v24 `[0.9036, 1.0021, 0.9123]` → Z-up `[0.9036, 0.9123, 1.0021]` → `to_glb` → 원래대로.

> **`A_normal.glb` 도 v24 도 Y-up 이다.** TRELLIS 내부 좌표로 되돌리지 않고 넣는 코드는
> 전부 같은 실수를 한다. 앞으로 이 경계를 지날 때마다 확인할 것.

## 7. 실측 — 2단계(texture) 통과 (2026-09-11)

```text
tex SLAT   14.8s · (5475, 32)
decode      8.8s · 속성 복셀 (3,014,492, 6)
             layout  base_color(0:3) metallic(3:4) roughness(4:5) alpha(5:6)
```

**v24 대비 형상 — 완전 보존**

| 노드 | v24 정점/면 | v27 정점/면 | 거리 중앙 | p95 | 최대 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `region_carried` | 94,877 / 149,150 | 95,314 / 148,930 | **0.00e+00** | **0.00e+00** | 1.21e-03 |
| `region_filled` | 33,864 / 62,188 | 38,893 / 60,260 | **0.00e+00** | **0.00e+00** | 1.85e-02 |

```text
bbox    v24 [0.9036 1.0021 0.9123]  =  v27 [0.9036 1.0021 0.9123]
center  v24 [0.0005 0.0002 0.0297]  =  v27 [0.0005 0.0002 0.0297]
```

**정점 중앙·p95 거리가 정확히 0 이다.** v24 정점이 그대로 들어 있다.
정점이 는 것은 UV 이음새 분리, 면이 준 것은 `to_glb` 의 cleaning(면적 0 삼각형 제거)이다.
최대값 1.85e-02 는 그 제거된 자리다.

재질은 `region_filled` 에도 2048² baseColor + metallicRoughness 가 생겼다.
v24 에서는 채움 노드에 텍스처가 아예 없었다(최근접 정점색).

> **판정: S10 의 뼈대가 섰다.** 남은 것은 관측부 재질 보존과 눈으로 하는 품질 대조다.

## 8. 실측 — 볼륨 1024 와 톤 보정 (2026-09-11)

**노드가 분리돼 있으므로 관측부 보존에 UV 마스크가 필요 없다.** 골라 쓰면 된다 —
`region_carried` 는 v24 것, `region_filled` 만 TRELLIS 것.
그래서 **관측부 재질 보존**(§14 미정 1번)이 UV 마스크 합성 없이 훨씬 싸게 풀렸다.

해상도를 올리면 `tex_slat_flow_model_1024` 를 쓰고 latent 가 64³ 이 되므로 **인코딩부터 다시** 한다.
복셀이 300만 → 1,200만으로 4배인데 **8GB 에서 OOM 없이 돌았다** (tex 122.6s · decode 49.2s).

| | 채움 σ | 채움 고주파 | 관측 σ | 관측 고주파 |
| --- | ---: | ---: | ---: | ---: |
| v24 원본 | (정점색) | — | 29.6 | 9.07 |
| v27 TRELLIS 512 | 11.0 | 2.36 | 17.4 | 3.27 |
| **v29 TRELLIS 1024** | **18.2** | **4.60** | **33.7** | **10.47** |

**질감 1.65배 · 고주파 1.95배.** 1024 의 관측부는 원본 디테일마저 넘어선다(33.7 > 29.6).
다만 **색이 주황으로 치우친다** — 채움 RGB `[134.5, 103.9, 75.9]` vs 관측 `[127.7, 117.9, 99.2]`.

→ **채널별 선형 이득** `gain = [0.9497, 1.1348, 1.3070]` 으로 평균만 맞춘다.
상대적 변화(질감)는 건드리지 않고, UV 아틀라스의 빈칸(검정)은 제외한다.
결과 `[127.2, 117.4, 98.7]` — 관측부와 일치한다.

> **이 보정은 사람이 건 것이다.** manifest `region_filled_color` 에 gain 값과 함께 적었다.

| 폴더 | 구성 | |
| --- | --- | --- |
| `v27-…+trellistex+up2` | 전 면 TRELLIS 512 | **관측부까지 재생성 — provenance 깨짐** |
| **`v28-…+trellisfill+up2`** | **v24 관측부 + v27 채움(512)** | **채택** |
| `v29-…+trellistex1024+up2` | 전 면 TRELLIS 1024 | provenance 깨짐 |
| `v30-…+trellisfill1024+up2` | v24 관측부 + v29 채움(1024) | 색 미보정 |
| `v31-…+trellisfill1024+tonematch+up2` | 위 + 톤 보정 | 숫자는 최선인데 안 골랐다 |

![재질 512 vs 1024 vs 톤보정](images/%EC%9E%AC%EC%A7%88-512-vs-1024-%ED%86%A4%EB%B3%B4%EC%A0%95.png)

> 왼쪽부터 관측부(기준) · 512 · 1024 · 1024+톤보정. 위는 UV 아틀라스 전체, 아래는 중앙 확대.
> **1024 에서 태토 알갱이가 보이기 시작하고, 톤 보정이 색을 관측부에 맞춘다.**

## 9. 채택은 v28 이다 — 눈으로 판정했다 (2026-09-11)

**숫자는 1024 쪽이 낫다.** 질감 1.65배, 고주파 1.95배, 톤 보정 후 평균색도 관측부와 일치한다.
**그런데 3D 로 열어보고 v28(512, 톤 보정 없음)을 택했다.**

푸리에 1위를 따르지 않고 렌더를 보고 6-fold 로 간 것과 같은 종류의 판단이다.
**텍스처 아틀라스 통계가 3D 인상과 갈린다.** 아틀라스는 UV 조각을 펼친 것이라
실제로 어떻게 보이는지를 대표하지 않는다 — 이음새·곡률·음영이 빠져 있다.

## 10. 왜 512 가 나았나 — 지표가 틀렸던 것이다

판정 이유는 *"채움이랑 표면 질감이 기존과 연결돼서"* 였다. 그 말이 지표를 고쳐준다.

**"얼마나 세밀한가"가 아니라 "같은 종류의 질감인가"** 다. 내가 쓰던 단일 고주파 값은
절대 디테일 양만 재므로 1024 를 이기게 만든다(4.60 vs 2.36). 그런데 관측부에 **없는 대역**의
미세 알갱이를 넣으면 더 정교해도 이질적으로 보인다.

관측부 텍스처를 기준으로 **파워 스펙트럼 방사평균**을 재고 거리를 보면 순위가 뒤집힌다.
(유효 타일 128px 60장 · Hann 창 · 24 대역 정규화)

| | KL(기준‖후보) | L1 |
| --- | ---: | ---: |
| 관측부 (기준) | 0.0000 | 0.0000 |
| **v27 채움 512** | **0.0038** | **0.0408** |
| v29 채움 1024 | 0.0057 | 0.0523 |
| v31 채움 1024+톤보정 | 0.0056 | 0.0496 |

**512 가 가장 가깝다. 눈 판정과 순위가 같다.**
톤 보정은 스펙트럼도 약간 끌어당기지만(0.0057 → 0.0056) 대역 불일치를 못 고친다 —
평균색만 바꾸는 연산이라 당연하다.

## 11. 색과 질감을 함께 — v28 을 기준으로 (`restore/compare_material.py`)

위 스펙트럼은 **휘도만** 봤고 색은 RGB 평균만 봤다. 둘을 함께 봐야 한다.
색은 **Lab 색차 ΔE**(CIE76), 질감은 **Lab 세 채널 각각의 스펙트럼 거리**(대칭 KL)로 잰다.
그리고 두 축을 나눈다 — 하나만 보면 답이 틀린다.

| 축 | 무엇 | 왜 필요 |
| --- | --- | --- |
| **A 내부 이질감** | 그 GLB 안에서 관측부 ↔ 채움부 | "보기에 자연스러운가" |
| **B 관측부 충실도** | 관측부가 v24 원본과 같은가 | A 만 보면 **전 면 재생성이 유리해진다** — 같은 모델이 만들었으니 |

![재질 비교 v28 기준](images/%EC%9E%AC%EC%A7%88-%EB%B9%84%EA%B5%90-v28%EA%B8%B0%EC%A4%80.png)

| 버전 | 내부 ΔE | 내부 질감 | 채널별 (L / a / b) | 관측부 충실도 |
| --- | ---: | ---: | --- | --- |
| v27 전 면 512 | 7.186 (0.99x) | 0.00631 (0.98x) | 0.0138 / 0.0035 / 0.0016 | **깨짐** (ΔE 5.05) |
| **v28 원본+채움 512** | **7.288 (1.00)** | **0.00641 (1.00)** | 0.0036 / 0.0128 / 0.0028 | **완벽** (0.000) |
| v29 전 면 1024 | 17.891 (2.46x) | 0.02229 (3.48x) | 0.0092 / 0.0415 / 0.0162 | **깨짐** (ΔE 16.3) |
| v30 원본+채움 1024 | 13.07 (1.79x) | 0.01380 (2.15x) | 0.0058 / 0.0286 / 0.0070 | 완벽 |
| v31 위 + 톤 보정 | **1.116 (0.15x)** | **0.04293 (6.70x)** | 0.0057 / **0.1154** / 0.0078 | 완벽 |

**v28 만이 "내부 질감 최선급 + 관측부 완벽"이다.** v27 은 내부 지표가 사실상 동률인데
관측부를 재생성해 ΔE 5.05 만큼 바꿔버렸다.

## 12. v31 이 반증 실험이 됐다 — 색보다 질감이 먼저다

톤 보정은 **색차를 7.288 → 1.116 으로 6.5배 줄였다.** 지표 하나만 보면 압도적이다.
**그런데 질감 거리가 0.00641 → 0.04293 으로 6.7배 나빠졌고, 눈 판정은 그쪽을 따랐다.**

범인은 **a 채널(적–녹 축)** 이다. 0.0128 → **0.1154**, 9배다.
채널별 선형 이득 `gain=[0.95, 1.13, 1.31]` 은 평균만 옮기는 것이 아니라
**편차까지 같은 배수로 늘린다.** 색얼룩의 공간 구조가 증폭돼 관측부에 없는 패턴이 된다.

> **색 평균을 맞추는 연산은 질감을 건드린다.** 전역 이득이 특히 그렇다.

## 13. v32 — Lab 평균 평행이동. 색과 질감을 같이 잡는다 **(현재 최적)**

원인이 **RGB 공간 조작**이다. `RGB → Lab` 이 비선형(감마 + 원뿔 응답)이라
RGB 채널별 배수는 `a = f(X) − f(Y)` 의 **공간 구조까지 뒤튼다.**

**Lab 에서 평균만 더하면** 된다. 곱셈이 아니라 평행이동이라 분산이 정의상 보존된다.

```text
관측부 Lab [49.77, 0.57, 11.79]   채움부 Lab [52.15, 0.06, 18.52]
평행이동   [-2.384, +0.510, -6.728]        Lab 범위 이탈 0.000%
표준편차   전 [4.584, 1.822, 3.083]  →  후 [4.582, 1.824, 3.082]
```

| 버전 | 내부 ΔE | 내부 질감 | L / a / b | 관측부 |
| --- | ---: | ---: | --- | --- |
| v28 | 7.288 (1.00) | 0.00641 (1.00) | 0.0036 / 0.0128 / 0.0028 | 완벽 |
| v31 RGB gain | **1.116 (0.15x)** | 0.04293 (6.70x) | 0.0057 / **0.1154** / 0.0078 | 완벽 |
| **v32 Lab 이동** | **1.483 (0.20x)** | **0.00594 (0.93x)** | 0.0036 / **0.0114** / 0.0028 | **완벽** |

**색차는 v31 과 동급이고 질감은 v28 보다도 낫다.** `a` 채널이 0.0128 → 0.0114 로 내려간다.
`v32-cyl+biharm+n6+trellisfill+labshift+up2`

> 질감이 **좋아진 것**(0.00641 → 0.00594, 7%)은 표본 60타일에서 유의하다고 단정하기 어렵다.
> 확실한 것은 **나빠지지 않았다**는 것이고, 그게 RGB gain 과의 차이다.
> **눈 확인은 아직 안 했다.**

> **다음 유물에서는 이 네 값으로 1차 판정한다.** 단일 고주파 값은 쓰지 않는다.
> 다만 내부 질감의 v27 대 v28 차이가 0.00631 대 0.00641 로 거의 없고 표본이 타일 60장이라
> **지표가 두 판을 가르지는 못한다.** 갈라준 것은 관측부 충실도(축 B)다.
> 3D 눈 대조를 없애지 말고 1차 필터로 쓸 것.
