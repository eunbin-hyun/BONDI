## 2. 어떻게 만드나 — 순서가 곧 설계다

```
AdaPoinTr 출력 8,192점 × 회전 TTA 8회 = 65,536점
        │
        ├─ ① (h, θ) 격자에 올려 칸마다 반지름 R
        ├─ ② **바깥벽으로 정렬**      ← 칸 중앙값은 벽 한가운데다
        ├─ ③ **회전체로 되돌림**      ← θ 변동은 정보가 아니라 잡음
        ├─ ④ 격자 평활 (h·θ)
        ├─ ⑤ **돌대 이식**            ← 관측 프로파일의 대역통과만
        ├─ ⑥ **벽 두께**              ← 단면 빈틈으로 측정, 안쪽벽 생성
        ├─ ⑦ 이음새 tuck              ← 관측 껍질 밑으로 깔아 틈을 막는다
        └─ ⑧ **회전 복사 텍스처**      ← 거울 타일링 + 밝기 이음
```

**②③④⑤ 의 순서가 중요하다.** 먼저 면을 매끄럽게 만들고 그 위에 돌대를 얹어야
두 손잡이(`--r-smooth`, `--ridge-gain`)가 독립이 된다. 반대로 하면 평활이 돌대를 같이 깎는다.

그리고 **방향을 나눈다** — θ 방향(각도별 차이)은 근거가 없으니 지우고,
h 방향(돌대)은 관측에서 읽은 실제 정보이니 남긴다.

## 3. 왜 색이 단색이었나 — 세 가지가 겹쳤다

![단색 원인](images/adapointr-재질-단색원인.png)

| | 원인 | 고친 방법 |
| --- | --- | --- |
| ① | 같은 높이에서 가까운 **도너 12개의 중앙값** | 관측 띠를 둘레에 그대로 붙이는 **거울 타일링** |
| ② | 원본 텍스처를 **정점색으로 굽고** 있었다 (1024² → 정점 94,877) | 무게중심 UV 보간으로 **원본 텍셀 직접** 읽기 |
| ③ | `(h,θ)` 텍셀에 **안쪽벽(그늘)**이 섞였다 — 실측 **표본의 52%** | 법선이 바깥을 보는 표본만 |

**중앙값은 튀는 값도 지우지만 무늬도 같이 지우는 연산이다.** 결손 호에서 먼 텍셀도
같은 가장자리 12개만 보게 되니 호 전체가 한 색으로 눕는다.

거울 타일링은 한 주기를 `seg + seg[::-1]` 로 잡는다. 이어붙인 자리의 양쪽 값이 같아
**경계가 끊기지 않는다** (reflect 패딩과 같은 원리).

색 국소 std **39% → 95%**.

### 복원할 수 없는 부분이 하나 있다

이 유물은 **얼룩이 회전대칭이 아니다.** 같은 높이 안에서도 각도별 밝기 표준편차가
**11.4**(전체 118 대비 10%)다 — 한쪽이 밝고 반대쪽이 어둡다.

회전 복사는 *"회전체니까 같은 높이의 다른 각도가 같다"*를 전제로 한다.
이 전제는 **물레 성형 자국(돌대)에는 맞지만 가마 소성·매장 얼룩에는 안 맞는다.**

그래서 무늬는 복사하고 **밝기만** 결손 호 양 끝의 관측값 사이로 이었다.
남은 차이는 얼룩 자체의 각도 변동과 같은 크기 — **원본에 정보가 없는 부분**이다.

## 4. 잣대 다섯 개 — 이번 기록의 핵심

![울퉁불퉁·틈](images/adapointr-울퉁불퉁-틈.png)

### ① 이면각은 국소만 본다

이면각(면과 면 사이 각)이 5.91°로 관측 6.01°의 98%인데도 **눈으로는 울퉁불퉁했다.**
이면각은 이웃한 두 삼각형만 보므로 **큰 파도를 못 잡는다.**

행마다 36각도의 바깥 반지름을 재고 **변동계수**를 내는 잣대를 새로 만들었다.
회전체면 0 이다 — 관측 0.0307, 그때 AI **0.0519 (1.7배)**.

토기는 물레로 빚은 회전체다. **결손부에서 각도마다 반지름이 다를 근거가 없다.**
이음새에서 멀어질수록 회전체 가중을 올려 되돌렸다 (0.0183).

### ② 정점 거리로는 "틈"과 "일부러 밀어 넣은 것"을 구분 못 한다

패치 테두리는 144×216 격자에 갇혀 있는데 관측 조각의 진짜 가장자리는 그보다 잘다.
그래서 **중앙 2.5mm · 최대 5.1mm** 벌어졌다.

팽창만 키우면 틈은 줄지만 패치가 관측면을 **뚫고 나온다.** 그래서 팽창 3칸 +
벽 두께의 일부만큼 **안으로 밀어** 관측 껍질 밑으로 깔았다.

그런데 그러면 정점 거리 지표가 **같이 커진다** — 틈과 tuck 을 구분 못 한다.
완성본을 다시 격자에 올려 **빈 칸을 세는** 잣대로 바꿨다 (투창 1,983칸은 제외).
**128칸 → 27칸 → 0칸.**

### ③ 분위수 폭에는 벽의 굽음이 섞인다

같은 지점을 세 방법으로 쟀다.

| 방법 | 결과 | 문제 |
| --- | ---: | --- |
| `r` 분위수 폭 (92%−8%) ← 쓰던 것 | **8.2mm** | 칸 안에서 벽이 **굽은 정도**까지 셌다 |
| 법선으로 바깥/안쪽 분리 후 중앙 `r` 차 | **0.9mm** | 파단 테두리에서 두 벽이 맞붙어(경계변 38,816) 눌렸다 |
| **단면 빈틈** | **3.6mm** | 맞다 |

`(h, θ)` 칸 안에서 `r` 을 정렬하면 두 벽 사이가 **비어 있다.**

```
r 정렬:  0.568 0.571 0.575 0.578 0.582 0.585 0.589 │ 빈 틈 │ 0.605 0.609 0.612 0.616
         └────────── 안쪽벽 ──────────┘                      └──── 바깥벽 ────┘
```

그 틈에서 자르고 양쪽 중앙값을 뺀다. 굽음에도 테두리에도 안 흔들린다.

**그리고 두께 프로파일을 가우시안으로 밀고 있었다.** 굽/바리 이음은 22mm 인데
바로 옆 몸통은 7mm 다 — 그 봉우리가 양옆으로 번져 결손부 벽이 통째로 두꺼워졌다.
중앙값 필터는 봉우리를 옮기지 않는다. **137% → 109%.**

### ④ 두께만 보고 **면의 위치**는 아무도 안 쟀다

![면 정렬](images/adapointr-면정렬.png)

복원면이 관측면보다 **중앙 3.8mm, 위쪽 몸통은 8mm** 안으로 들어가 있었다.

**모델 탓이 아니다.** 모델 출력의 바깥 프로파일은 관측과 **−0.28mm** 차이다.
문제는 격자 칸의 반지름을 `np.median` 으로 잡은 것이었다 —
한 칸에 바깥벽과 안쪽벽이 같이 들어가니 중앙값이 **그 한가운데**에 떨어진다.
실측으로 바깥벽보다 **4.67mm 안쪽**, 행 50분위와는 0.38mm 차이.

**고정된 보정량을 더하면 안 된다.** 벽 두께가 높이에 따라 3배 넘게 변해서
한 값으로 밀면 아래는 +4.4mm 넘치고 위는 −4.0mm 모자란다.
행마다 **법선이 바깥을 보는 관측면의 반지름**에 맞췄다. **−3.75mm → −0.94mm.**

> 목표를 90분위로 잡았을 때는 1.8mm 넘쳤다 — **검증은 법선으로 재는데 목표는
> 분위수로 잡아서** 생긴 차이다. 잣대와 목표는 같은 것을 가리켜야 한다.

## 5. 버전은 표 하나로 관리한다

![버전 비교](images/adapointr-재질-버전비교.png)

이름에 설정을 욱여넣는 방식(`A_normal_2node_tta8_144x216.glb`)은 한계에 왔다 —
돌대 gain·평활 sigma·텍스처 방식까지 붙일 수가 없고, 줄이면 **뭐가 달라서
좋아졌는지**가 사라진다.

`versions.py` 에 (번호, 폴더 꼬리표, 특징, 인자) 를 적고 결과물은
`vNN_특징/restored.glb` + `meta.json`(인자·빌드 로그) 로 간다.

```bash
python versions.py --list        # 무엇이 어떻게 다른지
python versions.py --build v15   # 그대로 다시 만든다
python versions.py --measure     # 전부 재서 버전표.csv
```

**옛 버전은 플래그로 고정한다.** 바깥면 거르기를 나중에 붙였더니 v7~v9 를 새 코드로
다시 빌드했을 때 색 국소가 82% → 97% 로 **그때 숫자가 안 나왔다.**
`--no-tex-outer` 를 남겨 옛 동작을 재현할 수 있게 했다 —
**표가 이력이려면 아무 줄이나 지금 다시 만들어도 같은 값이 나와야 한다.**

## 6. 그림은 자체 래스터라이저로 찍는다

`trimesh.Scene.save_image()` 는 pyglet 창을, pyrender 는 EGL 컨텍스트를 연다.
이 노트북의 TRELLIS venv 에는 둘 다 없고 **그 venv 는 본 파이프라인이 쓰는 것이라
건드리지 않는다**(`gupdari-71489/실행-구조.md` §5).

기록용 그림에 필요한 것은 (1) 실제 재질 색 (2) 음영뿐이라
**numpy z-버퍼 + 평면음영**이면 충분하다. 합성도 matplotlib 대신 PIL 로 한다 (같은 이유).
면 색은 텍스처 → 정점색 → `baseColorFactor` 순으로 떨어뜨린다.

## 7. 무엇을 배웠나

**"결과가 나쁘다"와 "재는 법이 틀렸다"를 구분하는 데 시간이 많이 걸렸다.**
다섯 번 다 후자였고, 매번 **눈으로 먼저 보이고 숫자가 나중에 따라왔다.**

| | |
| --- | --- |
| 이면각 98% 인데 울퉁불퉁 | 잣대가 **국소**만 봤다 |
| 색 전체 std 57% 인데 단색 | 잣대가 **전역**만 봤다 |
| 두께 7.9mm 로 맞춰 지었는데 두껍다 | 잣대가 **다른 것**을 쟀다 |
| 두께는 맞는데 면이 파묻힘 | 그 잣대가 **아예 없었다** |

그래서 지금은 결과물마다 **여섯 가지를 자동으로 잰다**(`versions.py --measure`).
새 기능을 붙일 때 어느 지표가 나빠지는지 바로 보인다 —
실제로 v15 에서 면 정렬을 넣자 돌대가 95% → 87% 로 내려간 것도 그렇게 잡혔다.

**측정이 없는 개선은 개선인지 알 수 없다.** 이 문서의 표들이 전부 그 얘기다.
