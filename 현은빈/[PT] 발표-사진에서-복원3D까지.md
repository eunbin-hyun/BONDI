## 0. 한 장으로

**추론 — 깨진 유물 하나를 복원하는 길**

```text
 ① 유물 사진 1장
        │  TRELLIS.2          복셀 → 잠재값 → 메시
        ▼
 ② 관측 3D   깨진 그대로       V 94,877 · F 149,150
        │  AdaPoinTr v3       점 2,048 → 8,192  (회전 TTA 8회 → 65,536)
        ▼
 ③ 완성된 점군               결손부에 새 점이 찍힌다
        │  (h,θ) 격자 144×216  점을 면으로
        ▼
 ④ 복원 3D                   region_observed(원본 무수정) + region_ai(추정)
```

**학습 — ②의 모델을 만드는 길** (미리 한 번만)

```text
 온전한 유물 사진 16장 ──TRELLIS.2──▶ 완형 3D 16점
                                        │  일부러 깎는다 (6패턴 × 20)
                                        ▼
                                  (부분, 완형) 1,920쌍 ──▶ AdaPoinTr 파인튜닝
```

**두 길 모두 사진에서 출발한다.** 박물관은 유물을 사진으로만 공개하기 때문이다.
왜 완형까지 사진에서 만들어야 했는지는 §2.1.1 에 있다.

**두 번의 AI 가 쓰인다.** 사진을 3D 로 올리는 **생성** 모델(TRELLIS), 결손을 메우는
**완성** 모델(AdaPoinTr). 성격이 다르다 — 앞은 *만들고*, 뒤는 *잇는다*.
앞은 확산 모델이고 뒤는 아니다 (§3.2).

**③→④ 는 AI 가 아니다.** 고전 기하 처리다. 발표에서 이 경계를 분명히 하는 게 좋다.

**여기까지 오기 전에 다른 길을 먼저 갔다.** 빗살무늬토기에 U-Net 을 붙여
**무늬는 복원했지만 형상은 못 만들었다** — 팀이 같은 유물로 형상까지 맡겨
재 보니 **학습 없는 고전 수학에 졌다.** 그 한계가 이 경로를 정했다 — §1.5.

## 1. 문제 — 무엇이 어려운가

박물관 유물은 **깨진 채로 온다.** 사진을 3D 로 올리면 깨진 모양 그대로 올라온다.
없어진 부분을 채워야 VR 전시에 쓸 수 있다.

어려운 이유가 셋이다.

| | |
| --- | --- |
| **정답이 없다** | 없어진 부분이 어떻게 생겼는지 아무도 모른다. 검증할 대상이 없다 |
| **학습 데이터가 없다** | "깨진 것 ↔ 온전한 것" 짝이 있어야 배우는데, 같은 유물의 온전한 모습이 없다 |
| **지어내면 안 된다** | 문화재다. 어디까지가 유물이고 어디부터가 추정인지 **구분이 남아야 한다** (`NFR-ETH-003`) |

세 번째가 기술 선택을 크게 바꾼다. 뒤에서 다시 나온다.

## 1.5 먼저 해 본 것 — 빗살무늬토기에 U-Net (2026-08~09)

> **발표에서 뺀다 — 무늬 U-Net 부분.** 빗살무늬토기의 무늬 복원은
> **공세민 발표와 겹친다.** 이 절은 기록으로만 남기고, 슬라이드에는
> **결론 한 줄**만 쓴다 — *"U-Net 은 무늬는 잇지만 없어진 형상은 못 만든다.
> 그래서 굽다리바리는 다른 길로 갔다."* 질문이 나오면 이 절로 답한다.

**AdaPoinTr 로 바로 간 것이 아니다.** 같은 신석기 빗살무늬토기를 두 갈래로 해 봤다 —
내가 **무늬**를 U-Net 에 맡겨 보고, 공세민이 **형상**을 맡겨 봤다.
거기서 갈린 결과가 지금 경로를 정했다.

- 대상: **빗살무늬토기** `ssu022891` — 3D 스캔 한 점
- 정답 없음. 완형이 세상에 없다

### 왜 U-Net 이었나

정답이 없으니 **정답을 만들어내야** 했다. 방법은 이것이다.

```
그 토기의 **온전한 영역**에서 64×64 패치를 뽑는다
   ↓
균열·결손 모양 마스크를 무작위로 씌운다        ← 가짜 훼손
   ↓
마스크 안을 지운 것이 입력, 원래 패치가 정답
   ↓
U-Net 학습
   ↓
학습된 모델을 **실제 손상 마스크**에 적용
```

**별도 완형이 필요 없다.** 원본의 멀쩡한 부분이 입력과 정답을 동시에 만든다
(masked image modeling · denoising autoencoder 계열의 self-supervised inpainting).

U-Net 을 고른 이유는 셋이다.

| | |
| --- | --- |
| **문제가 2D 가 된다** | 원통 전개로 `(높이 240 × 둘레 360)` 맵을 만들면 **일반 2D U-Net 이 그대로 들어간다** |
| **skip connection** | 구멍 주변 세부를 디코더로 직접 넘겨 **테두리가 안 끊긴다.** inpainting 의 표준 |
| **작아서 빠르다** | 16/32/64 채널. **105초**에 학습이 끝난다 (RTX 4070 Laptop) |

### 어떻게 만들었나

```
입력 2채널
  ├ 고주파 표면 (마스크 안은 0 으로 지움)
  └ 이진 마스크 (어디를 메울지)
        ↓
  Enc 16 → Enc 32 → Bottleneck 64 → Dec 32 → Dec 16      skip connection
        ↓
출력 1채널 — 고주파 표면
```

**저주파와 고주파를 나눈 것이 핵심이다.** 높이별 기본 반지름(큰 굽음)을 빼고
**무늬만** 복원 대상으로 삼는다. 문제가 작아진다.

손실은 세 항이다.

```
L = L_masked + 0.08 × L_context + 0.20 × L_gradient
```

`L_gradient` 가 중요하다. 픽셀 오차만 쓰면 **메워진 데가 평평해진다.**
기울기 항이 무늬 방향과 요철을 살린다.

**사전학습은 없다.** 무작위 초기화에서 시작해 그 토기 패치로만 학습했다
(900스텝 · 배치 24 · AdamW lr 1.5e-3 · FP16).

### 결과 — 됐다

![원본과 복원 비교](images/unet_original_vs_restored.png)

| 합성 결손 검증 | MAE | RMSE |
| --- | ---: | ---: |
| 학습 시작 | 1.8441 mm | 2.2700 mm |
| **채택 (step 700)** | **0.1904 mm** | 0.3019 mm |

출력은 **watertight 메시**다 — 경계 모서리 0 · 비다양체 0. VR 에 바로 쓸 수 있다.

![복원 진단](images/unet_restoration_diagnostics.png)

> **다만 이 0.19mm 는 온전한 부분에 가짜 손상을 내고 잰 값이다.**
> 실제 파손 부위에는 정답이 없다. **합성 성능 ≠ 역사적 타당성.**

### 팀이 반대쪽을 쟀다 — 형상을 U-Net 에 맡기면 (공세민)

내가 U-Net 에 맡긴 것은 **무늬(고주파)** 였다. 형상(저주파)은 높이별 기본 반지름으로
빼 두고 시작했다. **왜 그래야 하는지는 그때 재지 않았다** — 문제를 작게 만들려는
선택이었을 뿐이다.

공세민이 같은 신석기 빗살무늬토기로 그 빈자리를 쟀다. 정답이 없는 문제라
**완전히 닫힌 복원본 하나를 정답으로 고정하고 임의로 파손해** 벤치마크를 만들고,
일곱 방법을 같은 자에 올렸다. 그중 **항 하나만 다르게 맞춘 직접 대결**이 이것이다.

```
B3  = prof + 이중조화(lo_obs)     ← 학습 없음. 고전 수학
M1c = prof + U-Net(lo_obs)        ← 그 항만 신경망으로
```

| 결손부 오차 (628쌍 중앙값) | 격자 | 표면 |
| --- | ---: | ---: |
| **이중조화 `B3`** — 학습 없음 | **0.2779mm** | **0.5693mm** |
| U-Net `M1c` — 형상 전담 | 0.4159mm (+50%) | 0.6380mm (+12%) |
| 이웃 복사 `B0g` — 옆 칸 베끼기 | 0.4147mm | 0.6893mm |

![형상을 U-Net 에 맡긴 결과](images/pt-16-m1c-형상U-Net.png)

**U-Net 이 이긴 쌍은 격자 기준 4.6%** (Wilcoxon p = 2e-97). 파라미터 117,537개와 1800스텝
학습이 **옆 칸 반지름 베끼기(`B0g`)와 같은 값**을 냈다.

**왜 졌나 — 문제의 성격이다.** 저주파는 **경계조건 문제**다. 결손부 경계에서 값과
기울기가 주어지면 그 안을 잇는 답은 `Δ²u = 0` 의 해로 **유일하게 결정된다.**
배울 것이 없고 풀면 된다. 신경망은 그 유일해를 유한한 파라미터로 근사하려 드니
구조적으로 손해다.

고주파는 반대다. 경계조건이 답을 정하지 못하고 **주기 3.00mm 의 반복 규칙**을
알아야 채울 수 있다 — 그건 데이터에 있으니 U-Net 이 이긴다 (`M1b` 0.2737).

> 두 실험이 **같은 결론의 양쪽**이다. 무늬만 맡긴 것은 결과적으로 맞았고,
> **형상은 애초에 U-Net 이 할 일이 아니었다.**

### 한계 셋

| | |
| --- | --- |
| **큰 형상은 못 한다** | 위가 그 측정이다. U-Net 은 **무늬를 잇는 모델**이지 **없어진 형태를 만드는 모델**이 아니다. 아가리가 통째로 날아간 굽다리바리에는 못 쓴다 |
| **유물마다 다시 학습해야 한다** | 그 토기 자신으로 배우므로 `ssu022891` 전용이다. 다른 토기는 105초 다시 학습하면 되지만, **배울 만한 온전한 무늬가 남아 있어야** 한다 |
| **마스크가 병목이다** | U-Net 은 손상을 **탐지하지 않는다.** 마스크를 **입력으로 받는다.** 어디가 손상인지는 기하 규칙이 정한다 |

### 굽다리바리는 왜 다른 문제인가

공세민의 결론을 그대로 받으면 *"형상은 방정식으로 풀어라"* 다.
그런데 71489 에는 그게 안 통한다. **경계가 없기 때문이다.**

```
빗살무늬토기     표면의 29% 가 조각으로 떨어져 나갔지만
(공세민)         구멍마다 **둘레가 남아 있다**
                 → 경계조건이 답을 정한다 → 방정식이 이긴다

굽다리바리       굽다리 벽이 θ 85° 폭으로 **통째로** 없다
71489            아가리에서 높이의 40~50% 가 없다
                 → 경계가 한쪽뿐이라 답이 안 정해진다 → 사전지식이 필요하다
```

이 차이는 우리 쪽에서도 쟀다. 같은 패치(14,061칸)를 두 번 만들어 — 한 번은 AI 점을
쓰고, 한 번은 관측 경계만 두고 나머지를 전부 보간으로 — 반지름을 비교했다.

| 보간만으로 채우면 R 이 얼마나 달라지나 | |
| --- | ---: |
| 중앙 | **4.63mm** |
| 90분위 | **22.91mm** |
| *참고 — 벽 두께* | *5.7mm* |

**좁은 결손은 경계가 가까워 보간으로도 비슷하게 나온다.** 공세민이 잰 구간이 거기다.
넓어지면 경계에서 멀어져 밋밋해지고, 그 자리에서 90분위 23mm 가 벌어진다.

### 두 방법은 정답을 다른 데서 구한다

| | U-Net | AdaPoinTr |
| --- | --- | --- |
| 정답을 어디서 | **그 유물 자신**의 멀쩡한 부분 | **다른 유물 16형상**(완형) |
| 무엇을 복원 | 2D 무늬 · 국소 표면 | **3D 전역 형상** |
| 사전학습 | 없음 (처음부터) | ShapeNet-55 · 531에폭 |
| 학습 | **105초** · 유물마다 | 75분 · 한 번 |
| 일반화 | 안 됨 — 유물마다 재학습 | 됨 — 34점에 바로 적용 |

> *"이 토기의 무늬는 이 토기가 안다"* 와 *"굽다리바리는 대체로 이렇게 생겼다"* 의 차이다.
> **둘 다 정답 없는 문제를 다른 방향으로 푼 것**이고,
> 큰 결손을 메우려면 **뒤쪽이 필요했다.**

### 그래서 지금 파이프라인은 둘 다 쓴다

```python
R[h,θ] = median(그 칸의 AI 점 반지름)    # AI 점이 있으면
R[h,θ] = fill_unknown(이웃 평균)          # 없으면 라플라스 보간
```

방정식이 되는 데는 방정식, 안 되는 데는 AI — **공세민의 결론을 버린 게 아니라
적용 범위를 나눈 것**이다 (측정은 §7.6 · `결과.md` §5.16).

그리고 U-Net 에서 만든 **원통 전개**는 버리지 않았다 —
지금 메시화의 `(h,θ)` 격자가 그것이다 (§7).

## 2. 데이터 — 완형이 없다는 것부터 확인했다

### 2.1 AI-Hub 를 전수 측정했다

문화재 3D 데이터셋(AI-Hub 211-2)에 완형이 있을 것으로 기대했다. **695점을 전부 재 봤다.**

![AI-Hub 판정](images/pt-01-aihub판정.png)

**완형 0점.** 완형후보로 걸린 3점마저 오탐이었다 — 크기 1.0~1.7m 에 회전축이 수평이라
토기가 아니다. 라벨 JSON 에는 완형/결손 정보가 아예 없어서(bbox + 분류코드뿐)
**직접 재는 수밖에 없었다.** 판정기는 정답 하나(`RR_07_01_EA_028`, 하부 결실로 판독된 항아리)로
검증했다. 695점 측정에 **62초** 걸렸다.

당연한 결과였다. **211-2 는 *유적* 발굴 스캔이고, 발굴품은 깨져 있다.**

> **개념 — 왜 "완형"이 필요한가.** 점군 완성 모델은 `(부분, 완형)` 짝으로 배운다.
> 부분을 넣고 완형을 맞히게 시킨다. 완형이 없으면 **정답지가 없다.**

### 2.1.1 정확히 말하면 — "3D 데이터가 없다"가 아니다

**발표에서 자주 뭉개지는 곳이라 따로 적는다.**

| 흔한 표현 | 실제 |
| --- | --- |
| ~~"3D 데이터가 없어서"~~ | 3D 데이터는 **695점 있었다.** 적어서가 아니다 |
| **"완형 3D 가 0점이라서"** | 깨진 것만 695점 있어봐야 **정답지가 안 된다** |

그래서 **2D → 3D 를 두 군데에서 쓴다.** 이유가 서로 다르다.

```text
학습 경로   온전한 유물 사진 (e뮤지엄) ──TRELLIS──▶ 완형 3D 16점
                                                    │ 일부러 깎는다
                                                    ▼  (부분, 완형) 1,920쌍
            └ 이유: 완형 3D 가 세상에 없으니 만든다

추론 경로   대상 유물 사진 1장         ──TRELLIS──▶ 깨진 3D ──AdaPoinTr──▶ 복원
            └ 이유: 71489 의 3D 스캔도 공개돼 있지 않다
```

**박물관은 유물을 사진으로만 공개한다.** 3D 스캔은 안 나온다.
그래서 학습이든 추론이든 **출발점이 사진**일 수밖에 없었다.

> **말하는 법.** *"데이터가 없어서 어쩔 수 없이"* 보다
> *"전수 측정해서 없다는 것을 확인하고, 그래서 만들었다"* 가 맞다.

### 2.4 어떻게 나누고 어떻게 평가했나

**발표에서 두 줄이면 된다.**

> 완형 **19형상**을 3D 에서 깎아 **2,280쌍**을 만들었다.
> **학습에 안 쓴 3형상**으로 따로 평가했다.

**쌍이 아니라 형상 단위로 나눈다.** 쌍으로 나누면 같은 유물이 학습과 평가에
같이 들어가 **의미가 없다.**

| | 형상 | 쌍 | 무엇에 쓰나 |
| --- | ---: | ---: | --- |
| **train** | 14 | 1,680 | 가중치 학습 |
| **val** | 2 | 240 | **에폭 선택** |
| **test** | 3 | 360 | 보고용 |
| 합 | **19** | **2,280** | 73.7 / 10.5 / 15.8% |

> **test 는 나중에 뺐다.** 처음에는 val 로 에폭을 고르고 **그 val 로 성능을 보고**
> 하고 있었다. 뒤늦게 알아차려 3형상을 더 빼 다시 쟀더니 **5%p 낙관적**이었다.
> 그래서 val 이 test 보다 작다 — 설계된 비율이 아니다.

### 무엇으로 재나 — 지표 넷

| | 묻는 것 | 왜 필요한가 |
| --- | --- | --- |
| **재현율** (커버리지) | 정답점 중 예측이 δ 안에 있는 비율 | 얼마나 **메웠나** |

**바닥값을 뺀다.** 결손 띠가 얇으면 정답점이 **남아 있는 표면** δ 안에 들어가

## 2.5 왜 이 모델들을 골랐나

두 모델을 쓴다. **성격이 다르고, 고른 이유도 다르다.**

### 먼저 — 2D→3D 세 개를 같은 잣대로 재 봤다 (2026-09-03)

사진 한 장에서 3D 를 만드는 모델 **TripoSR · SF3D · SPAR3D** 를 같은 사진으로
돌리고, 같은 유형 유물의 **실측 스캔**(`ssu022891` · 높이 383mm)을 정답지로 뒀다.

| | **깊이/폭** (실물 1.0) | Chamfer | 정점 / 면 |
| --- | ---: | ---: | ---: |
| **TripoSR** | **0.94** | **10.1mm** | 79,389 / 158,748 |
| SF3D | 0.35 | 46.6mm | 9,728 / 17,772 |
| SPAR3D | 0.36 | 46.8mm | 12,961 / 22,920 |

**SF3D 와 SPAR3D 는 토기를 얇은 부조로 만들었다.** 앞에서 보면 토기인데
옆에서 보면 렌즈다 — 뒷면이 없는 게 아니라 **앞면 바로 뒤에 닫혀 있다.**

![2D→3D 세 모델 — 옆에서 보면 갈린다](images/pt-17-2d3d-부조.png)

**`side` 열을 보면 된다.** 앞(`front`)은 셋 다 토기처럼 보이는데,
옆으로 돌리면 SF3D·SPAR3D 는 **얇은 조각**이다. 맨 오른쪽 단면이 같은 얘기다 —
실측 스캔은 두께 있는 이중 벽인데 둘은 **한쪽으로 접힌 고리**다.

전처리 탓이 아니었다. 배경 제거는 깨끗했고, foreground ratio 를 0.75·0.85·1.0 으로
바꿔도 0.49·0.35·0.39 로 같았다. SPAR3D 는 **512점 조건 점군**을 거치는 구조인데도
깊이를 못 살렸다.

**구조로도 설명이 안 된다.** 넷 다 트랜스포머이고, 셋 다 메시를 낸다.
게다가 **SF3D 는 TripoSR 에서 파생된 모델**인데 같은 사진에서 0.35 대 0.94 로 갈렸다.
가장 비슷한 둘이 가장 크게 벌어진 것이라, 계열로는 못 가른다.

> **원인은 안 쟀다.** 확인한 것은 *아닌 것들*까지다 — 전처리 아님, foreground
> ratio 아님, 정답지·사진·정렬은 셋이 동일. 학습 데이터 차이나 delighting 의
> 영향은 안 봤다.

> **한계 — 사진 1장 · 유물 1점이다.** 첨저형이라 정면 실루엣이 특이한데, 그게
> 원인인지 모델 탓인지 못 가른다. **일반화하면 안 된다.**
> TRELLIS 는 이 비교에 **아예 없다** — 같은 잣대로 재지 않았다.
> 그래서 선정 근거로 쓰지 않고, 발표에서는 *"돌려보니 이랬다"* 로만 쓴다.

### TRELLIS.2 — 사진을 3D 로 올리는 쪽

| 이유 | 설명 |
| --- | --- |
| **사진 1장이면 된다** | 유물 사진은 e뮤지엄에 한 각도밖에 없다. 다중 시점(NeRF·3DGS)이나 스캔은 쓸 수 없다 |
| **8GB VRAM 에서 돈다** | 4B 모델인데 **쪼개서 하나씩 올린다.** 작업 환경이 RTX 4070 Laptop 8GB 다 |
| **재질까지 한 번에 나온다** | 3단계가 PBR 네 채널을 직접 생성한다. 언리얼에 넣을 때 머티리얼 셋업이 거의 없다 |
| **뚫린 구조가 살아남는다** ★ | 아래 |

**마지막 이유가 이 유물에서 결정적이다.**

> 디코더가 내는 것은 **O-Voxel** 이다. 논문은 *"field-free"* 라고 부른다.
> SDF 나 occupancy field 처럼 **공간 전체에 정의된 함수**를 두지 않고,
> **표면 복셀 각각이 자기 안의 표면 조각을 직접 기술**한다.

SDF 계열은 *"이 점이 안쪽인가 바깥쪽인가"* 를 매끄러운 함수로 답한다.
그래서 **얇은 판과 작은 구멍이 메워지거나 뭉개진다.**

**굽다리바리는 굽다리에 창(투창)이 뚫려 있다.** 이 구조가 살아남아야 유물이다.
O-Voxel 이 그걸 지킨다 — 기종을 보고 고른 선택이다.

### AdaPoinTr — 결손을 메우는 쪽

| 이유 | 설명 |
| --- | --- |
| **점군 완성 전용 모델이다** | 메시 **생성** 모델이 아니라 **완성** 모델이다. 있는 것을 두고 없는 것만 더한다 |
| **관측을 안 건드릴 수 있다** ★ | 아래 |
| **사전학습 가중치가 공개돼 있다** | ShapeNet-55. 유물 데이터가 1,920쌍뿐이라 **처음부터 학습은 불가능**하다 |
| **8GB 에서 파인튜닝된다** | lr 1e-5 · 배치 2 × 누적 8 · AMP. **75분**에 끝난다 |
| **CUDA 확장 없이 돈다** | 원본은 커스텀 CUDA 커널을 요구하는데, 순수 PyTorch 로 대체했다 (`install_shims()`) |

**두 번째가 §1 의 세 번째 어려움과 직결된다.**

메시 생성 모델(예: 손상 메시를 넣으면 완성 메시를 내주는 것)을 쓰면
**위상(topology)이 통째로 바뀐다.** 원래 유물의 면이 어디로 갔는지 추적할 수 없다.
*"어디까지가 유물이고 어디부터가 추정인가"* 를 못 가른다.

점군 완성은 **점을 더할 뿐**이다. 관측 메시는 그대로 두고, 더해진 점만 따로
메시로 만들어 **별도 노드**로 낼 수 있다. `NFR-ETH-003` 이 요구하는 것이 이것이다.

> **정리하면.** TRELLIS 는 *"뚫린 구조가 살아남는가"* 로, AdaPoinTr 은
> *"출처를 가를 수 있는가"* 로 골랐다. 둘 다 **성능 지표가 아니라 요건**이 기준이었다.
> 그리고 둘 다 **8GB 에서 돌아야 한다**는 하드웨어 제약을 통과해야 했다.

## 3. TRELLIS — 사진 한 장이 3D 가 되는 원리

### 3.0 복셀부터 — 개념

**복셀(voxel) = Volume + Pixel.** 3차원 격자 위의 **정육면체 칸 하나**다.
2D 이미지가 픽셀 격자이듯 3D 를 칸으로 쪼갠 것이고, *"부피를 가진 점"* 으로 봐도 된다.

**다만 TRELLIS 의 복셀은 두 가지가 다르다.** 발표에서 여기를 뭉개면 안 된다.

| | 보통 복셀 | **TRELLIS 의 복셀** |
| --- | --- | --- |
| 칸에 든 것 | 켜짐/꺼짐 (혹은 밀도 하나) | **32차원 벡터** — 그 칸 안에서 표면이 어떻게 지나는지 |
| 좌표 | 격자 안의 **자리**가 곧 좌표 (저장 안 함) | **좌표를 명시적으로 든다** — 채워진 칸만 남기므로 |
| 해상도 | 칸 크기가 곧 정밀도 | 칸은 64³ 인데 **최종 메시는 훨씬 정밀** |

세 번째가 핵심이다. 모델 이름 `f16c32` 가 *"16배 다운샘플 · 32채널"* 이라는 뜻이고,
**복셀 하나가 원래 해상도의 16×16×16 블록을 대표**한다. 칸은 성겨도 그 안의
형상은 벡터가 들고 있다가 디코더가 풀어낸다.

### 3.1 왜 복셀부터 뽑나

3D 를 **밀집 복셀**로 다루면 1024³ ≈ **10억 칸**이다. 어느 GPU 로도 확산 모델을 못 돌린다.

TRELLIS 는 **표면이 지나는 복셀만** 먼저 골라낸다. 수만 개로 줄어든다.
그 좌표 위에서만 이후 계산을 한다.

```text
입력 PNG
  → RMBG-2.0        배경 제거 (알파 마스크)
  → DINOv3          이미지 특징 토큰 — 텍스트 대신 이게 프롬프트다
  → [1] Sparse Structure   어느 복셀이 채워졌나 (32³ / 64³)    1.3B DiT
  → [2] Shape SLat         복셀마다 32채널 모양 잠재값          1.3B DiT
  → Shape Decoder          잠재값 → 표면 기하 (메시)
  → [3] Texture SLat       모양을 조건으로 재질 잠재값          1.3B DiT
  → Texture Decoder        base color / roughness / metallic
  → PBR 베이크 → GLB
```

> **개념 — SLat (Structured Latent).** *"어디에"* 와 *"무엇이"* 를 분리한다.
> 좌표는 1단계가 정하고, 그 좌표마다 붙는 32차원 벡터를 2·3단계가 채운다.
> 이래서 3D 생성이 **토큰 시퀀스 문제**가 되고, 트랜스포머를 쓸 수 있다.

### 3.2 무슨 모델인가 — 확산 모델(플로우 매칭)

**세 단계 모두 확산 계열 생성 모델이다.** Stable Diffusion 과 같은 갈래다.

> **개념 — 확산 모델.** 데이터에 잡음을 조금씩 더해 **완전한 잡음**으로 만드는 과정을
> 정해 두고, 신경망에 **그 역과정**을 배우게 한다. 생성할 때는 순수 잡음에서 시작해
> 조금씩 걷어내며 데이터로 되돌린다. *"한 번에 만든다"* 가 아니라 *"여러 번 다듬는다"* 다.

TRELLIS.2 는 그중 **rectified flow(플로우 매칭)** 를 쓴다. 잡음에서 데이터로 가는 경로를
**최대한 직선으로** 학습해서, 적은 스텝으로 도착한다.

| 설정 | 1단계 (구조) | 2단계 (모양) | 3단계 (재질) |
| --- | --- | --- | --- |
| 샘플러 | 오일러 | 오일러 | 오일러 |
| **스텝** | **12** | **12** | **12** |
| CFG 강도 | 7.5 | 7.5 | 7.5 |
| CFG 적용 구간 | 0.6 ~ 1.0 | 0.6 ~ 1.0 | 0.6 ~ 1.0 |

**눈여겨볼 것 셋**

- **12스텝.** 이미지 확산 모델의 20~50스텝보다 훨씬 적다. 경로가 직선에 가깝기 때문이다.
- **가이던스를 초반에만 건다.** CFG 를 전 구간이 아니라 잡음이 큰 t 0.6~1.0 에만 적용한다.
  **큰 구조는 조건을 강하게 따르게 하고, 세부 마무리는 자연스럽게** 둔다.
  전 구간에 걸면 과포화된다.
- **조건이 DINOv3 토큰이다.** 텍스트 인코더가 **없다.** 사진의 패치 특징이 직접
  크로스 어텐션으로 들어간다. **그래서 말로 고칠 수 없고, 결과를 바꾸려면 사진을 바꿔야 한다.**

**DiT (Diffusion Transformer)** — 백본이 U-Net 이 아니라 트랜스포머다.
희소 복셀이 이미 **토큰 시퀀스**라 트랜스포머와 잘 맞는다. 1.3B 짜리 셋을 쓴다.

> **대비 — AdaPoinTr 은 확산 모델이 아니다.** 한 번 통과해서 답을 내는
> **결정론적** 인코더-디코더다. 같은 입력을 넣으면 늘 같은 답이 나온다.
> *(그래서 §6 의 회전 TTA 가 의미를 갖는다 — 입력을 돌려야 다른 답이 나온다.)*

### 3.3 실무에서 나오는 결과 둘

- **배경이 남은 사진을 넣으면 여기서 터진다.** 벽·바닥이 전부 표면으로 잡혀
  복셀(토큰)이 폭증한다. 투명 PNG 를 넣어야 하는 이유다.
- **메모리는 모델 크기가 아니라 토큰 수에 비례한다.** 같은 모델이라도 입력에 따라
  OOM 이 나거나 안 난다. 상한을 `max_num_tokens=49152` 로 둔다.

4B 모델이 **8GB VRAM 에서 도는 이유**는 모델을 쪼개 **한 번에 하나만 GPU 에 올리기**
때문이다. 모델 크기가 아니라 *동시에 올라가는 크기*가 VRAM 을 결정한다.

**여기까지가 ①②다.** 산출물은 깨진 상태의 관측 3D — `V 94,877 · F 149,150`,
두께 있는 열린 껍질, 텍스처 1024².

## 4. AdaPoinTr — 점을 어떻게 찍나

### 4.1 구조

![AdaPoinTr 구조](images/pt-06-adapointr구조.png)

```text
입력 점 2,048
  → FPS               멀리 떨어진 점부터 골라 중심 c_i 를 뽑는다
  → DGCNN             중심 주변을 묶어 "점 프록시" 특징 F_i 로
  → 인코더            프록시끼리 어텐션 (기하 인식)
  → 적응형 쿼리 생성   Q_I (입력에서) ∪ Q_O (생성)
  → 디코더
  → FoldingNet 헤드   P_i = f(H_i) + c_i      ← 중요
출력 점 8,192 (고정)
```

> **개념 — 마지막 줄이 이 모델의 성격을 정한다.**
> `P_i = f(H_i) + c_i` 는 *"중심 `c_i` 에서 얼마나 떨어진 곳에 점을 놓을까"* 다.
> **점은 프록시 중심 주변에만 생긴다.** 결손부에 중심이 안 잡히면
> 그 자리에는 점이 생길 자리 자체가 없다.

### 4.2 출력 8,192점은 결손부용 예산이 아니다

**자주 오해하는 곳이다.** 모델은 **완성된 그릇 전체**를 8,192점으로 그린다.

| 한 번 추론 · 8,192점 | |
| --- | ---: |
| 이미 있는 관측을 **다시 그린 것** | 약 **7,544점 (92%)** |
| 결손부에 떨어진 **새 점** | **648점 (7.9%)** |

예산의 92% 가 이미 아는 곳에 쓰인다. 결손이 넓으면 성길 수밖에 없다.
**이게 뒤의 TTA 와 보간이 필요한 이유다.**

## 5. 파인튜닝 — 무엇이 문제였고 어떻게 고쳤나

여기가 발표의 **핵심**이다. 모델을 바꾼 게 아니라 **학습과 평가를 고쳤다.**

### 5.0 네 모델 — 무엇이 달라졌나

| | 무엇을 고쳤나 | 학습 데이터 | 채택 기준 | **F순증 0.35~0.50** |
| --- | --- | --- | --- | ---: |
| **사전학습** | — | ShapeNet-55 · 55분류 4.2만 CAD · **토기 0점** | — | 0.082 |
| **v1** | 첫 파인튜닝 | 완형 **9형상** × 5패턴 = 900쌍 · 결손 0.026~0.271 (평균 0.153) | val CD | 0.438 |
| **v2** | ① 학습 결손을 **깊게** ② 채택 기준을 바꿈 | 같은 9형상 · 결손 **0.021~0.717** (평균 0.351) | **커버리지 순증** | 0.586 |
| **v3** | ③ 형상을 넓히고 **`slant`** 추가 | 완형 **16형상** × 6패턴 = **1,920쌍** (handled 3점 처음) | 커버리지 순증 | **0.936** |

**세 번이 각각 다른 층을 건드렸다.** v2 는 **데이터 분포와 채택 기준**,
v3 는 **형상 다양성과 패턴**이다. 모델 구조는 한 번도 안 건드렸다.

> **이 절의 수치는 전부 TTA 없는 1회 추론(8,192점)이다.**
> 발표에서 보여줄 71489 복원본은 **TTA 8회**로 만든 것이다 — §6 에서 갈라 쓴다.

### 5.1 ① 벤치마크에 누출이 있었다

사전학습 모델을 그대로 재 보니 순증 **0.700** 이 나왔다. 그런데 실제 유물에서는
아무것도 안 됐다. 원인을 찾았다.

> `partial`(부분)을 `complete`(완형)의 **좌표계로 정규화**하면,
> 잘려나간 쪽에 **빈 공간이 남는다.** 모델이 원래 크기를 **액자에서 읽는다.**

같은 쌍·같은 가중치로 **정규화만** 바꾸니:

| | 커버리지 순증 |
| --- | ---: |
| `complete` 기준 정규화 (벤치마크 방식) | **0.700** |
| **자기 정규화** (`partial` 자신의 중심·축척) | **0.102** |

**ShapeNet-55 가 그렇게 만들어져 있다.** 실제 유물에는 그 단서가 없으니
현실 성능은 0.102 쪽이다. 이걸 모르고는 어떤 수치도 못 믿는다.

> **발표 포인트.** *"공개 벤치마크 점수가 높은 모델이 실제로도 좋은가"* 를
> 의심해서 직접 확인한 사례다.

### 5.2 ② 체크포인트를 val CD 로 고르면 안 된다

Chamfer Distance 는 **입력을 그대로 베끼기만 해도 좋게 나온다** — 출력의 92% 가
입력 재현이니 당연하다. 우리가 원하는 건 *"결손부를 얼마나 메우나"* 다.

그래서 **결손부 커버리지 이득**으로 골랐다. v3 는 **ep8** 채택 —
val CD 로 골랐으면 ep12 를 골랐을 것이다.

> **개념 — 지표가 목적과 다르면 최적화가 엉뚱한 곳으로 간다.**
> 손실 함수는 CD 를 써도 되지만 **채택 기준은 목적을 재야 한다.**

### 5.3 ③ 학습 분포가 얕았다

깊은 결손이 안 메워졌다. 모델 탓인 줄 알았는데 **데이터 탓**이었다.
완형을 9 → 16 형상으로 늘리고 `slant`(비스듬한 절단, 결손 34.6~70.7%)를 넣었다.

**테스트 세트**(학습에도 에폭 선택에도 안 쓴 3형상)에서 네 모델을 나란히:

| 결손 깊이 | 쌍 | 사전학습 | v1 | v2 | **v3** | v3−v2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.00~0.20 | 168 | 0.641 | 0.899 | 0.836 | 0.895 | +0.060 |
| 0.20~0.35 | 54 | 0.082 | 0.702 | 0.702 | **0.867** | +0.165 |
| **0.35~0.50** (71489 수준) | 53 | 0.082 | 0.438 | 0.586 | **0.936** | **+0.350** |
| 0.50~0.65 | 24 | 0.026 | 0.229 | 0.625 | **0.918** | +0.292 |

**71489 는 아가리에서 아래로 높이의 40~50% 가 손상돼 있다** —
h 0.6 위로 결손이 40~81% 다. 위 표의 `0.35~0.50` 구간이 그 수준이다.

`slant` 패턴만 보면 **0.485 → 0.985**. 나머지 패턴은 그대로라 **잃은 것이 없다.**

**학습 비용은 75분**(ep8 채택 · 14에폭 조기종료 · lr 1e-5 · 배치 2×누적 8 · AMP).

### 5.4 눈으로 보면

![학습 단계별 점](images/pt-07-학습단계별점.png)

**같은 유물 · 같은 입력 · 같은 추론 조건**인데 학습을 고칠수록 결손부에 점이 는다.

| | 사전학습 | v1 | v2 | **v3** |
| --- | ---: | ---: | ---: | ---: |

## 6. 회전 TTA — 출력이 8,192점으로 박혀 있어서

### 6.1 무엇을 하나

**사진이 아니라 3D 점 좌표 배열을 돌린다.** 렌더링도 카메라도 없다.

![회전 TTA](images/pt-08-회전TTA.png)

```python
for k in range(8):
    a = 2*pi*k/8
    q = rot_about(pts, up, a)          # 점 좌표를 45°k 돌린다
    o = infer(model, q)                # 추론
    outs.append(rot_about(o, up, -a))  # 되돌려 제자리에
```

### 6.2 왜 여러 번 하나 — 이유가 둘

| | |
| --- | --- |
| **출력 수가 학습 시점에 박혀 있다** | AdaPoinTr 은 무조건 8,192점을 낸다. 한 번으로는 못 늘린다 |
| **모델이 회전 불변이 아니다** | 같은 물체를 돌려 넣으면 다른 답을 낸다. 회차별 새 점이 **592~722개**(변동계수 0.06) |

두 번째가 곧 **모델 분산**이다. 여러 각도를 합치면 줄어든다.

### 6.3 얼마나 버나

| 71489 · 결손 후보 11,740칸 | 1회 | **8회** |
| --- | ---: | ---: |
| 출력 점 | 8,192 | **65,536** |
| 결손 칸을 덮은 비율 | 5.2% | **28.0%** |
| 점 사이 거리 (최근접 중앙) | 2.04mm | **0.92mm** |

> **8배를 돌렸는데 점 간격은 2.2배만 촘촘해진다** (이론값 √8 = 2.83).
> 출력의 92% 가 입력 재현이라 회차끼리 크게 겹치기 때문이다.

**그래도 28% 다.** 나머지 72% 는 다음 단계의 보간이 메운다.

## 7. 점 → 면 — `(h,θ)` 격자

### 7.1 왜 격자인가 (푸아송·볼피벗 대신)

점군은 3D 모델이 아니다. 면도 두께도 텍스처도 없다. 표준 방법은
푸아송 재구성이나 볼피벗인데, **셋 때문에 안 썼다.**

| | |
| --- | --- |
| ① **어디를 메울지 정해준다** | *"점이 없는 칸 = 결손"* 이라는 규칙이 생긴다. 투창은 예외로 뺀다 |
| ② **3D 문제가 2D 영상 문제가 된다** | 빌드 20여 단계 중 **14단계가 격자 위 2D 연산** — 가우시안 평활, 모폴로지 닫기, 라플라스 보간, 대역통과, 연결성분 |
| ③ **관측과 AI 를 안 섞는다** | 푸아송을 쓰면 둘이 **한 표면으로 녹는다.** 그러면 어디까지가 유물인지 못 가른다 |

**③ 이 결정적이다.** §1 의 세 번째 어려움이 여기서 해결된다. 문화재에서 출처 분리는
있으면 좋은 기능이 아니라 **요건**이다.

![점과 격자](images/pt-09-점과격자.png)

### 7.1.1 이 격자는 내가 고안한 것이 아니다

**출처를 밝혀 두는 게 맞다.** 발표에서 *"제가 만든 방법"* 이라고 하면 안 된다.

**원통 전개(cylindrical unwrapping)** 는 회전체를 다루는 **고전적인 기법**이다.

| 어디서 이미 쓰나 | 어떻게 |
| --- | --- |
| **고고학 실측도** | 토기 도면의 **단면도**가 바로 이것 — 회전체를 `반지름 × 높이` 로 그리는 관행 |
| **3D 스캔** | 턴테이블 스캔은 애초에 `(h, θ, r)` 로 데이터가 나온다 |
| **CG · 기하 처리** | cylindrical UV mapping · height field on a cylinder |

**이 프로젝트 안에서도 먼저 있었다.** 형상 복원의 다른 갈래인 `rotational/` 이
2026-09-10 에 이미 `r(y, θ)` 전개 맵에서 메시를 직접 만들고 있었다
([\[수학\] 회전대칭-메시-직접-복원.md](%5B%EC%88%98%ED%95%99%5D%20%ED%9A%8C%EC%A0%84%EB%8C%80%EC%B9%AD-%EB%A9%94%EC%8B%9C-%EC%A7%81%EC%A0%91-%EB%B3%B5%EC%9B%90.md)).
투창 `n-fold` 판정도 [\[수학\] 투창-n-fold-판정.md](%5B%EC%88%98%ED%95%99%5D%20%ED%88%AC%EC%B0%BD-n-fold-%ED%8C%90%EC%A0%95.md)
의 기준을 **그대로 재구현**한 것이다. 같은 해상도(96×144)에서 그쪽 측정을 재현해 확인했다.

> **새로운 것은 조합이다.** 결손 판정 · 투창 보호 · 메시화 · 텍스처 · **출처 분리**를
> 전부 **하나의 격자 위에서** 처리하도록 엮은 것. 그리고 그 대상이
> **생성 모델이 아니라 점군 완성 모델의 출력**이라는 점.
>
> **말하는 법.** *"제가 고안한 방법"* (✗) →
> *"회전체에 쓰는 표준 전개를 AI 출력에 맞게 엮었다"* (○)

### 7.2 R 격자를 어떻게 채우나

![메시 생성](images/pt-10-메시생성.png)

왼쪽이 **높이 하나를 잘라 위에서 본 단면**이다.

| | 무엇 | 점/회전 |
| --- | --- | --- |
| ① | 그 칸에 떨어진 **AI 점의 반지름 중앙값** → `R[h,θ]` | **점** |
| | 점이 없는 칸 → **라플라스 보간** (위·아래·좌·우 평균 1,000회) | 점 |
| | 바깥벽 정렬 — 칸 중앙값은 벽 *한가운데*라 그냥 쓰면 파묻힌다 | 관측 |
| ② | 그 높이의 중앙 반지름 쪽으로 당김 (`--axisym 0.85`) | **회전** |
| ③ | 칸 네 귀 → 삼각형 두 장 | — |

**②의 세기가 고정이 아닌 게 요점이다.** 이음새(관측과 붙는 곳)에서 **0**,
안으로 6칸 들어가며 **0.85** 까지 오른다. 전체 평균 **0.33** —
**3분의 2 는 점, 3분의 1 이 회전체**다.

> **왜 섞나.** 이음새에서 회전체를 쓰면 관측 조각과 **어긋난 턱**이 생긴다.
> 깊은 안쪽에서 점만 쓰면 모델 출력이 거칠어 **이면각이 28°** 까지 뛴다 (관측 6.0°).
> 붙는 곳은 점을, 먼 곳은 회전체를 믿는다.

### 7.3 격자가 깔고 있는 가정

![격자 가정](images/pt-11-격자가정.png)

`(h,θ) → r` 로 펴려면 **축에서 한 방향을 봤을 때 표면이 하나**여야 한다.
완전 회전대칭(`r = f(h)`)보다는 약하지만 **가정이 없는 것은 아니다.**

| 71489 · 칸당 반지름 무리 | 칸 | |
| --- | ---: | --- |
| 1개 | 25.0% | 홑겹 — 테두리·굽 바닥 |
| **2개** | **66.6%** | 안쪽벽 + 바깥벽 |
| 3개 이상 | **8.4%** | 가정을 벗어난다 |

벗어나는 자리가 **h 0.30~0.45 에서 37%** — **굽다리와 바리가 만나는 곳**이다.
축에서 쏜 선이 굽다리 벽을 지나고 그 위 바리 밑면을 또 지난다.

**통하는 이유는 2노드 분리에 있다.** 관측이 남은 곳은 원본 메시가 그대로 나가므로
이음부의 여러 겹도 안 건드린다. **격자는 새로 만드는 면만 표현하면 된다.**

### 7.4 만들지 않는 것도 판단한다

![구름 거부](images/pt-12-구름거부.png)

메시화는 들어온 것을 성실하게 형상으로 바꾼다. **구름이 들어오면 없는 형상을
자신 있게 내놓는다.** 실제로 한 유물이 파단선을 둘레로 돌려 **있지도 않은 넓은 챙**을
만들었다. 점 수로는 못 가른다 — 그 유물이 가장 많이 만든 축이었다.

그래서 **면 퍼짐**(칸 안 반지름 상대 산포)을 재서 0.07 을 넘으면 **거부한다**.
실측으로 정상 0.026~0.061, 구름 0.077~0.186 사이가 비어 있어 그 틈에서 잘랐다.

> **발표 포인트.** *"만들 수 있다"* 와 *"만들어도 되는가"* 는 다르다.
> 근거가 부족하면 **안 만드는 것이 맞는 동작**이다.

### 7.5 어디까지가 학습이고 어디부터가 규칙인가

**발표에서 가장 자주 나오는 질문 둘을 여기서 막는다** —
*"AI 가 다 한 건가요?"* 와 *"임계값은 감으로 맞췄나요?"*

| | 무엇 | 누가 정하나 |
| --- | --- | --- |
| **① 학습된 것** | AdaPoinTr 가중치 (`.pth`) | **데이터가 정한다.** 75분 × 3회 |
| **② 설계한 규칙** | `(h,θ)` 격자 · *"점 없는 칸 = 결손"* · 투창 n-fold · 2노드 분리 | 내가 설계. **학습 안 한다** |
| **③ 고른 임계값** | 면 퍼짐 0.07 · 밀도 상위 70% · 회전체 0.85 · 투창 h<0.55 | 내가 고름. **숫자를 보고** |

> **③을 바꿔도 `.pth` 는 손대지 않는다.**
> 그래서 이것은 **하이퍼파라미터 조정이 아니라 후처리 임계값**이다.
> 학습 하이퍼파라미터(`lr 1e-5` · 배치 2×누적 8 · 채택 기준)는 §5 에 따로 있고,
> 그쪽을 바꾸면 가중치가 바뀐다.

**①②③ 순서가 곧 "AI → 엔지니어링 → 판단"** 이다.

### 임계값은 감이 아니다 — 빈 구간에서 잘랐다

`경주_고적_13472` 가 파단선을 둘레로 돌려 **없는 넓은 챙**을 만든 것이 계기다.
**점 수로는 못 가른다** — 그 유물이 점을 가장 많이 만든 축이었다.

```
면 퍼짐 (칸 안 반지름의 상대 산포)

  정상   71489        0.051 ─┐
                             ├─  여기가 비어 있다  →  0.07 로 자름
  구름   고적_13472   0.077 ─┘ ~ 0.186
```

밀도 거르기(상위 70%)도 효과를 재서 정했다 —
퍼짐이 고적_13472 **0.0765 → 0.0514**(임계 아래로), 71489 0.0511 → 0.0383.

### 한계 — 그리고 나중에 확인된 것

**임계값을 유물 2점으로 골랐다.** 모델 쪽은 train/val/test 를 나눴는데
**메시화 쪽은 안 나눴다.** 그 2점이 곧 시연 대상이다 — 후처리판 과적합이다.

**다만 처음 보는 유물에서도 같은 방향으로 작동했다.**

| | 면 퍼짐 | 게이트 |
| --- | ---: | --- |
| `경주_583` | 0.099 | **거부** |
| `경주_8485` | 0.111 | **거부** |
| `경주_6311` | **0.030** | 통과 → 복원 |

**임계값을 정할 때 쓴 것이 아니라 뒤늦게 확인된 것이다.**

### 7.6 "빈 칸이면 어차피 다 메우는데 AI 가 의미 있나"

**나올 만한 질문이고, 답이 숫자로 있다.**

AI 는 **어디를 메울지**가 아니라 **어떤 모양으로 메울지**를 정한다.

| 질문 | 누가 정하나 |
| --- | --- |
| **어디를 메울까** | 관측 점유 — *"점 없는 칸"*. **AI 무관** |
| **어떤 반지름으로** | **AI 점.** 패치의 **46%** 에 직접 값을 준다 |

```python
R[h,θ] = median(그 칸의 AI 점 반지름)    # 점이 있으면
R[h,θ] = fill_unknown(이웃 평균)          # 없으면 보간
```

### 재 봤다 — AI 를 빼고 보간만으로 채우면

같은 패치를 두 번 만든다. 한 번은 AI 점을 쓰고, 한 번은 관측 경계만 쓰고 전부 보간한다.

| R 이 얼마나 달라지나 | |
| --- | ---: |
| 중앙 | **4.63mm** |
| 90분위 | **22.91mm** |
| *참고 — 이 그릇의 벽 두께* | *5.7mm* |

**중앙값이 벽 하나 두께만큼**이다. 90분위 23mm 는 형상이 아예 달라지는 크기다.

### 왜 보간만으로는 안 되나

라플라스 보간은 **경계를 매끄럽게 잇는 것**뿐이다. 경계에서 멀어질수록 정보가 없어 평평해진다.

```
좁은 결손   경계가 가까워 보간으로도 비슷하다
넓은 결손   경계가 멀어 밋밋해진다.  AI 가 "여기쯤 부풀어야 한다" 를 준다
```

**§2.4 의 표가 같은 이야기다.** 얕은 결손에서는 v1 0.899 · v3 0.895 로 동률인데,
깊은 결손에서 v1 **0.229** · v3 **0.918** 로 갈린다.
**보간으로 되는 구간과 안 되는 구간이 거기서 나뉜다.**

## 8. 투창 — 구멍을 구멍으로 남기기

굽다리바리는 굽다리에 **창(투창)** 이 뚫려 있다. 격자 규칙이
*"점 없는 칸 = 결손"* 이라 그냥 두면 **투창을 다 막아버린다.**

### 8.1 가정이 아니다 — 실제로 막았다

초기 메시화가 **투창을 전부 메웠다.** 원인을 갈라 보니 모델이 아니라 **내 격자 규칙**이었다.

```text
굽다리 빈 칸 248 중
  모델 출력이 점을 넣은 칸    67 (27%)     ← 모델은 73% 를 열어 뒀다
  내 fill_unknown 이 메운 칸  248 (100%)   ← 범인
```

**모델은 잘못이 없었다.** 보간이 *"빈 칸이니 메운다"* 를 성실하게 100% 수행했다.

### 8.2 크기나 폭으로는 못 가른다

문턱을 걸어 *"작은 구멍은 투창"* 으로 하려 했지만 안 된다 —
**진짜 투창 중에 θ폭 70°·80° 짜리가 있다.** 문턱을 그만큼 열면 **진짜 파단까지 샌다**
(`[수학] 투창-n-fold-판정.md` 가 앞서 겪은 것과 같다).

그래서 **주기성**으로 갈랐다. θ 방향 점유를 푸리에로 보아 **n-fold 주기가 서는 띠**를
찾고, 그 띠의 구멍만 투창으로 인정해 결손에서 뺀다.

**지금 71489 에서 1,862칸이 투창으로 보호받는다.** 이 장치가 없으면 그 1,862칸이
`결손 9,628` 에 합쳐져 **11,490칸이 통째로 메워진다.**

### 8.3 그런데 살이 깨진 창은 되돌린다

![깨진 살 복원](images/pt-13-깨진살복원.png)

투창은 단으로 나뉘고 각 단의 창은 크기가 고르다.
71489 에서 정상 창 7개가 높이폭 0.08~0.11 인데 하나가 **0.20 · 683칸** 으로
위아래 단을 가로질렀다 — **그 사이 가로살이 깨진 것**이다.
정상 창이 한 개도 안 걸치는 행만 결손으로 되돌린다 (184칸).

> **확인한 것 — 모델은 투창을 모른다.** 투창 칸에 모델이 만든 **새 점은 0개**다.
> 학습 완형이 전부 투창 있는 굽다리바리라 *"굽다리에는 구멍이 있다"* 를 이미 배웠다.
>
> **그래서 투창 보존은 AI 의 공이 아니라 메시화 쪽 장치다.**
> 막을 뻔한 것은 모델이 아니라 격자 규칙이다.
>
> **말하는 법.** *"AI 가 투창을 지켰다"* (✗) →
> *"AI 는 투창 자리에 점을 0개 만들었다. 막을 뻔한 건 내 규칙이었고, 그걸 고쳤다"* (○)

## 10. 한계 — 정직하게 말할 것

### 10.1 벽이 통째로 없으면 창도 못 지킨다

![깨진 벽](images/pt-15-한계-깨진벽.png)

71489 의 굽다리 벽이 **θ 38°~122°, 85° 폭으로 통째로 없다.** 그 안에 있던 창도
같이 사라져서, 깨진 벽과 창이 **하나의 빈 덩어리(1,613칸)** 로 이어진다.

투창 판정은 *"벽 속의 주기적인 구멍"* 을 찾는다. **벽이 없으면 볼 대상이 없다.**
그래서 전부 결손이 되고 **민벽으로 메워진다.**

자동으로 창을 찍어 넣기는 근거가 얇다 — 그 구간의 n-fold 확신도가 **21~29%** 이고
살아남은 창 간격도 110°·141°·109° 로 안 고르다. **위치를 지어내는 것**이 된다.

**현재 동작(민벽 + `region_ai` 표시)을 유지한다.** 석고 복원 관례와 같다 —
없어진 부분은 메우되 **무늬는 지어내지 않고** 복원부임을 구분되게 둔다.

### 10.2 그 밖

| | |
| --- | --- |
| **회전체 아닌 기종** | 손잡이·귀때·뚜껑은 `(h,θ) → r` 이 함수가 안 된다. 격자 방식을 못 쓴다 — **§10.3** |
| **provenance 를 유물 단위로 못 좁힌다** | 어느 **면**이 추정인지는 분리했지만, 어느 완형에서 왔는지는 못 댄다 |
| **sim-to-real 미검증** | 학습 완형은 *온전한* 사진의 TRELLIS, 71489 는 *깨진* 사진의 TRELLIS다. 이 상류 차이는 아직 확인 못 했다 (중단, 기각 아님) |
| **입력 점 수가 늘 2,048 고정** | 사전학습은 결손이 클수록 입력 점이 줄어 **개수 자체가 단서**였다. 우리는 남은 조각 크기와 무관하게 2,048점을 다시 뽑으니 그 단서가 없다 — 결손 10%짜리도 상류 기준 "많이 깨진" 쪽 신호로 들어간다. 해가 되는지는 아직 안 재봤다 |

### 10.3 추후 과제 — 회전체가 아닌 기종은 채우는 쪽만 바꾸면 된다

`(h,θ)` 격자가 `r = f(h,θ)` 를 전제한다. 손잡이가 하나 붙으면 같은 `(h,θ)` 에
반지름이 셋(손잡이 바깥·안쪽·몸통 벽) 나와 **함수가 안 된다.**

**점 찍는 AI 는 그대로 쓴다.** AdaPoinTr 은 ShapeNet-55 55분류로 사전학습된
범용 점군 완성 모델이라 기종을 안 가린다. 바꿀 것은 **점을 면으로 만드는 쪽**이다.

| | 방향 |
| --- | --- |
| **채우는 자리** | `(h,θ)` 격자 대신 **3D 복셀 격자**. `r` 이 함수여야 한다는 전제가 없어진다 |
| **출처 분리** | 칸마다 **관측/AI 라벨**을 달고 메시를 두 번 뽑는다. 점마다 꼬리표가 이미 있으니 격자보다 오히려 자연스럽다 |
| **투창 보존** | 밀도 절단은 안 된다 — 점군에 구별 정보가 없다(§5.12). **원본 메시가 이미 뚫린 곳을 확정으로 물려받고** AI 점이 그 안에 들어오면 버린다. 회전 가정이 필요 없다 |
| **TTA** | 축 둘레 회전을 못 쓴다. 점을 8배로 못 늘리므로 **복셀 해상도를 낮춰** 맞춘다 |

**대가도 분명하다.** 원본 구멍을 물려받는 방식은 *"보이는 창만 지킨다"* 이다.
71489 처럼 **벽이 통째로 없어져 창까지 사라진 구간은 포기**한다 — n-fold 판정이
필요했던 이유가 거기였다(§10.1).

> **안 해봤다.** `결과.md` §5.12 는 **격자를 빼면 무엇을 잃는지**까지만 쟀다
> (투창과 결손이 완벽히 상충 · 출처가 한 표면으로 녹음). 위는 그 둘을 어떻게
> 되찾을지의 **설계 방향이지 결과가 아니다.**

## 11. 발표에서 강조할 것 — 우선순위

| | 무엇 | 왜 센가 |
| --- | --- | --- |
| **1** | **벤치마크 누출 0.700 → 0.102** | 공개 지표를 의심하고 직접 확인했다. 재현 실험까지 붙어 있다 |
| **2** | **체크포인트를 val CD 아닌 커버리지로** | 지표가 목적과 맞아야 한다는 판단 |
| **3** | **학습 분포 진단 → `slant` → 0.510 → 0.985** | 모델이 아니라 데이터를 고쳐 푼 사례 |
| **4** | **`(h,θ)` 격자 — 왜 푸아송이 아닌가** | 기술 선택에 이유가 있다. 출처 분리 요건과 직결 |
| **5** | **만들지 않는 판단 (면 퍼짐 게이트)** | 근거 없으면 안 만든다 |
| 6 | 회전 TTA · 투창 보존 | 곁가지. 질문 나오면 답할 정도로 |

**빼는 것** — §1.5 의 무늬 U-Net 은 슬라이드에 안 넣는다. 공세민 발표와 겹친다.
전환 근거 한 줄(*형상은 U-Net 이 할 일이 아니었다*)만 쓰고 넘어간다.

**질문이 거의 확실히 나오는 곳 셋**

- *"왜 푸아송을 안 썼나"* → **출처를 못 가르기 때문.** §7.1 ③
- *"그 격자 가정이 안 맞는 유물은?"* → 손잡이·귀때·뚜껑. **91.6% 라는 숫자로 재 뒀다**
- *"AI 가 지어낸 것 아닌가"* → 모델이 만든 점은 출력의 **8%** 뿐이고,
  나머지는 관측 재현이다. 그리고 **어느 면이 추정인지 노드로 분리해 뒀다**
- *"빈 칸이면 어차피 다 메우는데 AI 가 의미 있나"* → AI 를 빼고 보간만 하면
  R 이 **중앙 4.6mm · 90분위 22.9mm** 달라진다 (벽 두께가 5.7mm 다). §7.6
