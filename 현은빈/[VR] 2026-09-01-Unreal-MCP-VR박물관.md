## 1. Unreal MCP 연결

### 1.1 구조

언리얼 에디터 플러그인이 로컬에 HTTP 서버를 띄우고, 그 위에서 MCP 프로토콜로 에디터를 조작하는 방식이다.

```text
Claude Code
   ↓ MCP (HTTP)
127.0.0.1:8000        ← 언리얼 에디터 프로세스가 직접 LISTEN
   ↓
게이트웨이 도구 3개 (list_toolsets / describe_toolset / call_tool)
   ↓
실제 툴셋 50개 이상
```

도구가 처음부터 다 노출되는 게 아니라 **게이트웨이 3개가 나머지를 감싸는 구조**였다. 그래서 목록만 봐서는 뭘 할 수 있는지 알 수 없고, `describe_toolset`으로 안쪽을 열어봐야 한다.

### 1.2 켜는 순서

| 단계 | 위치 |
|---|---|
| ① 플러그인 활성화 | `Edit → Plugins` → `Unreal MCP` + `All Toolsets` |
| ② 서버 자동 시작 | `Edit → Editor Preferences → General → Model Context Protocol → Auto Start Server` |
| ③ 에디터 재시작 | 이걸 해야 8000번 포트가 잡힌다 |
| ④ 설정 파일 생성 | 에디터 콘솔(`~`)에서 `ModelContextProtocol.GenerateClientConfig ClaudeCode` |
| ⑤ Claude Code 재시작 | MCP 서버는 **세션 시작 시점에만** 로드된다 |

②를 안 하면 언리얼이 여는 포트는 `1985` 하나뿐이다. 이건 MCP 포트가 아니다.

### 1.3 오늘 헷갈렸던 것 — 에디터 / 콘솔 / Content Browser

셋을 같은 것으로 착각했다.

| 이름 | 정체 | 어디에 |
|---|---|---|
| 언리얼 에디터 | 프로그램 전체(창 하나) | — |
| 콘솔 | 명령어 한 줄 치는 입력창 | 에디터 안, `~` 키 |
| Content Browser | 에셋 탐색 패널 | 에디터 안, 보통 아래쪽 |

`GenerateClientConfig`는 **콘솔**, 폰트 임포트는 **Content Browser**다.

### 1.4 `.mcp.json`은 개인 설정이다

MCP 설정 파일은 언리얼 에디터를 켠 사람에게만 유효하고, AI 직군이 쓰는 Blender MCP 설정과 충돌할 수 있다. 그래서 저장소에 커밋하지 않고 `.gitignore`에 넣기로 했다. (dev 브랜치에 반영)

### 1.5 MCP로 되는 것 / 안 되는 것

**되는 것**

- 레벨 액터 스폰·삭제·이동, 아웃라이너 폴더 정리 (`SceneTools`, `ActorTools`)
- 머티리얼 인스턴스 생성·파라미터 설정 (`MaterialTools`)
- UMG 위젯 생성 및 구성 (`UMGToolSet`)
- 블루프린트 변수 생성, **그래프 로직을 텍스트 DSL로 작성** (`BlueprintTools`)
- 뷰포트 스크린샷, 로그 조회

**안 되는 것 — 이게 중요하다**

| 항목 | 이유 |
|---|---|
| **에셋 임포트** | 툴셋에 기능 자체가 없다 (폰트 임포트가 여기서 막혔다) |
| **Android 빌드·SDK 경로·패키징** | 도구 범위 밖. **G1 게이트는 MCP로 못 뚫는다** |
| **VR Preview 실행** | `StartPIE`에 `PlayMode_InVR`이 있지만 out-of-process 모드는 자동으로 뷰포트 재생으로 강등된다 |

> 처음에 "블루프린트 로직 작성은 안 된다"고 판단했는데 **틀렸다.** Epic 공식 문서 요약만 보고 내린 결론이었고, 실제 툴셋을 열어보니 DSL로 그래프를 짤 수 있었다. **문서보다 실제 도구 목록을 열어보는 게 정확하다.**

## 3. `L_Museum` 전시실 제작

`L_XRTemplate`을 직접 고치지 않고 **사본 `L_Museum`을 떠서** 작업했다. 원본이 남아 있어야 뭐가 깨졌을 때 비교가 되고, 명세 21.1의 씬 분리(`Boot` / `Museum` / `Diagnostics`) 규칙과도 맞는다.

### 3.1 배치

| 액터 | 위치 (cm) |
|---|---|
| `Pedestal_01 / 02 / 03` | x=-250, y=-250 / 0 / +250, z=50 |
| `Proxy_Artifact_01 / 02 / 03` | 각 전시대 위 z=115~118 |
| `Player Start` | x=-480, y=0 (전시대 2.3m 앞, 정면) |

- **전시대 높이 1.0m** — 서서 관람 + 앉은 자세 지원 (`NFR-UX-005`)
- **간격 2.5m** — `U-10 미확정`. 실기에서 조정
- **프록시 유물 30cm** — 소형 유물 한정 (`D-43`)

> **유적이 안 정해져도(U-06) VR 작업은 막히지 않는다.** 전시 공간, 이동, 전시대 배치, 잡기, 근접 패널 전부 프록시(구·원기둥·원뿔)로 만들 수 있다. 명세 17장 원칙 4번 "작은 것부터 끝까지 연결한다"와도 맞는 순서다.

### 3.2 단위 — 1 uu = 1 cm

명세는 meter로 쓰여 있는데 언리얼은 **1 unit = 1cm**다. 1.0m → `100`. 지금까지 실수한 값 대부분이 여기서 나왔다.

### 3.3 첫 결과물이 별로였던 이유

전시대를 배치하고 스크린샷을 찍었더니 새까맣게 묻혀 있었다. 좌표는 맞는데 보이질 않았다.

1. **XR 템플릿은 박물관이 아니라 데모 놀이터다.** 권총 2정, 모닥불, 잡기 테스트 블록 8개, 상자 십수 개가 널려 있었다. → 소품 27개 제거
2. **서쪽 절반에 천장이 없었다.** 태양광이 그대로 꽂혀 과노출이 나고, 벽 그림자가 새까맣게 떨어졌다. → `Ceiling_Gallery`로 덮어 실내로 만들자 내가 단 조명이 비로소 주광이 됐다.
3. 조명이 원본의 **별도 서브레벨** `L_XRTemplate_Lighting`에 들어 있어서 사본은 원본 조명을 그대로 참조하고 있었다.

### 3.4 조명 — 단위는 candela

**세기를 60,000으로 넣어서 화면이 하얗게 날아갔다.** 언리얼 스포트라이트 기본값이 `8 candela`인데 7,500배를 넣은 셈이다.

| 필 라이트 (코너 4개) | 22 cd, 그림자 캐스팅 끔 |

벽·바닥이 순백이면 빛이 전부 반사돼서 아무리 낮춰도 밝다. **재질을 어둡게 까는 게 먼저**였다.

### 3.5 재질 — 컴포넌트 오버라이드로

### 4.1 패널이 안 보였던 이유 두 가지

**① `drawSize`는 픽셀인데 월드 크기로 렌더된다.**
`WidgetComponent`의 `drawSize 700×420`이 월드 스케일 1.0에서 **700 유닛 = 7m**로 그려졌다. 화면을 뒤덮을 만큼 커서 벽처럼 보였다. 절대 스케일 0.1로 낮춰 **70cm × 42cm 실물 크기**로 맞췄다 (`NFR-UX-001` "약 1m에서 읽힐 것" 기준).

**② 부모 액터 스케일이 자식 컴포넌트에 상속된다.**
유물 액터 스케일이 0.3이라 자식 패널도 0.3배로 줄어든다. `relativeScale3D`를 3.33으로 보정하면 월드 스케일이 1.0이 된다.

**참고:** `bHiddenInGame`은 **플레이 중에만** 숨기는 옵션이다. 에디터 뷰포트에서는 원래 보인다.

## 5. 한글 폰트 — 원인이 두 개였다

패널 제목이 `??????  (???)`로 나왔다. 폰트만 문제가 아니었다.

### 5.1 엔진에 한글 글리프가 없다

```text
/Engine/EngineFonts/Roboto            라틴 전용
/Engine/EngineFonts/DroidSansMono     라틴 전용
/Engine/EngineFonts/SmallFont, TinyFont, RobotoTiny, ...
```

전부 한글이 없다. 폰트 에셋을 만들지 않으면 `FR-UI-007`(한국어 UI, MUST)이 **원천적으로 불가능**하다.

### 5.2 전송 단계에서 이미 깨져 있었다

폰트를 물린 뒤에도 텍스트 **값 자체**가 `??????`로 저장돼 있었다. HTTP 본문이 UTF-8로 전송되지 않아서 **언리얼에 도착하기 전에 이미 `?`로 뭉개진** 상태였다. `Content-Type`에 `charset=utf-8`을 명시해 해결했다.

> 이걸 못 찾았으면 "폰트 깔았는데 왜 여전히 깨지지"로 한참 헤맬 뻔했다. **증상이 같아도 원인이 여러 개일 수 있다.**

### 5.3 임포트는 MCP로 안 된다

MCP 툴셋에 에셋 임포트 기능이 없고, 언리얼 자동 임포트 감시(`bMonitorContentDirectories`)는 켜져 있어도 에디터가 포커스를 받아야 동작하는 것으로 보인다. → **Content Browser에서 직접 Import**

임포트하면 `FontFace` 1개 + `Font` 2개가 생긴다. `Runtime` 캐시일 때 타이프페이스 이름은 `Default`다.

### 5.4 남은 숙제 — FE(공세민) 담당 영역

맑은 고딕은 **동작 확인용**이다. 배포 전에 정리해야 한다.

| 문제 | 내용 |
|---|---|
| 라이선스 | Windows 번들 폰트라 APK 임베드 배포에 제약이 있을 수 있다. `NFR-ETH-002`가 자산 100%의 출처·라이선스 표시를 요구하는데 폰트만 불명이면 앞뒤가 안 맞는다 |
| 용량 | 12.8MB. Quest 2 내부 빌드에 부담 → 실제 쓰는 글자만 추린 **서브셋 폰트** |
| 대안 | Noto Sans KR, 나눔고딕 등 SIL/OFL 계열 |

명세 6.2에서 폰트·문구·가독성은 FE 책임이므로 **공세민과 맞춰야 한다.**

## 6. 근접 정보 패널 로직 (미완)

`FR-UI-001`(근접 자동 표시) / `FR-UI-002`(가장 가까운 1개만) 로직을 DSL로 쓰다가 컴파일 타임아웃으로 중단됐다. 다만 **작성 과정에서 설계 결함 두 개를 찾았다.**

### 6.1 `Distance` 대신 `Distance2D`를 써야 한다

3D 직선거리를 쓰면 **높이 차이가 거리에 섞여 들어간다.**

```text
유물 중심     z = 115cm (전시대 100 + 유물 반높이)
플레이어 원점  z = 0cm

설정한 반경          220cm
실제 수평 반경  √(220² − 115²) ≈ 187.5cm
```

전시대 높이를 1.2m로 올리면 반경이 1.83m로 **저절로 바뀐다.** 나중에 디버깅하기 짜증나는 종류의 버그다.

### 6.2 Pawn 액터 원점이 아니라 카메라 기준으로 재야 한다

`GetActorLocation(pawn)`은 **폰의 원점이지 머리 위치가 아니다.** 룸스케일 VR에서 갈라진다.

- 스틱으로 이동 → 폰 액터가 움직임 → 거리 정상 ✅
- **실제로 한 발짝 걸어감 → HMD만 움직이고 폰은 제자리** → 유물 코앞인데 패널이 안 뜸 ❌

명세 `FR-VR-004`가 스틱 연속 이동이라 주 경로는 괜찮지만, 시연자가 무의식적으로 몸을 기울이는 건 막을 수 없다.

### 6.3 깜빡임 방지 — 히스테리시스

명세 21.3 대응으로 **표시 2.2m / 해제 3.0m**로 임계값을 다르게 뒀다. 경계에서 왔다 갔다 해도 껌뻑이지 않는다.

### 6.4 반경은 얼마가 맞는가 — 실기에서만 알 수 있다

실제 박물관 참고값:

| 구분 | 통상 범위 |
|---|---|
| 유물~관람자 최소 이격 | 약 0.5~1m |
| 진열장 앞에서 들여다보는 거리 | 약 0.4~0.8m |
| 통로 폭 | 1.5m 이상 |

**관람자가 유물에 관심을 갖는 거리는 대체로 1m 안쪽**이다. 현재 1.88m는 그보다 훨씬 넓다.

그리고 **화면에서 잰 2m와 헤드셋에서 느끼는 2m는 다르다.** HMD에서는 거리를 실제보다 가깝게 지각하는 경향이 있고, IPD 설정과 Quest 2의 좁은 시야각(약 90°)이 여기에 영향을 준다. 함정은 **패널이 뜨는 거리와 읽히는 거리가 따로 노는 것** — 2m 밖에서 뜨면 "떴는데 뭐라는지 모르겠네"가 된다.

→ `ShowRadius`를 인스턴스 편집 변수로 빼두고, 헤드셋에서 **1.2 / 1.6 / 2.0m**를 직접 걸어보며 `U-10`을 닫는다.

## 7. OpenXR 런타임 — 오늘 가장 중요한 개념

헤드셋으로 보려다 막혔고, 원인을 파고들면서 개념이 정리됐다.

### 7.1 OpenXR은 "규격"이지 "구현"이 아니다

```text
언리얼 앱
   ↓  OpenXR API로 말을 건다        ← 명세의 "XR 런타임 : OpenXR"
[OpenXR 런타임]                      ← 이걸 골라야 한다
   ├─ Meta 런타임      (Quest 담당)
   └─ SteamVR 런타임   (Steam 기기 담당)
   ↓
실제 헤드셋
```

콘센트 규격을 정했다고 전기가 들어오는 건 아니다. 발전소가 하나 물려 있어야 하고, 그게 **런타임**이다. **Windows에 여러 개 깔릴 수 있지만 활성은 항상 하나뿐이다.**

### 7.2 오늘 막혔던 지점

| | 상태 |
|---|---|
| 언리얼 OpenXR 플러그인 | ✅ 켜짐 |
| Meta 런타임 설치 | ✅ 등록됨 |
| **활성 런타임** | ❌ **SteamVR** ← 여기만 틀림 |

```text
현재 활성 : C:\Program Files (x86)\Steam\...\SteamVR\steamxr_win64.json
필요      : C:\Program Files\Meta Horizon\Support\oculus-runtime\oculus_openxr_64.json
```

이 상태로 `VR Preview`를 누르면 김소영 문서 2-4 문제해결 표의 **회색 화면** 증상이 나온다.

**해결:** Meta Horizon Link 앱 → `Settings → General → OpenXR Runtime → Set Meta Horizon Link as active`, 그리고 `Unknown Sources` ON.

### 7.3 명세는 둘 다 쓰라고 돼 있다

명세 22.2에 **같은 표에 나란히** 있다. 경쟁 관계가 아니라 층이 다르다.

```text
809: | XR 런타임    | OpenXR              | 확정     |
811: | PC VR 연결   | Meta Link (유선/무선) | W1 확인 |
```

### 7.4 SteamVR로도 되긴 한다 — 그래도 Meta를 쓰는 이유

| | Meta 런타임 | SteamVR 런타임 |
|---|---|---|
| 경로 | 언리얼 → Meta → Quest | 언리얼 → SteamVR → Meta → Quest |
| 중간 단계 | 없음 | SteamVR이 항상 떠 있어야 함 |
| 지연 | 더 적음 | 한 겹 더 |

1. 명세가 Meta Link로 못박아뒀다 (811줄, `W1 확인`)
2. **G1 판정의 신뢰도** — 지금은 "UE5 + Quest 2가 되는가"를 판정하는 자리다. SteamVR을 끼우면 실패했을 때 *엔진 문제인지 SteamVR 문제인지* 구분이 안 된다. **게이트 판정은 변수를 줄여야 한다**
3. 김소영 문서가 Meta 기준으로 쓰여 있어 대조하기 편하다

### 7.5 팀 차원의 함의

김신정 조사 노트(명세 926줄):

> PC 한 대에서 Quest 런타임과 PICO 런타임을 **동시에 활성 OpenXR 런타임으로 둘 수 없음**

오늘 상황이 정확히 그 사례다. **같은 PC로 두 기기를 번갈아 테스트하면 매번 런타임 설정을 오가야 한다.** → 기기별로 담당자를 나누는 게 낫다.

### 7.6 프로젝트 설정은 이상 없었다

```text
OpenXR              ✅ 활성
OpenXRHandTracking  ✅ 활성  (D-07 손 추적)
PICOController      ✅ 엔진 내장 — 이름만 보고 끄지 말 것
Meta XR / OculusXR  ✅ 없음  ← 김소영 문서 권장 구성 그대로
```

명세 17장 원칙 6번 **"XR 입력 체계는 하나만, 두 SDK를 섞지 않는다"** 를 지키고 있는 상태다.

## 12. 배운 것 한 줄씩

- OpenXR을 켜는 것과, 어느 OpenXR **구현**을 활성으로 두는가는 다른 문제다.
- 게이트 판정은 변수를 줄여야 한다. 실패했을 때 원인을 특정할 수 없으면 판정 자체가 무의미하다.
- 문서 요약보다 실제 도구 목록을 열어보는 게 정확하다. 한 번 틀렸다.
- 같은 증상이라도 원인은 여러 개일 수 있다. 한글 깨짐은 폰트와 인코딩 두 군데였다.
- 화면에서 잰 치수와 헤드셋에서 느끼는 치수는 다르다. 수치 확정은 실기에서.
