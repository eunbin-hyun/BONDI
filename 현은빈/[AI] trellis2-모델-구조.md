## 0. 한 줄 요약

사진에서 **"어디에 물체가 있나"를 성긴 복셀로 먼저 뽑고**, 그 복셀마다 **모양 잠재값과 재질 잠재값을 두 번의 확산 생성으로 채운 뒤**, 이를 **메시와 PBR 텍스처로 풀어내는** 3단계 생성 파이프라인이다.

```text
입력 PNG
  → RMBG-2.0                  배경 제거 (알파 마스크)
  → DINOv3                    이미지 특징 토큰 추출 (조건 벡터, 512/1024 두 해상도)
  → [1단계] Sparse Structure  물체가 차지하는 복셀 좌표 생성 (32³ 또는 64³ 격자)
  → [2단계] Shape SLAT        복셀마다 32채널 모양 잠재값 생성
  → Shape Decoder             잠재값 → O-Voxel 표면 (메시)
  → [3단계] Texture SLAT      이미지 + 모양을 조건으로 재질 잠재값 생성
  → Texture Decoder           base color / roughness / metallic / opacity
  → 메시에 PBR 베이크 → GLB
```

핵심 수확 세 가지.

1. **3D 생성의 병목은 "어디를 계산할 것인가"다.** 밀집 복셀은 불가능하고, 표면이 지나는 복셀만 골라내는 것이 모든 단계의 전제다.
2. **모양과 재질을 분리해서 두 번 생성한다.** 재질 단계가 모양을 조건으로 받기 때문에 텍스처가 형상에 맞는다.
3. **4B 모델이 8GB에서 도는 이유는 모델을 쪼개서 한 번에 하나만 GPU에 올리기 때문이다.** 모델 크기가 아니라 "동시에 올라가는 크기"가 VRAM을 결정한다.

## 1. 단계별 모델 구성

`pipeline.json`에 선언된 모델 목록이다.

| 단계 | 모델 (ckpts 이름) | 크기 | 하는 일 |
| --- | --- | --- | --- |
| 배경 제거 | RMBG-2.0 | 소형 | 물체만 남긴 RGBA 만들기 |
| 조건 추출 | DINOv3 | 약 0.3B | 사진을 패치 토큰으로 변환. 텍스트 대신 이 토큰이 프롬프트 역할 |
| 1. 희소 구조 생성 | `ss_flow_img_dit_1_3B_64` | 1.3B DiT | 어느 복셀이 비어 있고 어느 복셀이 채워졌는지 생성 |
| 1. 디코더 | `ss_dec_conv3d_16l8` (TRELLIS v1 것 재사용) | 소형 | 잠재 격자 → 실제 복셀 점유 |
| 2. 모양 생성 | `slat_flow_img2shape_dit_1_3B` (512 / 1024 두 버전) | 1.3B DiT | 채워진 복셀 각각의 국소 형상 잠재값 |
| 2. 디코더 | `shape_dec_next_dc_f16c32` | 소형 | 잠재값 → 표면 기하 |
| 3. 재질 생성 | `slat_flow_imgshape2tex_dit_1_3B` (512 / 1024) | 1.3B DiT | 모양을 알고 나서 표면 재질 잠재값 |
| 3. 디코더 | `tex_dec_next_dc_f16c32` | 소형 | 잠재값 → PBR 채널 |

1.3B DiT 세 개에 인코더와 디코더를 합쳐 "4B 모델"이라고 부른다. 생성 모델(DiT)은 bf16, 디코더는 fp16으로 배포된다.

`ss_dec`의 경로가 `microsoft/TRELLIS-image-large/...`인 것에서 **1단계 디코더는 TRELLIS v1 것을 그대로 가져왔다**는 걸 알 수 있다. 희소 구조 표현은 v1과 v2가 호환된다.

모델 이름의 `f16c32`는 16배 공간 다운샘플, 32채널 잠재값이라는 뜻이다. 즉 1024³ 자산이 64³ 잠재 격자 위의 32차원 벡터들로 압축된다.

## 2. 왜 희소 구조를 먼저 뽑는가

3D를 밀집 복셀로 다루면 1024³은 약 10억 개 셀이다. 어느 하드웨어로도 확산 모델을 돌릴 수 없다.

물체의 **표면이 지나가는 복셀만** 골라내면 수만 개로 줄어든다. 그래서 1단계에서 좌표만 정하고, 2단계와 3단계는 그 좌표 위에서만 계산한다. 2, 3단계의 DiT는 이 복셀들을 토큰 시퀀스로 받는 트랜스포머다.

이 구조에서 나오는 실무적 결과 두 가지.

- **배경이 남은 사진을 넣으면 여기서 복셀 수가 폭증한다.** 배경 벽, 바닥이 전부 표면으로 잡혀 토큰이 늘고, 뒤 단계 메모리가 터진다. 투명 PNG를 넣으라는 이유가 이것이다.
- **메모리 사용량은 모델 크기가 아니라 복셀(토큰) 수에 비례한다.** 같은 모델이라도 입력에 따라 OOM이 나거나 안 난다. 포크 코드는 `max_num_tokens=49152`로 상한을 둔다.

## 3. SLAT — Structured Latent

복셀 하나에 **위치 좌표 + 32차원 벡터**를 붙인 표현이다. 이 벡터 하나가 그 복셀 근처의 미세한 표면 형태(또는 재질)를 압축해 담고 있고, 디코더가 풀어낸다.

TRELLIS v1은 SLAT 하나에서 가우시안 스플랫, 메시, Radiance Field를 각각 다른 디코더로 뽑았다. TRELLIS.2는 **모양 SLAT과 재질 SLAT을 분리**했다.

```text
Shape SLAT   : 이미지 조건            → 형상 잠재값
Texture SLAT : 이미지 조건 + Shape SLAT → 재질 잠재값
```

3단계 모델 이름이 `imgshape2tex`인 것이 이 구조를 말한다. 재질 생성이 이미 확정된 모양을 조건으로 받기 때문에, 텍스처가 형상 경계에 맞게 나온다. v1에서 텍스처가 형상과 살짝 어긋나던 문제를 구조적으로 막은 것이다.

`pipeline.json`에는 두 SLAT 각각의 채널별 `mean`, `std` 32개가 들어 있다. 잠재값을 표준화해서 확산 모델이 다루기 쉬운 분포로 만든다.

---

## 4. 생성 방식 — 플로우 매칭

Stable Diffusion과 같은 계열이지만 노이즈 스케줄 대신 **직선 경로를 학습한 rectified flow**다. 세 단계 모두 `FlowEulerGuidanceIntervalSampler`를 쓴다.

| 설정 | 1단계 (구조) | 2단계 (모양) | 3단계 (재질) |
| --- | --- | --- | --- |
| 샘플러 | 오일러 | 오일러 | 오일러 |
| 스텝 | 12 | 12 | 12 |
| CFG 강도 | 7.5 | 7.5 | 7.5 |
| CFG 적용 구간 | 0.6 ~ 1.0 | 0.6 ~ 1.0 | 0.6 ~ 1.0 |
| guidance_rescale | 0.7 | 0.5 | — |

눈여겨볼 점.

- **12스텝.** 이미지 확산 모델의 20~50스텝보다 훨씬 적다. rectified flow는 경로가 직선에 가까워 적은 스텝으로 수렴한다. H100에서 512³ 3초, 1024³ 17초가 나오는 이유의 하나다.
- **가이던스 구간 제한.** CFG를 전 구간이 아니라 t가 0.6~1.0인 초반(노이즈가 큰 쪽)에만 적용한다. 큰 구조는 조건을 강하게 따르게 하고, 세부 마무리는 조건 없이 자연스럽게 두는 방식이다. CFG를 전 구간에 걸면 과포화되는 문제의 해법이다.
- **조건은 DINOv3 토큰이다.** 텍스트 인코더가 없다. 사진의 패치 특징이 직접 크로스 어텐션으로 들어간다. 그래서 텍스트로 수정하는 것은 안 되고, 결과를 바꾸려면 사진을 바꿔야 한다.

## 5. O-Voxel과 출력

디코더가 내는 것은 복셀 안에서 표면이 어디를 지나는지 기술하는 **O-Voxel** 표현이다. 논문은 이를 "field-free"라고 부른다. SDF나 occupancy field처럼 공간 전체에 정의된 함수를 두지 않고, 표면 복셀 각각이 자기 안의 표면 조각을 직접 기술한다. 그래서 얇은 판, 구멍, 뚫린 구조 같은 **복잡한 토폴로지**가 살아남는다.

출력은 메시에 PBR 네 채널을 베이크한 GLB다.

| 채널 | 의미 |
| --- | --- |
| base color | 기본 색 |
| roughness | 거칠기 |
| metallic | 금속성 |
| opacity | 투명도 (유리, 얇은 천 표현) |

TRELLIS v1은 가우시안 스플랫과 메시를 따로 냈고 텍스처는 뷰에서 베이크했다. TRELLIS.2는 재질을 생성 단계에서 직접 뽑기 때문에 언리얼에 넣으면 머티리얼 셋업이 거의 필요 없다. 09-03에 겪은 GLB 스케일과 축 문제는 그대로 해당된다.

## 6. 해상도 옵션 — 512 / 1024 / cascade

`run()`의 `pipeline_type` 인자다. 1단계 격자 크기(`ss_res`)와 쓰는 모델이 다르다.

| 옵션 | 1단계 격자 | 모양 | 재질 | 무게 |
| --- | --- | --- | --- | --- |
| `512` | 32³ | 512 모델 | 512 모델 | 가장 가벼움 |
| `1024` | 64³ | 1024 모델 | 1024 모델 | 가장 무거움 |
| `1024_cascade` | 32³ | 512로 뽑고 1024로 업샘플 | 1024 모델 | 1024보다 가벼움 |
| `1536_cascade` | 32³ | 같은 방식으로 한 단계 더 | 1024 모델 | — |

`1024`는 1단계부터 64³ 격자를 쓰기 때문에 복셀 수가 크게 늘어 가장 무겁다. `1024_cascade`는 큰 구조를 32³에서 잡고 세부만 올리는 방식이라 같은 최종 해상도에서 메모리가 덜 든다.

8GB에서는 `512`로 성공을 확인하고, 올릴 때는 `1024`보다 `1024_cascade`가 안전하다.

## 7. 8GB에서 돌아가는 원리 — low_vram 모드

포크의 `low_vram` 모드가 하는 일을 `run()`에서 그대로 읽을 수 있다.

```python
if self.low_vram:
    self.image_cond_model.to(self.device)   # DINOv3를 GPU로
cond_512 = self._cast_cond(self.get_cond([image], 512))
if self.low_vram:
    self.image_cond_model.cpu()             # 끝나면 CPU로
    torch.cuda.empty_cache()
```

이 패턴이 1단계 플로우 모델, 1단계 디코더, 2단계 플로우 모델, 2단계 디코더, 3단계 플로우 모델, 3단계 디코더 각각에 붙어 있다. **단계마다 필요한 모델 하나만 GPU에 올리고 끝나면 내린다.**

| 항목 | 전부 올릴 때 | low_vram |
| --- | --- | --- |
| 동시에 GPU에 있는 DiT | 3개 (약 7.8GB) | 1개 (약 2.6GB) |
| 나머지 모델 위치 | GPU | 시스템 RAM |
| 단계 전환 비용 | 없음 | PCIe 복사 시간 추가 |

bf16 1.3B DiT 하나가 약 2.6GB라 한 번에 한 개만 있으면 8GB 안에서 활성값 자리가 남는다. 나머지는 노트북의 64GB RAM에 대기한다. 그래서 8GB 노트북에서는 **RAM 용량이 실질적 요구사항**이 되고, 단계 전환 때 모델이 오가는 시간이 생성 시간에 더해진다.

여기서 배운 것. **VRAM 요구량은 "모델 총 크기"가 아니라 "한 시점에 GPU에 올라가 있어야 하는 것의 크기"다.** 공식 24GB 요구는 전부 올려놓고 빠르게 돌리는 조건이고, 시간을 내주면 메모리를 깎을 수 있다. 이건 이 모델만이 아니라 다단계 파이프라인 전반에 적용되는 원리다.

## 8. TRELLIS v1과의 관계

두 모델은 같은 뼈대를 공유한다.

```text
희소 구조 생성 → SLAT 생성 → 디코딩
```

| | TRELLIS v1 | TRELLIS.2 |
| --- | --- | --- |
| 공개 | 2024-12 | 2025-12 |
| 크기 | 1.2B | 4B (1.3B × 3) |
| 이미지 인코더 | DINOv2 | DINOv3 |
| SLAT | 하나 | 모양 + 재질 분리 |
| 표면 표현 | SDF / FlexiCubes | O-Voxel (field-free) |
| 출력 | 가우시안 / 메시 / Radiance Field | PBR 메시 |
| 공식 VRAM | 16GB | 24GB |
| 라이선스 | MIT | MIT |

v1의 1단계 디코더를 그대로 재사용하는 것에서 알 수 있듯이 희소 구조 표현은 같고, 바뀐 것은 그 위에 얹는 잠재값의 구성(모양·재질 분리)과 디코딩 방식(O-Voxel)이다. 우리 용도(유물 하나를 사진에서 뽑아 전시실에 놓기)에는 PBR 메시가 바로 나오는 TRELLIS.2가 맞다.
