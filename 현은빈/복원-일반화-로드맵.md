## 0. 한 줄 요약

복원에는 축이 넷인데 **형상 셋이 한 덩어리로 묶여 있다.**
원통 좌표(표현) = 회전대칭(근거) = θ-h 빈칸(영역) 이라 하나를 빼면 전부 무너진다.
이 문서는 셋을 분리해 **하나씩 갈아끼울 수 있게 만드는 순서**다.
넷째인 재질은 이미 분리돼 있고 [별도 문서](%5BAI%5D%20%EC%9E%AC%EC%A7%88-trellis2-%ED%85%8D%EC%8A%A4%EC%B2%98%EB%A7%81.md)로 나갔다.

> v24 를 버리자는 것이 아니다. 이 유물에는 v24 가 최선이고, 아래는 **다음 유물을 위한 준비**다.
> 다른 기종 하나로 검증하기 전에는 v24 경로를 바꾸지 않는다 (§5 게이트).

### 0.2 AI 가 들어가는 자리는 둘뿐이다

```text
사진 한 장
   │
   ├─[A] 손상 3D 생성 ── TRELLIS.2 ───────────────────── AI ①
   │      └→ 손상 GLB (메시 + PBR)
   │            │
   │   ┌────────┴─────────┐
   │  region_carried   [B] 결손 채움                     형상 축
   │   (무수정)            │
   │          ┌────────┬───┴─────┬──────────┐
   │       v24 현재  S6 대안  S11 참고유물  S9 보류
   │      (y,θ) 격자  SDF 볼륨   프로파일     학습 prior ── AI ③
   │      + 회전대칭  + S8      (학습 없음)   (마지막 수단)
   │
   └─[C] 재질 ── TRELLIS.2 텍스처링 (S10) ─────────────── AI ②
                  형상에 일절 개입하지 않는다
```

## 1. 축이 넷이다 — 형상 셋 + 재질

| 축 | 질문 | 틀리면 | 지금 쓰는 것 | 일반화 |
| --- | --- | --- | --- | --- |
| **표현** | 면이 한 덩어리로 붙는가 | 조각남 | `(y, θ)` 격자 — 정점 공유로 **정의상 보장** | 회전체 전용 |
| **근거** | 무슨 모양으로 채우는가 | 형상이 틀림 | 회전대칭 프로파일 + 이중조화 | 회전체 전용 |
| **영역** | **어디를** 채우는가 | 투창을 메우거나 파손을 남김 | 크기 문턱 + n-fold 푸리에 | **θ 축이 있어야 성립** |
| **재질** | 채움면이 관측면과 같아 보이는가 | 얼룩짐 | TRELLIS 텍스처링 (S10) | **이미 형태 무관** |

**형상 세 축이 독립이라는 것이 이 문서의 전제다.** 실제로 독립이다 —
**영역 판정을 고치면 v24 경로와 SDF 경로가 똑같이 이득을 본다.** 판정 결과가 마스크 한 장이기 때문이다.

**재질은 이미 떨어져 나갔다.** S10 이 형상에 일절 개입하지 않고 노드별로 골라 쓸 수 있게 끝났으므로
아래 순서에 끼우지 않는다. 전문은 [재질-trellis2-텍스처링.md](%5BAI%5D%20%EC%9E%AC%EC%A7%88-trellis2-%ED%85%8D%EC%8A%A4%EC%B2%98%EB%A7%81.md).

### 1.1 영역이 가장 약한 고리다

표현과 근거가 아무리 좋아도 **어디를 채울지가 틀리면 결과가 틀린다.** 그리고 지금 가장 덜 됐다.

"관측이 없다" 에는 원인이 셋인데 **둘만 가르고 있다.**

| 원인 | 현재 처리 | 맞나 |
| --- | --- | --- |
| 깨져서 없다 | 채움 | ✓ |
| 원래 구멍이다 (투창) | 문턱 + n-fold 로 제외 | ✓ 이 유물은 |
| **사진이 못 본 곳** | **`region_carried` 에 섞여 있다** | **✗ (S1)** |

세 번째가 양쪽으로 틀린다.

- 뒷면에 파손이 있었는데 TRELLIS 가 매끈하게 메웠다 → **결손 판정이 아예 안 일어난다** (과소)
- TRELLIS 가 뒷면을 엉성하게 만들었다 → **없던 파손을 복원한다** (과채움). 원본 근거가 없어 검증도 불가

카메라 IoU 85.5% 는 **사진 시점**의 검증치다. 반대편은 검증된 바 없다.

### 2.1 검토했으나 제외한 경로 (2026-09-11)

### 2.2 AdaPoinTr 를 직접 돌려 확인했다 (2026-09-14)

§2.1 의 `PoinTr · AdaPoinTr` 행이 확장판까지 묶어놓고 증거는 PoinTr 것만 달고 있었다.
*"확장판은 다르지 않나"* 로 다시 꺼내지지 않게 **직접 돌렸다.**
작업 폴더는 `restore/adapointr-eval/` — 배경·데이터·모델·결과가 각각 md 로 있다.

**같은 모델이 한쪽은 메우고 한쪽은 아무것도 안 한다. 차이는 모델이 아니라 입력이다.**

| 실험 | 입력 | 결과 |
| --- | --- | --- |
| 완형 9점을 합성으로 깸 (쌍 72개) | 굽다리를 잘라낸 고배 | **메운다** — 결실 커버리지 순증 0.785 |
| `RR_07_01_EA_028` (08-28 과 동일) | 바닥 없는 돔 | **결실 하부 출력점 0개** |

EA_028 에서 PoinTr 대비 숫자는 **전부 좋아졌다** — 잔존부 정합 3.5 → 0.8mm,
엉뚱한 보충점 960 → 82개. **그런데 개선이 전부 "입력을 더 충실히 재현하는" 방향이다.**
막힌 지점은 "입력에 없는 것을 만드는" 쪽인데 거기는 0 그대로다.

**실제 대상 71489 로도 확인했다** — 그냥 넣으면 보충점 20/8192,
v32 의 `region_filled` 로 껍질을 잘라 구멍을 만들어 넣어도 **71개 · 커버리지 순증 0.000**.

**갈리는 것은 결손의 크기가 아니라 "비교할 기준이 남아 있는가" 다.**

| | 예 | 결과 |
| --- | --- | --- |
| **기준 있음** — 나머지 둘레가 멀쩡하고 한 구간만 결손 | 합성 `rim`·`side`·`bottom` | **메운다** 0.785~0.996 |
| **기준 없음** — 둘레 전체가 제각각 | **71489 아가리** | **0** |
| **기준 없음** — 남은 형상이 그 자체로 완형 | EA_028 하부 몸통 | **0** |

71489 는 아가리에 깊은 V자 결손도 있고 측면 결실도 큰데 **그래도 0** 이다.
국소이냐 아니냐가 아니라, 모델이 *"여기서 벗어났다"* 고 볼 **기준 테두리**가 남았느냐가 갈린다.
장서진 [08-26](../%EC%9E%A5%EC%84%9C%EC%A7%84/2026-08-26.md) 의 PoinTr 부적합 사유 ③
*"침식형 결손을 결손으로 인식 못 함"* 과 같은 얘기다.

### 2.3 정규화 누출 — §2.2 의 숫자를 뒤집었다 (2026-09-14 밤)

합성 평가에서 `partial` 을 **`complete` 의 중심·축척**으로 정규화하고 있었다.
그러면 잘려나간 쪽에 빈 공간이 남아 **모델이 원래 크기를 액자에서 읽는다.**
실제 유물에는 complete 가 없으니 그 단서가 없다.

같은 쌍·같은 가중치로 정규화만 바꿔 쟀다.

| ragged 깎임 깊이 | complete 기준 | **자기 정규화 (실제 조건)** |
| --- | ---: | ---: |
| 0.10~0.20 | 순증 **0.700** | **0.102** |
| 0.40~0.50 | 순증 **0.521** | **0.019** |

**§2.2 의 "메운다(0.785)" 는 누출된 값이다.** 실제 조건에서 사전학습 모델은 거의
아무것도 안 메운다 — 71489 의 보충점 20 은 이상한 값이 아니라 정상이었다.

> 우리 코드만의 문제가 아니다. **ShapeNet-55 벤치마크가 partial 을 완형의 정준
> 좌표계에 두고 만든다.** 모델이 그 단서에 기대도록 학습됐고, 그게 실제 유물에서
> 무너지는 이유다.

### 2.4 그래서 파인튜닝은 되나 — 된다. 다만 기종 특화다

자기 정규화로 900쌍(완형 9점 × 5패턴 × 20) 파인튜닝했다.

| 패턴 | 사전학습 | **파인튜닝** |
| --- | ---: | ---: |
| `bottom` 순증 | 0.025 | **0.939** |
| `rim` 순증 | 0.375 | **0.975** |
| `ragged` 순증 | 0.181 | **0.832** |
| `none` 보충점 (과채움) | 1 | 7 — 안 늘었다 |
| 잔존부 오차 중앙 | 1.16mm | **2.98mm** ← 대가 |

**크기 단서 없이도 완성을 배운다.** 다만 셋이 남는다.

| | |
| --- | --- |
| **깊은 손상은 약하다** | 깎임 0.40~0.50(71489 수준)에서 순증 0.179 |
| **관측부가 나빠진다** | 잔존부 정합 1.16 → 2.98mm. `NFR-ETH-003` 관점에서 그냥 넘길 수 없다 |
| **기종 밖은 안 된다** | `EA_028`(항아리)은 결실 하부 15점. 굽다리바리로 학습한 모델이다 |

실제 71489 는 보충점 20 → 253 으로 올랐고 **결손부에 몰린다.** 다만 v32 수준의
아가리 복원까지는 못 간다.

**결론: 제외 판단은 유지하되 이유가 바뀐다.** "못 한다"가 아니라
**"기종별로 학습해야 하고, 그 대가로 관측부 충실도를 잃으며, 깊은 결손에는 여전히 약하다"** 이다.
회전대칭 가정(v24~v32)은 이 셋 어디에도 걸리지 않는다 — 둘레가 전부 깎여도
남은 프로파일에서 `r(y)` 를 세우면 되고, 관측부를 건드리지 않으며, 기종 무관이다.

### S2. 구연부 — 입구는 구멍이 아니라 경계다

### S6. SDF 볼륨 표현 전환 — 보류

**왜 보류.** 표현을 바꿀 이유는 "비회전체에서도 면이 붙게" 인데,
**S8(볼륨 이중조화)이 같은 문제를 더 싸게 푸는지 먼저 봐야 한다.** S8 이 되면 S6 는 필요 없을 수 있다.

**근거는 강해졌다.** §4.3 에서 본 대로 TRELLIS v1 이 v2 보다 면을 잘 잇는 이유가
**공유 스칼라장(꼭짓점 SDF)** 이다. S6 는 그 원리를 학습 모델 없이, 해상도 제약 없이 가져오는 것이다.

**아이디어만 적어둔다.** 마칭큐브는 0-레벨셋에서 항상 연속 다양체면을 뽑으므로
격자가 준 보장을 형태 제약 없이 얻는다. provenance 는 **오려붙이기**로 지킨다.

```text
1. 관측 메시 → narrow-band TSDF
2. 결손 영역 SDF 를 채운다              ← 근거 슬롯 (S7/S8/S9)
3. 마칭큐브 → 완형 연속면 M_full
4. M_full 삼각형별 원본까지 거리 d
     d <  ε → 버린다 (관측 영역)
     d >= ε → 남긴다 = M_fill
5. 원본 관측 메시(무수정) + M_fill = 2노드
```

M_fill 은 M_full 의 부분집합이라 내부가 완전히 연속이고, 잘린 테두리는 이미 ε 이내로 붙어 있다.
지금 D+ 의 경계 스냅 1,262정점 이동이 불필요해진다.

**미정 — 거의 전부.**

- TSDF 인가 UDF 인가. 관측 메시가 비다양체 변 22개를 갖고 있어 부호 결정이 안 될 수 있다
- narrow band 폭, 볼륨 해상도, 메모리 (8GB 노트북)
- 오려내기 ε 값
- **`o_voxel.postprocess.to_glb` 의 remesh 와 겹치는가.** §4.2 에서 확인했듯 remesh 가 이미
  비슷한 일을 하고 있다. 중복이면 안 만들어도 된다

### S7. 대칭 검출 — 가정을 측정으로 바꾼다

**왜.** 지금 manifest 가 `"회전대칭 가정"` 이다. 검증 가능한 가정 하나라는 것이 이 경로의 값어치인데,
**정작 그 가정이 얼마나 맞는지 숫자가 없다.**

**무엇을 바꾸나.** 파이프라인을 안 건드리고 측정만 하는 새 스크립트.

```text
회전:  축 후보마다 θ 회전 → 원본과 chamfer 거리 곡선
       최소점 주기 = n-fold 차수 · 최소값 = 대칭 잔차(mm)
반사:  평면 후보마다 미러 → chamfer
```

**얻는 것 셋.**

1. manifest 승격 — `"회전대칭 가정"` → `"회전대칭 검출, 잔차 1.2mm"`
2. **기종 자동 분기** — 굽다리바리는 회전잔차가 낮고, 손잡이 달린 기종은 회전잔차가 높고 반사잔차가 낮다.
   파이프라인이 스스로 다른 근거를 고를 수 있다
3. [투창-n-fold-판정.md](%5B%EC%88%98%ED%95%99%5D%20%ED%88%AC%EC%B0%BD-n-fold-%ED%8C%90%EC%A0%95.md) §3.2 의 미해결 —
   푸리에 1위(띠A 4 / 띠B 3)와 눈 판정(6)이 갈린 것 — 에 **독립 근거**를 준다

**미정.**

- 축 후보를 어떻게 생성할지. `pick_vertical_axis` 가 이미 있으나 그건 축 하나만 고른다

- **결손이 chamfer 를 오염시킨다.** 깨진 쪽은 어느 회전각에서도 안 맞으므로
  잔차가 부풀려진다. 관측 영역만으로 제한하는 방법 **미정**
- "대칭이 있다" 판정 임계 **미정**

### S8. 볼륨 이중조화 — 회전대칭 없이 곡률을 잇는다

**왜.** 지금 `fill_solve` 가 `(y,θ)` 맵에서 푸는 `Δ²u = 0` 은 **회전대칭 잔차** 위에서 푼다.
같은 방정식을 3D 볼륨에서 풀면 **회전대칭 없이** 곡률 연속 채움이 된다. 형태 무관이다.

**무엇을 바꾸나.** `build_mesh_direct.fill_solve` 의 5점 라플라시안을 7점(3D)으로.
경계조건은 관측 밴드 값 Dirichlet. 코드 구조는 그대로다.

**미정.**

- **무엇을 푸는가.** 2D 에서는 `r − r̄(y)` 였다. 3D 에서 대응물은 SDF 인데, 그러면 S6 가 선행된다.
  SDF 없이 푸는 방법이 있는지 **미정** — 이게 이 단계 최대 미정
- 볼륨 해상도와 희소 선형계 크기. `spsolve` 로 될지 반복법이 필요할지
- 검증 대상 — **적색연질토기호(김소영)로 시험할 것.** 굽다리바리는 회전체라 변별이 안 된다

### S9. 학습 prior — 보류

DeepSDF latent 최적화 또는 diffusion SDF inpainting.
**근거가 `"AI 추정"` 으로 떨어지므로 마지막 수단이다.** S6 가 선행되어야 한다.

### S11. 참고유물 프로파일 prior — 회전대칭 가정을 데이터로 바꾼다

**왜.** `fill_solve` 가 지금 쓰는 근거는 **그 유물 자신의 회전대칭 프로파일 `r̄(y)`** 하나다.
결손이 큰 구간에서는 참조할 관측이 없어 외삽이 되고, 비회전체로는 아예 안 넘어간다.
**같은 기종 다른 유물의 프로파일**을 쓰면 두 문제를 동시에 친다.

**이미 있다 — 만들 필요가 없다.** 김소영이
[복원실험-총괄](../%EA%B9%80%EC%86%8C%EC%98%81/%EB%B3%B5%EC%9B%90%EC%8B%A4%ED%97%98-%EC%B4%9D%EA%B4%84.md) §3 에서
굽다리바리 코퍼스로 A1~A9 를 돌려놨다.

| | 결과 |
| --- | --- |
| **A7 — 이 계열의 기준 방법** | prior 39점 · 잠근 테스트 12점 · **uniform kNN-5 RMSE 0.0698** (전역평균 0.135 대비 약 48% 감소) |
| A8 — 반증 | 밴드 투표·잔차 전이·softmax·2-cluster 로 복잡하게 해도 **균등 kNN 대비 추가 이득 없음** |
| A3 — 제약 | 굽각·몸통 폭 불일치로 기하 게이트 통과 0개 → **직접 donor mesh 사용 기각.** 프로파일 통계로만 쓴다 |

**무엇을 바꾸나.** `build_mesh_direct.fill_solve` 의 Dirichlet 경계값을
`r̄(y)`(자기 회전대칭) 에서 **kNN-5 참고 프로파일**로 바꾼다. 이중조화 풀이 자체는 그대로다.

**값어치 넷.**

1. **학습이 없다.** 프로파일 kNN 평균이라 8GB 무관, 학습 시간 0
2. **provenance 가 안 떨어진다.** 근거가 `"참고유물 N점의 kNN-5 평균"` 이고
   **어느 유물을 참조했는지 열거 가능**하다. S9 의 `"AI 추정"` 과 결정적으로 다르다
3. **축이 맞다.** S6·S8 이 "어떻게"(표현·수학)라면 S11 은 "무슨 모양으로"(근거)다. 충돌하지 않는다
4. **S7 을 대체할 수도 있다** — 대칭이 얼마나 맞는지 재는 대신 가정을 아예 데이터로 갈아끼운다

**미정.**

- **71489 가 prior 39점 안에 들어 있는가.** 들어 있으면 자기 자신을 참조하게 된다
- **평가 단위.** A7 수치는 **정규화 사진 프로파일 내부 평가**다.
  mm·3D Chamfer·71489 복원 정확도로 **바꿔 읽으면 안 된다** (총괄 §3 경고)
- 프로파일을 `(y,θ)` 격자 경계값으로 옮기는 변환 — 축 정렬과 높이 정규화 기준 **미정**
- **중복 확인이 먼저다.** 총괄 §2 에 김소영이 09-10~09-11 에 **71489 를 직접** 만진 기록이 있다
  (`chunk 3a` 좌표계 오류 발견 → 옛 실패 결론 철회 · `chunk 3b` 축 주입 →
  `profile_complete` 는 민감도로 기각, `local_bracket` 은 아티팩트 남은 중간 결과).
  **착수 전에 어디까지 했는지 맞춰볼 것** — 이미 답이 나와 있을 수 있다

#### S11 착수 기록 (2026-09-12~14) — **보류**

e뮤지엄 굽다리바리 **43점**으로 직접 만들어 봤다 (`restore/gupdari-shape-prior/`).
랜드마크 정렬 → PCA 로 프로파일 100개 값을 주성분 6개로 줄이는 구성이다.
참고 구조는 3DMM 계열 — 얼굴 랜드마크 자리에 **프로파일 구조 전이점 7~8곳**을 놓는다.

**보류한 이유는 실패가 아니라 불필요다.** 형상 사전은 *"프로파일의 절반 이상이 사라진
유물"* 에 필요한 도구인데, **71489 는 프로파일이 대체로 살아 있어서** 회전대칭 뼈대 +
구연부 회귀로 충분했다. S11 자체는 여전히 유효하고, 착수 시점이 이르렀던 것이다.

**건진 것 셋.**

실루엣 분리를 손으로 짠 규칙에서 사전학습 모델(rembg / U²-Net)로 **그 자리만** 바꿨다.
굽다리바리 27점에서 **굽 오염 중앙 41.1% → 0.0%**, 앙각 추정 사분위폭 8.3° → 3.9°.
v1~v7 내내 못 떼던 그림자가 한 번에 사라졌다.

빗살무늬토기에서는 **반대**였다 (규칙이 U-Net 을 이김, 이면각 4.22° vs 6.92°).
차이는 실력이 아니라 **문제에 쓸 구조가 있느냐**다.

| | 이용할 구조 | 이긴 쪽 |
| --- | --- | --- |
| 결실부 표면 잇기 | 회전체는 회전에 대해 **자기 자신** | 규칙 |

> 문턱값을 일곱 번 만진 것은 **없는 규칙을 찾은 셈**이었다.
> 이 판단 기준은 S9 에도 그대로 쓴다 — [AdaPoinTr 검증](%5BAI%5D%202026-09-15-AdaPoinTr-%EC%99%84%ED%98%95%EA%B2%80%EC%A6%9D.md) 참고.

## 4. S4 결과 요약 — 임계 가설은 반증됐다 (2026-09-11)

> 전문: **[slat-임계-실험.md](%5BAI%5D%20slat-%EC%9E%84%EA%B3%84-%EC%8B%A4%ED%97%98.md)**
> 이 절만 AI 축이라 별도 문서로 뺐다. 여기에는 **로드맵에 영향을 주는 것만** 남긴다.

### 4.1 결론 셋

| # | 결론 | 로드맵에 미치는 영향 |
| --- | --- | --- |
| 1 | `intersected` 임계는 조각남의 손잡이가 **아니다**. logit 중앙 12.156, τ ±3 에 둔감 | **S4 종결 · S5 불필요** |
| 2 | **GLB 위상 ≠ 디코더 위상.** `remesh` 가 경계변 26,921 → 0 으로 닫는다 | **위상 측정 규약 변경** (§4.2) |
| 3 | TRELLIS **v1 이 연결성에 유리한 것은 맞으나** 해상도 64³·PBR 없음으로 대가가 크다 | **S6 의 근거가 강해진다** (§4.3) |

**SLAT 을 형상 복원에 쓰는 경로는 닫는다.** TRELLIS 의 역할은 **A단계 하나**로 확정한다.
2026-09-10 에는 *"latent 문제라서"* 라는 틀린 이유로 내려왔고, 이번에는 실측 근거로 닫는 것이다.

### 4.2 위상 측정 규약이 바뀐다

`o_voxel.postprocess.to_glb(remesh=True, ...)` 가 위상을 다시 만든다.
지금까지의 조각수·경계변 측정이 전부 그 위에서 이뤄졌다.

| | 디코더 직후 | `A_normal.glb` |
| --- | ---: | ---: |
| 조각 (위치 용접) | 2 | 2 |
| **경계변** | **26,921** | **0** |
| 비다양체 변 | 27,729 | 22 |

> **앞으로 위상은 디코더 직후 쿼드에서 잰다.** GLB 에서 재면 remesh 를 재는 것이다.
> [결손-메우는-방법-검토.md](%5B%EC%88%98%ED%95%99%5D%20%EA%B2%B0%EC%86%90-%EB%A9%94%EC%9A%B0%EB%8A%94-%EB%B0%A9%EB%B2%95-%EA%B2%80%ED%86%A0.md) §1 의
> 경계변 0 도 remesh 탓이었다. 다만 **결론(A안 불가)은 그대로다** — 우리가 입력으로 쓰는 것이
> remesh 된 GLB 이기 때문이다.

### 4.3 v1 검토가 S6 를 뒷받침한다

v1 가중치는 이미 로컬에 전부 있다(3.1GB). 표현도 실제로 다르다 —
v1 은 **격자 꼭짓점의 SDF 값**을 쓰므로 이웃이 부호를 공유해 **면이 원리적으로 이어진다.**
v2 `FlexiDualGrid` 는 복셀마다 `intersected` 를 독립 예측한다.

**그런데 v1 이 연결되는 이유가 곧 S6 가 하려는 것이다.** 공유 스칼라장(SDF)이지 학습 모델이 아니다.

| | v1 메시 디코더 | **S6 (SDF 볼륨)** |
| --- | --- | --- |
| 연속면 보장 | 꼭짓점 SDF → 마칭큐브 | **같음** |
| 해상도 | 64³ 고정 | **자유** |
| 재질 | vertex color | v2 PBR 그대로 (A단계 출력) |
| 학습 | 필요 | **없음** |
| provenance | "AI 추정" | **"곡률 연속 외삽" 등** |

→ **v1 은 쓰지 않는다. 원리만 S6 로 가져온다.**

## 7. 버전 이름 규칙 — 폴더 이름만 보고 방법을 안다

v18 부터 태그가 빠져서 `v24` 가 무엇인지 폴더 이름으로 알 수 없다.
`v7-cyl-fixed`·`v9-mirror-cond` 처럼 쓰던 것을 **슬롯으로 고정**한다.

```text
v<번호>-<형상>+<채움>+<개구>+<재질>[+<추가>]
```

| 슬롯 | 값 |
| --- | --- |
| **형상** | `cyl` 원통전개 · `sdf` SDF 볼륨 · `slat` SLAT 주입(종결) |
| **채움** | `biharm` 이중조화 · `harm` 조화 · `fwd` 전진복사 |
| **개구** | `n4`·`n6` n-fold · `deg50` θ폭 문턱 · `none` |
| **재질** | `nn` 최근접 복사 · `lama` LaMa 인페인팅 · `trellistex` 전 면 TRELLIS · `trellisfill` **채움만** TRELLIS |
| 추가 | `unet` 요철 U-Net · `snap` 경계 스냅 · `up2` 메시 업샘플 ×2 · `labshift` Lab 평균 평행이동 · `knn5` 참고유물 kNN-5 프로파일(S11) |

없는 슬롯은 뺀다. 예 — `v28-cyl+biharm+n6+trellisfill+up2` · `v32-cyl+biharm+n6+trellisfill+labshift+up2`

**2026-09-11 에 전부 소급 적용했다.** 매핑은 `restore/out/RENAME_MAP.txt` 에 있고,
오른쪽→왼쪽으로 rename 하면 되돌아간다. 문서·스크립트의 `out/<폴더>` 참조도 같이 고쳤다.
