# 기하·AI 복원 후보 공통 평가 도구

> 작성 기준: 2026-09-11  
> 상태: 공통 인터페이스 v0 구현 완료, 팀 공용 배포 전 보완 중

이 문서는 여러 유물 복원 방법을 같은 기준으로 검사하는 도구의 사용 안내다.

현재 71489 복원 후보는 모두 형상 문제가 남아 있다. 최종 복원 후보는 아직 없다. 이번 단계의
산출물은 **기하 방식과 AI 방식을 함께 시험하는 공통 검사대**다.

## 1. 핵심 요약

- 모든 복원 방법은 같은 입력을 사용한다.
- 복원 방법은 새로 만든 부분만 별도 `patch`로 제출한다.
- 입력 메시의 기존 정점과 면은 그대로 보존한다.
- 완형 정답 데이터가 있을 때만 복원 정확도를 계산한다.
- 근거가 부족한 영역은 열린 상태로 남길 수 있다.
- 기하 방식과 AI 방식은 같은 보존 규칙과 출력 형식으로 비교한다.

```text
동일한 입력 메시
  → 공통 관측점과 원본 보존용 참조 생성
  → 기하 복원 또는 AI 복원 실행
  → 새로 만든 patch만 제출
  → 원본 보존·파일 구조·기권 상태 검사
  → 완형 정답이 있을 때만 정확도 계산
```

## 2. 먼저 알아야 할 용어

| 용어 | 쉬운 설명 |
|---|---|
| 메시 | 3D 물체의 표면을 점과 삼각형으로 표현한 데이터다. |
| 점군 또는 point cloud | 3D 공간에 있는 점들의 모음이다. 삼각형 면이 없는 관측 데이터다. |
| 입력 메시 | 복원을 시작할 때 사용하는 3D 형상이다. 현재 71489 입력은 사진 한 장으로 TRELLIS가 만든 메시다. |
| 공통 case | 한 번의 비교에 사용할 입력 메시, 관측점, 좌표계, 단위, 원본 보존용 참조를 묶은 폴더다. |
| `carried geometry` | 입력 메시에서 복원 결과로 그대로 가져가는 기존 정점과 면이다. 복원 방법이 이동하거나 삭제하면 안 되는 부분이다. |
| 승계한 부분 | 복원 방법이 새로 만들지 않고 입력 메시에서 그대로 가져온 부분이다. 입력에 원래 있던 오류와 파쇄 흔적도 함께 포함될 수 있다. |
| `patch` | 결손을 보완하기 위해 복원 방법이 새로 만든 정점과 면이다. 기존 부분과 분리해서 저장한다. |
| `proxy` | 실물 유물을 직접 측정한 형상 대신 사용하는 대체 입력이다. TRELLIS 생성 메시가 여기에 해당한다. |
| 실측 3D 스캔 | 3D 스캐너나 검증된 사진측량으로 실물 표면을 직접 측정해 만든 데이터다. AI가 한 장의 사진에서 추측해 만든 메시와 구분한다. |
| Ground Truth 또는 GT | 복원 결과와 비교할 수 있는 독립적인 정답 3D 형상이다. 손상 전 완형 실측 스캔이나 정답을 알고 만든 합성 형상이 예시다. |
| 독립 GT | 복원 방법이 생성하거나 참고한 메시와 별도로 확보한 정답이다. 복원 방법의 추측을 다시 정답으로 사용하는 순환 평가를 막는다. |
| `normal` | 3D 표면의 각 점이 어느 방향을 향하는지 나타내는 벡터다. 표면 재구성 모델이 외벽과 내벽을 구분할 때 사용한다. |
| `confidence` | 복원 방법이 각 patch 결과를 얼마나 신뢰하는지 표시하는 값이다. 실제 정답일 확률로 자동 해석하지 않는다. |
| SHA-256 해시 | 파일 내용으로 계산한 긴 식별값이다. 해시가 같으면 두 파일의 바이트 내용이 같다고 확인할 수 있다. |
| seed | 무작위 샘플링을 다시 실행할 때 같은 결과를 얻도록 고정하는 시작 숫자다. |
| `abstained` | 입력 전체에 대해 믿을 만한 결과를 만들 수 없어 복원 방법이 전체 출력을 기권한 상태다. |
| `unresolved` | 일부는 처리했지만 근거가 부족한 특정 영역을 열린 상태로 남긴 결과다. |

### 71489에서 말하는 ‘원본’의 범위

- 보존 대상은 TRELLIS가 사진에서 생성한 입력 메시다.
- 데이터 출처는 사진 한 장을 이용한 TRELLIS 생성 결과다.
- 원본 보존 통과는 **복원 단계가 입력 메시를 추가로 바꾸지 않았다**는 뜻이다.
- 실물 유물과 입력 메시의 정확도는 아직 검증하지 않았다.

## 3. 원본을 보존하는 방법

복원 방법은 기존 파편을 이동해 윤곽을 다듬지 않는다. 새로 추정한 patch만 추가한다.

평가 도구는 복원 전후의 기존 정점 좌표를 직접 비교한다.

```text
복원 전 carried 정점 좌표
복원 후 carried 정점 좌표
            ↓
      하나라도 달라졌는가?
```

- 좌표가 모두 같으면 원본 보존 검사를 통과한다.
- 정점 하나라도 달라지면 원본 보존 검사에 실패한다.
- patch의 품질은 별도 검사 대상이다.
- 원본 보존 통과만으로 복원 성공을 판정하지 않는다.

이 구조를 사용하면 입력에서 가져온 부분과 새로 만든 부분을 색상이나 노드로 구분할 수 있다.
잘못된 patch만 제거하고 입력 메시를 다시 사용할 수도 있다.

## 4. 정확도를 계산하는 조건

복원 정확도는 독립 GT가 있을 때 계산한다.

독립 GT가 있으면 다음 항목을 측정할 수 있다.

- 제거한 영역과 복원 patch 사이의 거리
- Chamfer distance와 F-score
- 원래 열린 투창을 잘못 막은 비율
- 축 고정과 축 재추정 사이의 오차 차이

현재 71489에는 손상 전 완형 실측 스캔이 없다. 지금 검사할 수 있는 항목은 다음과 같다.

- 기존 정점을 바꾸지 않았는가
- patch가 여러 조각으로 끊겼는가
- 비정상적인 경계나 비매니폴드 엣지가 생겼는가
- 축과 설정을 조금 바꿨을 때 결과가 크게 흔들리는가
- 렌더에서 혹·띠·납작해짐이 보이는가

현재 정확도 상태는 `NOT_EVALUATED_NO_INDEPENDENT_GT`다. 평가할 독립 정답이 없다는 의미다.
정상적인 평가 보류 상태다. 실제 유물과의 mm 오차와 정확도 백분율은 산출하지 않는다.

## 5. 근거가 부족할 때의 처리

복원 방법은 두 가지 방식으로 판단을 보류할 수 있다.

- `abstained`: 입력 전체를 처리할 근거가 부족한 상태다.
- `unresolved`: 일부 영역만 처리할 근거가 부족한 상태다.

71489에 적용하면 다음과 같다.

```text
축과 입력 normal 전체가 불안정함
  → 전체 복원 중단
  → abstained

그릇 몸통 일부에는 양쪽 잔존면이 있음
투창대는 의도적 구멍과 파손 구멍을 구분하기 어려움
  → 몸통 patch만 생성
  → 투창대는 unresolved
```

기권과 미해결 표시는 현재 증거가 지지하는 범위를 기록하는 정상 출력이다. 열린 부분이 남아 있어도
관측된 투창을 잘못 막는 결과보다 안전하다.

## 6. 71489에서 확인한 결과

기하 후보 8개를 공통 형식으로 변환해 검사했다. 혹·세로 리브·납작해짐·수평 띠 같은 형상 문제가
남아 있어 최종 후보는 채택하지 않았다.

| 확인 항목 | 결과 | 의미 |
|---|---|---|
| 공통 입력 | 관측점 8,192개와 carried 참조 생성 | 각 방법이 같은 입력을 사용할 수 있다. |
| 재현성 | 같은 seed에서 입력 NPZ SHA 일치 | 같은 설정으로 같은 모델 입력을 다시 만들 수 있다. |
| AI용 입력 | 2,048점 고정 크기 입력의 반복 SHA 일치 | AI 모델 전처리를 고정할 수 있다. |
| 후보 연결 | 기존 기하 후보 8개를 patch-only 형식으로 변환 | 다른 방식의 결과를 한 평가기에 넣을 수 있다. |
| 원본 보존 | 8개 후보 모두 carried 정점 최대 변화 `0.0` | 후보가 입력 메시의 기존 정점을 이동하지 않았다. |
| 정확도 처리 | 독립 GT가 없어 정확도 계산 중단 | 실제 유물과의 정확도는 아직 모른다. |
| 복원 판정 | 채택 후보 없음 | 공통 검사대 동작과 복원 성공을 분리했다. |

direct biharmonic 후보는 매끄러움 수치가 좋았지만 그릇이 납작해졌다. 이 결과는 단일 수치에
의한 자동 채택을 금지하는 근거다. 구체적인 solver 실패 기록은
[굽다리바리 부위별 라우팅](굽다리바리-부위별-라우팅.md)에 둔다.

## 7. NKSR 실행을 중단한 이유

NKSR은 관측점을 연결해 표면을 다시 만드는 방법이다. 입력점의 normal 방향이 안정적이어야 한다.

![71489 normal 품질 검사](images/completion-eval/normal-quality-gate.png)

| 입력 범위 | 원래 normal과 주변점 기반 normal의 차이 p95 | 이웃 수를 바꿨을 때 normal 차이 p95 | 판정 |
|---|---:|---:|---|
| 전체 8,192점 | 67.12° | 68.28° | 중단 |
| 상부 4,096점 | 72.63° | 69.18° | 중단 |
| 허용 기준 | 40° 이하 | 15° 이하 | 두 조건 모두 필요 |

`p95`는 전체 측정값의 95%가 이 값 이하라는 뜻이다. 값이 클수록 일부 점의 방향이 크게 흔들린다.

현재 입력은 두 허용 기준을 모두 넘었다. NKSR 실행은 보류 상태다.

다음 허용 실험은 한 번의 normal 정리다.

- 서로 떨어진 파편 덩어리를 분리한다.
- 외벽과 내벽을 분리한다.
- 각 표면 안에서 normal 방향을 정리한다.
- 같은 기준으로 다시 검사한다.

다시 검사한 뒤 아래 조건 중 하나가 남으면 현재 TRELLIS proxy의 NKSR 실험을 종료한다.

- normal 차이 p95가 40°를 넘는다.
- 이웃 수에 따른 normal 차이 p95가 15°를 넘는다.
- 사용할 수 있는 관측점이 원래 점의 30%보다 적다.
- 외벽과 내벽을 안정적으로 분리하지 못한다.

새로운 360도 사진 기반 점군이 들어오면 같은 검사를 처음부터 다시 실행한다.

## 8. 다른 사람이 사용하는 방법

사용자는 복원 알고리즘의 결과 파일과 실행 정보를 제공한다.

- 사용한 입력 3D 파일과 SHA-256 해시
- 실제 분석 좌표계와 단위
- 새로 만든 patch 점 또는 patch 메시
- 방법 이름·버전·설정
- confidence 값 또는 `unavailable` 표시
- 기존 carried 정점을 수정했는지 여부

현재 코드는 `CommonPJ/mini-project/pedestal-restoration/`에 있다.

```powershell
# 1. 입력 메시를 공통 case로 변환한다.
python src/prepare_completion_case.py --input input.glb --output case `
  --case-id example --artifact-id example --source-kind generated_proxy `
  --sample-count 8192 --seed 0 --up-axis Z --units normalized

# 2. AI 모델용 2,048점 입력을 만든다.
python src/prepare_model_tensor.py case/case.json --output model-input --point-count 2048

# 3. 기존 GLB 후보에서 새 patch만 꺼낸다.
python src/export_glb_patch_prediction.py case/case.json `
  --candidate-glb candidate.glb --output prediction `
  --prediction-id example-method --method-name example --method-version v1

# 4. 원본 보존과 결과 계약을 검사한다.
python src/completion_contract.py case/case.json --prediction prediction/prediction.json
python src/evaluate_completion.py case/case.json prediction/prediction.json `
  --output prediction/evaluation.json
```

서로 다른 입력 메시에서 나온 점수는 직접 비교하지 않는다. 같은 입력 case 또는 같은 독립 GT를
사용한 결과끼리 비교한다.

## 9. v0의 의미와 dev 편입 조건

v0는 핵심 형식이 동작하는 첫 번째 버전이다. 2026-09-11 기준으로 dev 준비 항목 7개 중 6개를
완료했다.

- [x] 절대경로가 없는 작은 실행 예제를 추가했다.
- [x] carried 정점 하나를 변경하면 반드시 실패하는 테스트를 추가했다.
- [x] 정답을 아는 작은 합성 형상에서 Chamfer `0`, F-score `1.0`을 검산했다.
- [x] GLB 노드 방식 외에 별도 patch NPZ 파일을 지원한다.
- [x] append-only 전체 메시와 patch face mask를 함께 받는 형식을 지원한다.
- [x] Python 3.14.6, NumPy 2.5.3, SciPy 1.18.1, Trimesh 5.1.0 검증 버전을 고정했다.
- [ ] 다른 사람의 독립 solver 결과 한 건을 연결한다. 2노드 handoff importer는 준비됐고 실제 파일을 기다린다.

완료한 여섯 항목의 테스트는 모두 통과했다. 상세 실행 기록은 canonical 프로젝트의
`records/completion-dev-smoke.md`에 있다.

이 항목을 통과하면 71489 자료는 실험 사례로 남긴다. 유물에 종속되지 않는 공통 코드만 dev PR로
분리한다. 현은빈의 별도 solver도 알고리즘 코드를 합치지 않고 결과 patch를 이 형식에 연결할 수
있다.

360도 사진 기반 재구성 결과가 들어오면 새 입력 case를 만든다. 기존 기하 후보와 AI 후보는 같은
원본 보존 규칙으로 다시 비교한다.
