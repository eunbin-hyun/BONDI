## 1. 핵심 결론

**1) Blender MCP는 "MCP 서버"가 없어도 소켓만 있으면 쓸 수 있다.**

팀 PC의 Blender 5.2에는 **Blender Lab 공식 MCP 애드온**이 켜져 있고 `localhost:9876`에서 듣고 있다.
Claude 데스크톱 앱에는 이 애드온용 MCP 서버(`uv run blender-mcp`)가 등록돼 있지만 Claude Code 세션에는 없었다.
그래서 소켓에 직접 JSON을 보내는 15줄 클라이언트(`bmcp_client.py`)로 전 과정을 진행했다.

```text
요청:  {"type":"execute","code":"<파이썬>","strict_json":false} + "\0"
응답:  {"status":"ok","result":{...}}  ← 코드 안에서 result 딕셔너리에 담은 값
```

코드는 Blender 메인 스레드에서 돌아가므로 `bpy` 전체(임포트·불리언·베이크·Cycles 렌더·내보내기)가 다 된다.
커뮤니티 `blender-mcp`(ahujasid)와 프로토콜이 다르다. 그쪽은 `{"type":"get_scene_info"}` 식이다.

**2) 회전 대칭 유물은 "프로파일 하나"로 복원된다.**

고배·항아리·토기는 물레 성형이라 (반지름, 높이) 곡선 하나를 회전시키면 완형이 나온다.
파편에서 회전축과 높이별 반지름만 뽑으면 되고, 결손이 절반 넘게 있어도 된다.
권영호의 항아리 회전대칭 복원과 같은 원리인데, 이번엔 점군이 아니라 **메시를 직접 생성**해서 watertight까지 보장했다.

**3) 텍스처 결손도 회전 대칭으로 채울 수 있다.**

UV를 `u = 각도, v = 프로파일 호길이`로 깔면 텍스처의 **한 행이 같은 높이**가 된다.
파편이 없는 구간은 같은 행의 다른 각도를 복사하면 무늬가 자연스럽게 이어진다.
OpenCV 같은 라이브러리 없이 Blender 내장 numpy만으로 4K 텍스처 채우기가 7초에 끝났다.

**4) 파일 형식은 `.glb`가 정답이다.**

같은 모델을 OBJ/GLB/GLTF로 받았는데 OBJ에는 UV만 있고 텍스처가 없었다.
GLB에는 2048² 베이스컬러가 들어 있었다. 단, GLB 재질이 `metallic 1 / roughness 1`로 잘못 박혀 있어 손으로 고쳐야 했다.
AI 생성 서비스(THREE.GLTFExporter로 내보낸 것)의 재질 기본값은 믿지 말고 열어서 확인한다.

## 3. 원형 복원 (형태) — 어제 작업

### 3.1 회전축 추정

z를 48구간으로 나눠 구간별로 (x, y)에 원을 최소제곱 피팅하고, 중심들의 **중앙값**을 축으로 잡았다.
평균이 아니라 중앙값을 쓴 이유는 파편이 한쪽으로 몰려 있어 구간별 피팅이 심하게 튀는 구간이 있기 때문이다.
결과 축은 bbox 중심에서 y로 1.5 cm쯤 벗어나 있었다. bbox 중심을 축으로 쓰면 틀린다.

### 3.2 프로파일 설계

높이별 반지름의 p95(외면)와 원 피팅 반지름을 표로 뽑고, 그걸 보면서 (r, z) 키포인트 55개를 손으로 정했다.
자동으로 곡선을 맞추지 않은 이유는 대각 다리처럼 뚫린 구간은 p95가 의미가 없어서다.

```text
대각 최소 반지름 0.092  →  굽 바닥 0.166  →  배신 최대 0.201 (구연)
벽 두께 0.012 (실물 고배 5 mm 정도에 대응하는 비율)
```

프로파일은 **축 → 대각 내면 하강 → 굽 바닥 → 외면 상승 → 구연 → 배신 내면 하강 → 축** 한 줄로 닫힌다.
축에 닿는 두 점(배신 바닥, 대각 천장)을 삼각형 팬으로 막으면 그대로 수밀 메시다.

### 3.3 생성·절개·검증

1. 1.5 mm 간격 재샘플 → 160분할 회전 → 118,064 정점
2. 투창: 파편의 다리 각도 히스토그램이 55°, 115°, 235°, 295° 근처에 몰려 있어 **60° 주기**로 판단. 2단 × 6개 엇갈림(하단 다리 55°+60k, 상단 25°+60k). Boolean EXACT 차집합
3. 침선 2줄, 돌대 2줄은 프로파일에 가우시안 요철로 넣었다 (**추정**)
4. 검증: 비다양체 모서리 **0**, 파편→복원면 거리 p50 4.1 / p90 12.6 / max 33.4 (파일 단위 × 1000)

### 3.4 출처 구분

복원 메시 각 면의 중심에서 정리본 파편까지 BVH 최단거리를 재서 0.014 미만이면 `Original`, 아니면 `Restored` 재질을 붙였다.
원본 존재 구간이 **75.5%**. 권영호가 LAS classification으로 한 provenance 구분을 메시에서는 재질 슬롯으로 한 것이다.

## 4. 실사 복원 (재질) — 오늘 작업

### 4.1 UV

Smart UV Project를 쓰지 않고 직접 깔았다. 회전체는 `u = atan2(y, x) / 2π`, `v = 프로파일 호길이 / 전체 길이`로 하면 **겹침 없는 전개도 한 장**이 된다.
각 정점의 v는 (r, z)에서 프로파일 최근접점을 찾아 호길이를 읽었다.
경계(u=0) 처리: 한 면 안에서 u 범위가 0.5를 넘으면 작은 쪽에 +1. 축 정점(r=0)은 각도가 없으니 같은 면 다른 정점의 평균 u를 준다.

### 4.2 투영 베이크

파편(GLB) → 복원 메시로 **Selected to Active** 베이크. 케이지 1.5 cm, 최대 레이 3.5 cm.

| 베이크 | 방법 | 결과 |
| --- | --- | --- |
| 색 | Diffuse, Color만 | 파편 텍스처가 복원면 위로 옮겨짐 |
| 커버리지 마스크 | 파편에 흰 Emission 재질을 잠시 입히고 **Emit** 베이크 | 흰=파편 있음. UV 면적의 66.8% |

마스크를 따로 베이크하는 이유는 색 베이크의 검정이 "파편 없음"인지 "파편이 검은색"인지 구분이 안 돼서다.

### 4.3 결손부 채우기 (numpy만)

호스트 Python에는 numpy도 없었고 Blender 내장 Python에는 numpy만 있었다. 그래서 알고리즘을 직접 썼다.

1. **행별 밝기 필터**: 그 행 유효 픽셀의 밝기 중앙값 대비 0.6~1.5배 밖은 무효. AI 텍스처에 구워진 그림자와 안쪽 면이 걸러진다
2. **같은 행 다른 각도 복사**: 무효 구간마다 5° 단위 72개 시프트 중 소스 유효율이 가장 높은 것을 고른다
3. **경계 64 px 크로스페이드**
4. 유효 픽셀 3% 미만인 행(구연 띠, 축 근처)은 위아래 행 보간
5. 대각·굽 구간은 파편 텍스처가 블록 노이즈라 **행 중앙값 60% + 가로 블러 40%**로 매끈하게 밀었다
6. 전체 0.9배 (구워진 조명 완화)

첫 시도에서 구연에 검은 띠가 생겼다. 파편의 **파단면**(깨진 단면, 어두운 갈색)이 구연 높이의 유일한 유효 픽셀이라 그 색으로 한 바퀴를 채운 것이다.
"유효 픽셀 3% 미만 행은 무효" 규칙과 z > 0.474 구연 행 강제 무효로 잡았다. **소수 픽셀이 행 전체를 오염시키는 패턴**은 회전 채우기의 고질적 함정이다.

### 4.4 재질

채운 텍스처 위에 절차적 층을 얹었다. 텍스처만으로는 매끈한 플라스틱처럼 보인다.

| 층 | 노드 | 값 |
| --- | --- | --- |
| 굽기 얼룩 | Noise 7 → ColorRamp → Multiply 0.55 | 큰 색 변조 |
| 미세 색 입자 | Noise 420 → Multiply 0.5 | |
| 거칠기 | Noise 35를 0.50~0.72로 매핑 + 어두운 곳 −0.10 | 검은 얼룩이 살짝 광택 |
| 범프 3겹 | 태토 입자 Noise 1400 / 물레 자국 Wave(Z 방향) 180 / 텍스처 명도 | 0.18 / 0.06 / 0.15 |
| 코팅 | Coat 0.06, Roughness 0.35 | 경질토기 광택 |
| 형태 흔들림 | Displace 모디파이어, Clouds 0.06, 강도 2.5 mm | 완벽한 회전체 느낌 제거 |
| 출처 스위치 | Value 노드 `Provenance` 0/1 | 1이면 채운 구간을 크림색으로 표시 |
