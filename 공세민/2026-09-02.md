# 2026-09-02 학습 정리 — Quest 2에 UE5 프로젝트를 띄우는 경로 비교

- 학습 주제: 언리얼 프로젝트를 Quest 2에서 보는 방법에는 무엇이 있고, 각각 무엇이 다른가
- 배경: PC VR의 표준 경로인 Meta Horizon Link가 팀 개발 PC에서 호환성 오류로 막혀 있다
- 확인 기준: 공식 문서와 팀 문서(`김소영/unreal-포팅/unreal-quest2-porting.md`, `김소영/VR환경세팅-스트리밍용.md`) 기준 정리.
  같은 날 저녁 **ALVR + SteamVR 무선 연결을 실제로 확인했다.** 절차는 [quest2-alvr-steamvr-setup.md](quest2-alvr-steamvr-setup.md)에 분리했고, 나머지 미검증은 7절에 명시했다.

---

## 1. 핵심 결론

**1) "헤드셋에 띄운다"에는 방향이 다른 두 가지가 섞여 있다.**

이걸 구분하지 못하면 도구 선택을 계속 틀린다.

```text
PC → 헤드셋   PC가 렌더링해서 헤드셋으로 밀어넣음   = VR Preview 가능
헤드셋 → PC   헤드셋 화면을 밖으로 내보냄            = 확인만 가능
```

Link / Steam Link / Virtual Desktop은 앞쪽이고, 웹 캐스팅(미러링)은 뒤쪽이다.
**캐스팅은 실행 수단이 아니라 확인 수단이다.** 헤드셋에서 이미 무언가 돌고 있어야
캐스팅할 대상이 생긴다.

**2) 스트리밍 프리뷰는 성능을 못 믿는다.**

Link 계열은 전부 **PC GPU로 렌더링**한 결과를 보내는 것이다. Quest 2가 실제로
Vulkan·모바일 렌더러로 돌린 결과가 아니다. 프리뷰에서 60fps가 나와도 APK로 뽑으면
무너질 수 있다. 프리뷰는 **상호작용 확인용**, 성능 판정은 **APK 실행**으로 한다.

**3) OpenXR 런타임은 한 번에 하나만 활성화된다.**

Meta Link와 SteamVR 중 하나를 활성 런타임으로 지정해야 하고, 잘못 잡혀 있으면
VR Preview가 회색으로 뜬다. 기기·경로를 바꿀 때마다 여기를 먼저 확인한다.

## 2. 경로 비교

| 경로 | 방향 | PC측 필요물 | 비용 | 팀 PC 상태 |
| --- | --- | --- | --- | --- |
| **Quest Link (USB)** | PC → 헤드셋 | Meta Horizon Link | 무료 | ✗ 호환성 오류 |
| **Air Link (Wi-Fi)** | PC → 헤드셋 | Meta Horizon Link | 무료 | ✗ 위와 동일 원인 |
| **Steam Link (Wi-Fi)** | PC → 헤드셋 | Steam + SteamVR | 무료 | ✗ Quest 스토어에 미노출 (원인 미확인) |
| **ALVR (Wi-Fi)** | PC → 헤드셋 | Steam + SteamVR + ALVR Streamer | 무료 | ✓ **연결 확인** (09-02) |
| **Virtual Desktop (Wi-Fi)** | PC → 헤드셋 | VD Streamer | 유료 약 $20 | 미시도 |
| **APK 단독 실행** | 헤드셋 자체 | Android SDK/NDK | 무료 | 미검증 (G1 게이트) |
| **웹 캐스팅** | 헤드셋 → PC | 브라우저만 | 무료 | 미검증 |

**Air Link는 Horizon Link PC 앱의 기능이다.** Horizon Link가 안 뜨면 Air Link도
같이 못 쓴다. 별개의 대안이 아니다.

### Horizon Link가 막힌 이유

`김소영/VR환경세팅-스트리밍용.md`에 기록된 내용이다.

- 개발 PC: Core Ultra 9 185H + RTX 4070 Laptop + 64GB — 성능 요구사항은 충족
- Intel Arc Graphics + RTX 4070의 **하이브리드 그래픽 구성**이고,
  Meta는 Intel Arc를 Horizon Link 미지원으로 명시하고 있다
- NVIDIA 제어판에서 `OculusClient.exe` 등을 고성능 GPU로 지정하고 재부팅해도 동일

원인이 Intel Arc라고 Meta가 직접 판정한 것까지 확인되지는 않았다. 유력한 추정이다.

## 3. 각 경로 절차

### 3.1 Steam Link (무선, 현재 팀 채택 경로)

1. PC에 Steam + SteamVR 설치
2. SteamVR → ≡ → Settings → OpenXR → **Set SteamVR as OpenXR Runtime**
   - `Current OpenXR Runtime: SteamVR` 확인
3. Quest 2 스토어에서 Steam Link 앱 설치
4. PC와 Quest 2를 같은 네트워크에 — **PC는 랜선, Quest는 5GHz**
5. Quest에서 Steam Link 실행 → 내 PC 선택 → 페어링
6. SteamVR 공간이 보이고 양손 컨트롤러가 잡히는지 확인
7. 언리얼 → 맵 열기 → OpenXR 플러그인 ON → ▶ 옆 ▼ → **VR Preview**

### 3.2 Quest Link (USB, 현재 불가)

Horizon Link가 정상화되면 이 경로가 가장 빠르다. 기록만 남긴다.

1. Meta Horizon Link 설치·로그인
2. Settings → General → **Unknown Sources** ON
3. 같은 화면에서 **OpenXR Runtime → Set Meta Horizon Link as active**
4. USB3 포트 + **데이터 전송 가능한** 케이블 (충전 전용 케이블 주의)
5. 헤드셋 Meta 버튼 → Quick controls → Link → Launch
6. 언리얼에서 VR Preview

### 3.3 APK 단독 실행

절차는 `김소영/unreal-포팅/unreal-quest2-porting.md` 3절에 상세히 있다. 요약만 적는다.

```text
Android SDK/NDK 준비 → Android 프로젝트 설정 → 패키징 → MQDH/adb 설치 → 헤드셋 실행
```

반복 개발에서는 `Package Project`보다 **Platforms → Android → (기기) → Launch**가 낫다.
패키징·설치·실행을 한 번에 하고, 두 번째부터는 변경분만 쿠킹해서 더 빠르다.

무선 설치도 된다. 최초 1회만 USB로 `adb tcpip 5555` → 이후 `adb connect <헤드셋IP>:5555`.
MQDH에도 wireless ADB 토글이 있다. 다만 빌드 자체가 수 분 걸리므로 케이블을 뽑아서
얻는 이득은 크지 않다. 자리 이동이 잦을 때 쓸 만하다.

### 3.4 웹 캐스팅

1. 헤드셋과 같은 Meta 계정으로 <https://horizon.meta.com/casting/> 로그인
2. 헤드셋 → 빠른설정 → 미러링 → **웹** 선택
3. 브라우저에 헤드셋 화면이 표시된다

PC 앱을 아무것도 설치하지 않아도 된다. Horizon Link 문제와 무관하게 동작한다.

## 4. 웹 캐스팅의 위치

처음에 "이걸로도 되는 것 아닌가" 싶었는데, 1절의 방향 구분이 답이다.
**VR Preview 대체는 안 된다.** PC가 렌더링한 화면을 헤드셋으로 보내는 기능이 아니다.

대신 **APK 경로와 조합하면 스트리밍 앱 없이 개발 사이클이 닫힌다.**

```text
언리얼 → APK 패키징 → 헤드셋 설치 → 헤드셋에서 단독 실행 → 웹 캐스팅으로 PC에서 확인
```

이 조합의 실질적 이점:

- PC 스트리밍 앱이 필요 없다 → Horizon Link 호환성 문제를 우회한다
- **실기 성능이 그대로 보인다** — Link 프리뷰의 근본 한계(2절, 1절-2)를 안 겪는다
- 팀에 보여주거나 화면 녹화할 때 그대로 쓴다. FR-UI-006(미러링) 확인에도 직결된다

**캐스팅의 한계**

- 한쪽 눈 화면만, 해상도·프레임 제한, 지연 있음 →
  **캐스팅 화면으로 성능을 판정하면 안 된다.** 프레임은 `OVR Metrics Tool` 또는
  헤드셋 안에서 `stat fps`로 본다
- 캐스팅 인코딩이 헤드셋 리소스를 먹는다. 성능 측정 시에는 끈다

---

## 5. 그래서 어떻게 개발하는가

경로 하나로 다 하려고 하지 않는 게 맞다. 목적에 따라 나눈다.

| 목적 | 수단 | 반복 비용 |
| --- | --- | --- |
| 로직·블루프린트 확인 | 에디터 PIE (VR 없이) | 즉시 |
| VR 상호작용·시점 확인 | Steam Link + VR Preview | 즉시 |
| **성능·실기 동작 판정** | APK + 캐스팅 | 빌드 수 분 |

PIE로 최대한 밀어내고, VR 특유의 것만 프리뷰로 보고, **성능과 최종 판정은 반드시 APK로**
한다. 어제(09-01) 실습에서 얻은 "화면으로 판단하면 틀린다"가 여기에도 그대로 적용된다.
프리뷰에서 잘 돌아가는 것은 실기 동작의 근거가 아니다.

## 6. 무선 스트리밍의 네트워크 조건

무선은 사실상 네트워크가 전부다.

- **PC는 반드시 유선(랜선)** — PC까지 무선이면 지연이 두 배로 붙는다
- Quest 2는 **5GHz 대역** (2.4GHz는 실용성 없음)
- **SSAFY Wi-Fi는 같은 서브넷이어도 로컬 discovery(mDNS/multicast)가 막혀 PC 검색이 안 된다.**
  김소영 님이 09-02에 Wireshark로 확인했고, 노트북 핫스팟으로 바꾸자 바로 됐다
  ([ssafy-wifi-airlink-분석.md](../김소영/ssafy-wifi-airlink-분석.md)). 교육장에서는 핫스팟이 기본이다

## 7. 아직 검증하지 않은 것

정직하게 남긴다. 전부 추정 또는 문서 기준이다.

| 항목 | 상태 |
| --- | --- |
| Steam Link 경로 | 스토어에 안 보여 미시도. **ALVR + SteamVR로 대체해 연결 확인** |
| ALVR 경로에서 언리얼 VR Preview까지 되는가 | 미검증 — 연결과 SteamVR 홈까지만 확인 |
| 웹 캐스팅이 Unknown Sources 앱(자체 빌드 APK)도 캐스팅하는가 | 미확인 |
| Horizon Link 오류 원인이 Intel Arc가 맞는가 | 추정. Meta의 직접 판정 아님 |
| Quest 2 APK 빌드 성공 여부 | **미검증 — G1 게이트** |
| 캐스팅 지연·해상도가 시연에 쓸 만한 수준인가 | 미측정 |
| 무선 스트리밍이 교육장 Wi-Fi에서 되는가 | 미확인 (AP isolation 가능성) |

## 8. 다음에 할 것

- ALVR 연결 상태에서 언리얼 VR Preview까지 확인한다 (연결은 됐다)
- APK 빌드를 뚫는다 (Android SDK 35.0.1 / NDK r27c / JDK 21). 이게 G1 게이트다
- APK가 되면 웹 캐스팅으로 Unknown Sources 앱이 미러링되는지 확인 — FR-UI-006과 직결
- `Platforms → Android → Launch` 반복 사이클의 실제 소요 시간을 재둔다.
  이게 몇 분인지에 따라 개발 방식이 달라진다
