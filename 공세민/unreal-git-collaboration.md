## 0. 한 줄 요약

`.uasset`과 `.umap`은 **Git이 병합하지 못한다.** 두 사람이 같은 파일을 고치면 한쪽이 사라진다.
그래서 충돌을 **해결하는** 규칙이 아니라 **안 나게 하는** 규칙이 필요하다.

---

## 1. LFS에 대한 흔한 오해

| | Git LFS가 해주는 것 |
| --- | --- |
| 저장소 용량 폭증 | **해결** — 바이너리는 별도 저장소, Git에는 포인터만 |
| `.uasset` 동시 편집 충돌 | **해결 못 함** — 여전히 병합 불가 |

LFS는 협업을 가능하게 해주지 않는다. **용량 문제만** 푼다.
협업을 가능하게 하는 것은 "같은 파일을 동시에 열지 않는다"는 합의다.

### 강제하고 싶다면 — `lockable`

`.gitattributes`에 `lockable`을 붙이면 체크아웃 시 파일이 **읽기 전용**이 된다.
편집하려면 `git lfs lock`을 해야 하고, 남이 잠근 파일은 잠글 수 없다.

```gitattributes
*.uasset filter=lfs diff=lfs merge=lfs -text lockable
*.umap   filter=lfs diff=lfs merge=lfs -text lockable
```

공지에 의존하지 않고 도구가 막아준다. GitLab이 LFS 잠금 API를 지원한다.
3인 규모면 팀 채널 공지로도 충분하지만, 사고가 한 번 나면 도입할 만하다.

---

## 2. 저장소 준비 — 순서가 중요하다

한 번만 하지만 **순서를 틀리면 되돌리기 어렵다.**

```text
① GitLab LFS 활성화 여부 + 용량 한도 확인      ← 아직 미확인 (CONTRIBUTING 10절)
② .gitattributes 의 LFS 섹션 주석 해제 → 커밋
③ 그 다음에 프로젝트 파일 커밋
```

②를 건너뛰고 ③을 하면 바이너리가 **일반 Git 히스토리에 영구히 박힌다.**
나중에 LFS로 옮겨도 히스토리 용량은 줄지 않는다. 히스토리 재작성이 필요해진다.

### 올리기 전에 빼야 할 것

| 대상 | 처리 | 크기 (2026-09-08 testproj 기준) |
| --- | --- | --- |
| `Saved/`, `Intermediate/`, `DerivedDataCache/` | `.gitignore` (이미 등록됨) | 1.2 GB |
| `Content/` 안의 원본 `.obj` `.glb` `.jpg` `.ttf` | **공유 스토리지** (`FR-OPS-004`) | 191 MB |
| 레벨에 배치하지 않은 유물 에셋·텍스처 | 올릴지 판단 | 약 113 MB |

원본 파일이 `Content/` 안에 있으면 패키징에도 섞인다. 임포트가 끝나면 밖으로 뺀다.

---

## 3. 매일 지킬 것 — 세 가지

### ① 에디터를 닫고 pull 한다

언리얼을 열어둔 채 pull 하면 파일이 잠겨 실패하거나, **더 나쁘게는** 메모리에 있는
옛 버전이 나중에 저장되면서 남의 작업을 덮어쓴다. 가장 흔한 사고다.

### ② 만질 파일을 먼저 알린다

`git lfs lock <파일>`이 확실하다. 3명이면 팀 채널에 "BP_StageToggle 만집니다" 한 줄이어도 된다.
중요한 것은 **시작 전에** 알리는 것이다.

### ③ 짧게 작업하고 바로 올린다

바이너리는 브랜치를 오래 들고 있을수록 위험하다. dev가 앞서 나가도 **병합으로 따라잡을 수 없다.**
반나절~하루 안에 MR을 올릴 크기로 자른다.

## 4. 충돌을 구조로 줄이기

거창한 소유권 표 없이도 **레벨만 나누면 대부분 해결된다.**

지금 `L_Museum`에 액터 45개가 전부 들어 있어서, 두 사람이 각각 조명과 유물을 만져도
같은 `.umap`을 건드린다. 서브레벨 2~3개로 쪼개면 그 충돌이 사라진다.

> **퍼시스턴트 레벨은 여전히 공유 파일이다.** 서브레벨 목록·스트리밍 설정·World Settings가
> 여기 있다. 액터를 전부 서브레벨로 내리고 퍼시스턴트를 비워두면 실질적으로 아무도 안 건드리게 된다.

블루프린트는 원래 파일이 나뉘어 있으니 "누가 뭘 만드는지"만 겹치지 않으면 된다.
미리 표를 짜기보다 그때그때 정해도 충분하다.

### World Partition은 지금 필요 없다

액터마다 파일이 분리돼 협업에는 더 좋다(같은 레벨의 다른 액터를 동시 편집해도 충돌 없음).
다만 **방 하나에 액터 45개 규모에서는 과하고**, 스트리밍 오버헤드도 Quest 2에서 공짜가 아니다.

## 5. 실제로 터진 것들

2026-09-07~08 작업 중 겪은 것이다. 문서로 읽는 것보다 이쪽이 실전에 가깝다.

### 블루프린트는 읽기만 해도 dirty 가 된다

조회만 했는데 블루프린트 6개가 수정됨으로 표시됐고, 에디터를 닫을 때 저장 프롬프트가 떠서
그대로 저장됐다. 내용은 동일했지만 타임스탬프가 바뀌었다.

> **커밋 전에 `git status`를 보고 의도하지 않은 에셋 변경은 되돌린다.**
> 안 그러면 MR에 노이즈가 쌓이고 남의 파일과 충돌한다.

### 액터 스케일과 컴포넌트 스케일은 곱해진다

`WidgetComponent`가 자체 `RelativeScale3D` 0.1을 갖고 있는데 **액터** 스케일을 0.09로 바꿨더니
0.009가 되어 패널이 6 cm짜리 점이 됐다. 렌더가 깨진 줄 알고 한참 엉뚱한 곳을 팠다.

> 크기를 바꿀 때 **어느 레벨의 스케일인지** 확인한다. 컴포넌트에 이미 스케일이 있으면 거기서 바꾼다.

### 재시작해야 반영되는 설정이 있다

`r.Substrate`, `r.RayTracing`은 프로젝트 설정을 바꿔도 **실행 중 CVar는 옛 값**으로 남는다.
ini와 런타임이 어긋난 상태에서 겪은 증상은 실제 문제와 무관할 수 있다.

> 바꾼 뒤 **에디터를 재시작하고 나서** 판단한다. `Lumen`(GI·반사)은 즉시 반영된다.

### VR 프리뷰는 에디터 시작 시점에만 탐지된다

SteamVR·Link를 나중에 켜도 이미 떠 있던 에디터에서는 VR 프리뷰가 계속 잠겨 있다.

> **헤드셋 연결 → 런타임 실행 → 그 다음 에디터 실행.** 순서를 지킨다.

### 에셋 이름을 바꾸면 리다이렉터가 생긴다

Content Browser에서 **Fix Up Redirectors** 한 뒤 커밋한다. 안 하면 남들이 깨진 참조를 본다.

### 라이팅 빌드 데이터

`_BuiltData` 파일은 크고 매번 바뀐다. 굽기로 했다면 **누가 빌드할지 한 명 정한다.**
현재는 조명이 전부 Movable이라 해당 없다.

## 6. MR 규칙

- **에셋 변경 MR에는 스크린샷을 붙인다.** 바이너리는 diff를 볼 수 없어 리뷰어가 확인할 방법이 없다.
- 한 MR에 여러 사람의 파일을 섞지 않는다.
- `dev`에 직접 commit 하지 않는다. `feature/*` · `fix/*` · `chore/*` 에서 작업하고 MR을 올린다.
