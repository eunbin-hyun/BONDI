# VR 트랙 전달 — 인왕제색도 복원 지형 v0.10

- 전달: 김채원 (AI) → VR 트랙
- 날짜: 2026-09-10
- 목적: **UE5 임포트·실기 확인이 목표.** 형상 완성도는 아직 진행 중이며, 이 단계에서
  잡고 싶은 것은 좌표·스케일·성능이지 미관이 아니다.

---

## 1. 무엇을 넣으면 되나

`runtime/` 5개 파일이 전부다. 한 장면에 **지형 1 + 나무 + 기와집 + 운무**를 놓는다.

| 파일 | 면 수 | 역할 |
|---|---:|---|
| `runtime/terrain_jeong.glb` | 10,000 | **정선의 지형** (과장 적용) — 기본으로 이걸 쓴다 |
| `runtime/terrain_real.glb` | 10,000 | 실측 지형 — 토글용. 위 파일과 **같은 좌표·pivot** |
| `runtime/trees.glb` | 10,271 | 나무 168그루 (동양 소나무 167 · 버드나무 1) |
| `runtime/house.glb` | 32 | 기와집 2동 |
| `runtime/fog.glb` | 1,130 | 운무 (반투명) |
| `runtime/inscription.glb` | 2 | 화제·인장 (공중에 뜬 판, 알파 텍스처) |
| `runtime/base.glb` | 2,682 | **디오라마 받침** — 지형 가장자리를 잘라 내린 벽 + 바닥 |

**한 단계 표시 시 장면 면 수 = 24,117** (명세 20장 임시 기준 30,000 이내)
**텍스처 2장** — 지형만 텍스처(베이스컬러 1024 + 노멀 1024). 나머지는 정점색.

`master/` 는 줄이지 않은 원본이라 **VR에는 넣지 않는다** (지형 396,150면).

## 2. 좌표·단위 계약 (명세 19.3)

| 항목 | 값 |
|---|---|
| 단위 | **meter** |
| 상하 축 | **Z-up** |
| pivot | **바닥 중심** (5개 파일 전부 동일) |
| 포맷 | glTF 2.0 GLB |
| 단계 정렬 | `terrain_real` ↔ `terrain_jeong` 동일 변환 |

**임포트 시 스케일·회전 보정값이 필요하면 그건 이 파일의 결함이다.**
`MeshScale`·`MeshRollFix` 를 만지지 말고 나에게 알려주면 다시 내보낸다.
확인 스크립트: `scripts/check_coordinate_contract.py assets --mode scene`

**주의 — 크기가 크다.** 지형 한 변이 약 **2.5 km × 2.85 km**, 높이 540 m다.
언리얼 기본 단위는 cm이므로 임포트 시 **Import Uniform Scale = 100** 이 필요하다.
(glTF 임포터가 meter→cm 변환을 자동으로 하는지 이번에 확인해 주면 좋겠다.)

## 2-1. 지형 텍스처 — 노멀맵을 꼭 켜 주세요

지형은 1만 면이라 그냥 두면 매끈한 경사면으로 보인다. **노멀맵이 표면 요철을 되살린다.**

- `baseColorTexture` → 위에서 내려다본 평면 UV
- `normalTexture` → 같은 UV. **Tangent Space**
- 노멀맵 내용 = 5 m DEM이 갖고 있으나 1만 면 메시가 잃은 잔굴곡 + **원화 붓질(부벽준)을 요철로 바꾼 것**

언리얼에서 노멀맵 임포트 시 **`sRGB` 체크 해제 · Compression Settings = `Normalmap (DXT5, BC5)`** 여야 한다.
(현은빈이 겪은 `TC_Default` + sRGB 오설정과 같은 함정이다.)


## 2-3. 1:1 몰입(액자 진입) — 관람자가 설 자리

`records/entry_point.json` 에 넣어 뒀다. 좌표계는 `runtime/*.glb` 와 같다 (pivot = 바닥 중심).

| 항목 | 값 (에셋 로컬, meter) |
|---|---|
| 눈 위치 | X = −1.0 · Y = −1175.0 · Z = 154.3 |
| 발밑 바닥 | Z = 152.7 (눈높이 1.6 m) |
| 바라보는 방향 | +Y (위쪽 +Z) |
| 실제 방위 | 진북 288.93° · 수평화각 45.0° |

**부모 액터 스케일 1.0 기준값이다.** 임포트 배율 100을 걸었다면 100을 곱한다
→ `(-100, -117500, 15430)` cm.

이 자리가 스카이라인 정합으로 구한 정선의 시점이다. 여기 서면 원화와 같은 구도가 된다.
구현 절차는 `ENTER_THE_PAINTING.md` 참조.

## 2-2. 디오라마 받침

`base.glb`는 지형 가장자리를 수직으로 잘라 내린 벽과 바닥이다.
- **축소 전시**(테마관 좌대 위)로 쓸 때: 그대로 두면 박물관 지형 모형이 된다
- **1:1 몰입**으로 쓸 때: 관람객 눈에 안 들어오지만 가장자리가 뚫려 보이는 것을 막는다

축척은 **`base.glb`와 나머지 전부에 같은 배율**을 걸면 된다 (pivot이 전부 같은 바닥 중심이라 축척만 바꾸면 됨).
3 m 폭 디오라마 = 약 1:830.

## 3. 머티리얼 — 언릿으로 해 주세요

모든 색이 **원화(먹그림)에서 나온 값**이다. PBR 라이팅을 걸면 먹의 농담이 조명에 덮여 화풍이 깨진다.

- **Shading Model: Unlit**
- 지형 : Emissive Color 에 **baseColorTexture** 연결. 노멀맵은 Unlit에서는 라이팅에 안 걸리므로,
  요철을 보이게 하려면 노멀맵의 R채널을 **명암 곱셈**으로 섞거나(간단),
  지형만 **Default Lit + 약한 방향광**으로 두는 것(정석) 중에 골라 주세요. 어느 쪽이 나은지 실기로 판단 부탁.
- 나무·기와집·받침 : Emissive Color 에 **Vertex Color** 연결
- 운무 : 위와 같되 `Blend Mode: Translucent` + Vertex Color 의 **Alpha**

## 4. 이번에 확인하고 싶은 것 (우선순위)

1. **임포트 시 스케일이 1:1로 맞는가** — 사람 키(1.7 m)를 옆에 두고 지형이 산처럼 보이는가
2. **프레임** — 27,488면 + 언릿에서 PC VR 프레임이 얼마인가 (`stat fps`)
3. **정점색이 살아 있는가** — 나무·집이 회색 덩어리면 정점색 임포트가 꺼진 것
3-1. **노멀맵이 먹히는가** — 지형 경사면에 잔굴곡이 보이는지. 안 보이면 sRGB/압축 설정 확인
3-2. **받침을 켠 축소 전시**와 **1:1 몰입** 중 어느 쪽이 나은지 (양안시차 때문에 축소 쪽이 유리할 것으로 예상)
4. **운무 알파가 나오는가**
5. 가능하면 Quest 2 내부 빌드에서도 1~4 (G1 통과했다면)

## 5. 알려진 한계 (이 단계에서는 고치지 않음)

- **전경 지형이 평평하다.** 근경 0~200 m 기복이 4.6 m 뿐이다. 그 자리가 현재
  서촌 시가지라 2024년 수치지형도에서 이미 평탄화돼 있다. 원화에서 역산해
  복원할 예정이며, 그 결과가 나오면 지형 파일만 교체된다 (좌표 계약은 그대로).
  그때까지 임시로 **절차적 잔결층(최대 1.15 m, 620 m 밖 0)** 을 얹어 두었다.
  측정값이 아니다 — `records/micro_relief.json` 에 그렇게 적어 두었다.
- **전경 지면의 무늬는 원화가 아니다.** 시선이 지면을 88.8°로 스치는 구역에서는
  원화 화소 하나가 46배로 늘어나 검은 띠가 된다. 신축 12배를 넘는 자리는
  투영을 포기하고 '원화 하단 지면 톤 + 지형 음영 + 잔결'로 대체했다.
- 나무·기와집이 아직 **저폴리 자리표시**다. 위치·크기는 측정값이고 형상은 임시다.
- 전경 나무의 실물 높이가 2~4 m로 작다. 위 전경 지형 문제와 같은 원인이다.
- 기와집 본채 폭 22.3 m는 지붕선 획 2개를 한 채로 합친 값이라 두 채일 가능성이 있다.
- **원화 이미지의 소장기관 표기·이용조건 미확인.** 대외 공개물에는 아직 쓰지 말 것.
