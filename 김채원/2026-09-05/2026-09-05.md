# 2026-09-05 학습 정리 — 단일 이미지 3D 재구성 모델 4종 비교와 8GB VRAM 제약 극복

- 작성자: 김채원
- 학습 주제: 사진 한 장에서 문화유산 유물을 3D로 복원하는 모델 4종을 공정하게 비교하고, 32GB를 요구하는 모델을 8GB 노트북에서 돌리는 방법
- 대상 데이터: `Artifacts/굽다리바리_PS0100100201807115000000_0.jpg` (신라 굽다리접시, 慶州 新收 71150)
- 핵심 기술: 단일 이미지 3D 재구성, 오일러 지표 기반 위상 검증, 단계별 GPU 오프로딩, 연결 성분 분리, 이차오차 데시메이션
- 실행 환경: WSL2 + CUDA 12.1, NVIDIA RTX 4070 Laptop GPU (8GB, 가용 약 6.9GB), WSL 메모리 24GB + 스왑 32GB
- 비교 모델: TripoSR, Stable Fast 3D, TRELLIS, SAM 3D Objects `@f91db41`

## 1. 학습 목표

지난 작업(`2026-08-28`)에서 LiDAR 점군 기반 석인상 재구성을 다뤘고, 그 결론은 **"이 유물에는 복원할 물리적 결손이 거의 없고 메시의 구멍은 전부 스캔 사각"**이었다. LiDAR는 실측 데이터를 주지만 장비와 현장 접근이 필요하다.

이번에는 반대쪽 극단을 확인하고자 했다. **박물관 공개 사진 한 장만으로 어디까지 갈 수 있는가.** 구체적인 목표는 세 가지였다.

1. 단일 이미지 3D 재구성 모델 4종 중 문화유산 유물에 쓸 만한 것을 가려낸다.
2. 그 판정을 인상이 아니라 **측정 가능한 기준**으로 내린다.
3. 32GB VRAM을 요구하는 최신 모델을 8GB 노트북에서 실행할 수 있는지 확인한다.

세 번째가 중요한 이유는 팀 전원이 동일 사양의 노트북을 쓰기 때문이다. 8GB에서 돌아가지 않으면 그 모델은 이 프로젝트에서 선택지가 아니다.

## 2. 대상 유물과 판정 기준

굽다리바리를 고른 것은 우연이 아니다. 이 유물은 단일 이미지 재구성의 **약점을 정확히 찌르는** 세 가지 형질을 동시에 갖고 있다.

| 형질 | 왜 어려운가 | 판정 방법 |
|---|---|---|
| **투창(透窓) 관통** | 굽다리 2단에 뚫린 직사각 창. 뒷면은 사진에 없다 | **위상수학** — 관통 구멍 1개가 genus를 1 올린다 |
| **물레 성형흔** | 몸통을 감는 수평 융기선. 미세해서 뭉개지기 쉽다 | **주파수 분석** — 벽을 펼쳐 융기선 대역의 기복을 잰다 (8.3) |
| **구연부 파손** | 결실된 아가리. 모델이 온전한 원으로 "복원"하기 쉽다 | 공통 카메라 렌더의 **부위 확대 크롭** (8.1) |

### 2.1 왜 투창이 결정적인가

이것이 이번 작업에서 얻은 가장 중요한 방법론이다.

모델이 굽다리의 창을 **표면에 눌린 음영**으로 그리면, 렌더 이미지는 그럴듯해 보인다. 눈으로는 구별되지 않는다. 그러나 오일러 지표는 속지 않는다.

```text
χ = 2c − 2g     (c = 연결 성분 수, g = genus)
```

관통 구멍이 실제로 뚫려 있으면 genus가 올라가고 χ가 내려간다. 음영만 있으면 genus는 0에 머문다. **렌더를 보지 않고도 표에서 읽을 수 있는 판정 기준**이 생긴다.

이 기준은 문화유산 도메인에서 특히 유효하다. 토기의 투창, 향로의 배연구, 석탑의 감실처럼 "뚫려 있음" 자체가 유물의 정체성인 경우가 많기 때문이다.

## 3. 시행착오 1 — 각 모델의 뷰어로 비교하면 아무것도 비교되지 않는다

### 문제

처음에 TripoSR, Stable Fast 3D, TRELLIS를 각각 돌리고 각 저장소가 제공하는 뷰어/렌더 스크립트로 결과 이미지를 뽑았다. 그런데 나온 그림을 나란히 놓으니 비교가 되지 않았다.

- 카메라 거리와 화각이 제각각이라 크기가 다르게 보인다
- 조명 설정이 달라 같은 표면이 다른 재질처럼 보인다
- 정규화 방식이 달라 비율 비교가 불가능하다
- TripoSR은 정점 색, TRELLIS는 텍스처 맵이라 색 표현 경로 자체가 다르다

**모델의 차이인지 렌더 설정의 차이인지 구분할 수 없었다.**

### 해결

`results/_scripts/render_compare.py`를 하나 만들어 **모든 메시를 같은 파이프라인에 통과**시켰다.

- 하나의 카메라, 하나의 조명, 하나의 정규화
- 6면 턴테이블을 고정 각도로 렌더
- 색(`tex_*.png`)과 지오메트리(`geo_*.png`)를 분리 출력 — 텍스처가 지오메트리의 결함을 가리지 못하게 한다
- 동시에 `stats.json`으로 위상 지표를 함께 기록

색과 지오메트리를 분리한 것이 특히 중요했다. 텍스처가 있는 모델은 지오메트리가 뭉개져도 사진처럼 보인다. 무광 회색으로 다시 렌더하니 실제 표면 품질이 드러났다.

### 배운 것

**비교 실험에서 가장 먼저 고정해야 할 것은 모델이 아니라 측정 장치다.** 각 저장소의 데모 스크립트는 자기 결과를 잘 보이게 하려고 설정이 조정되어 있다. 이걸 그대로 쓰면 모델을 비교하는 게 아니라 데모 스크립트를 비교하게 된다.

## 4. 시행착오 2 — 32GB 모델을 8GB에 올리기

### 문제

SAM 3D Objects는 앞선 3종과 체급이 다른 최신 모델이라 반드시 비교군에 넣고 싶었다. 그런데 요구 사양이 **Linux + 32GB VRAM**이었다. 이 노트북은 Windows에 RTX 4070 Laptop 8GB(가용 약 6.9GB)다.

처음에는 포기하고 `50acdfe` 커밋에 "sam-3d-objects was not run: it requires 32GB VRAM against this machine's 8GB"라고 적었다.

### 해결 — 무엇을 바꾸고 무엇을 바꾸지 않을지 먼저 정하기

다시 붙기로 하면서 원칙을 하나 세웠다. **모델이 무엇을 계산하는지는 건드리지 않고, 가중치가 어디에 언제 있는지만 바꾼다.** 샘플러, 스텝 수, cfg 강도, 시드는 배포된 `pipeline.yaml` 그대로 둔다. 그래야 비교 결과가 유효하다.

Linux는 WSL2 GPU 패스스루로 해결하고, VRAM은 `run_sam3d.py`에서 네 가지를 바꿨다.

| 항목 | 업스트림 | 수정 후 |
|---|---|---|
| 체크포인트 7종 | 전부 GPU 상주, fp32 | CPU에 구성 후 단계별로만 GPU 이동 |
| 생성기 | fp32 (체크포인트 13.1GB) | 체크포인트 로드 시점에 fp16 캐스팅 |
| FlexiCubes 격자 | 1.38GiB GPU 상주 | CPU에 두고 추출 시에만 이동 |
| 메시 추출 | GPU | GPU 시도 후 OOM이면 CPU 폴백 |

fp16 캐스팅이 안전한 근거는 **설정 파일이 이미 fp16 오토캐스트로 생성기를 돌리고 있었다**는 점이다. fp32로 올려놓고 fp16으로 연산하고 있었으므로, 로드 시점에 캐스팅해도 수치가 달라지지 않는다.

### 어디서 터지는지 정확히 찾기

단계별 VRAM 피크를 계측한 결과 병목이 한 곳에 몰려 있었다.

| 단계 | peak VRAM | 8GB 대비 |
|---|---:|---:|
| pointmap (MoGe) | 2.32 GiB | 29% |
| stage 1, sparse structure | 4.00 GiB | 50% |
| stage 2, structured latent | 2.98 GiB | 37% |
| **decode / mesh (GPU 시도)** | **6.70 GiB** | **84% → OOM** |
| decode / mesh (CPU 추출) | 4.66 GiB | 58% |
| decode / gaussian | 3.36 GiB | 42% |

원인은 `SparseFeatures2Mesh`가 FlexiCubes를 `res = resolution × 4 = 256`으로 돌리는 데 있었다. 256³×21 fp32 가중치 격자(1.4GB)에 257³×7 정점 격자가 얹히고, 그 위에 상주 인덱스 격자 1.38GiB가 더해진다.

**이 한 단계만 CPU로 내리면 된다.** 비용은 약 70초였다.

### 결과

```text
체크포인트 로딩  186 초
추론             321 초
출력             525,928 정점 / 1,051,288 면 (27,140 복셀)
```

32GB를 요구하던 모델이 8GB에서 돌았다. 그리고 **굽다리의 투창을 2단 모두 실제 관통으로 재구성**했다.

### 배운 것

- "32GB 필요"라는 요구 사양은 대개 **가장 무거운 한 단계**의 요구치다. 전 구간이 그만큼 필요한 것이 아니다.
- 단계별 VRAM을 계측하기 전에는 어디를 고쳐야 할지 알 수 없다. **계측이 최적화보다 먼저다.**
- 정확도에 영향을 주지 않는 변경(배치 위치, 이미 오토캐스트되는 정밀도)과 주는 변경(샘플러, 스텝)을 구분해야 비교 실험이 유효하게 남는다.

### 부수적으로 겪은 것

- HF 체크포인트(`facebook/sam-3d-objects`, 13.1GB)는 **게이트 모델**이라 사전에 접근 승인을 받아야 한다. `setup_wsl.sh`가 다운로드에 도달했을 때 403으로 멈춘 뒤에야 알았다.
- WSL에 메모리 24GB + 스왑 32GB를 `%USERPROFILE%\.wslconfig`로 배정해야 했다. 체크포인트 로딩 중 CPU 측이 약 13GB를 찍는다.
- SAM 3D는 객체 마스크를 요구한다. Otsu 임계값 방식은 **굽다리를 통째로 잃었다** — 회색 석재가 임계값의 반대편에 떨어진다. rembg(u2net)로 교체했고, 이것이 TripoSR의 자체 전처리와 같은 방식이라 네 모델이 동일한 분할을 보게 되는 이점도 얻었다.

## 5. 시행착오 3 — 159개의 껍데기

### 문제

SAM 3D 결과의 위상을 재보니 이상했다.

```text
연결 성분(shells)   159
χ                  +284
stray faces        57,716 (5.49%)
```

껍데기가 159개다. 유물은 하나인데 159개 덩어리로 나왔다는 뜻이다. 여기서 **판단이 갈렸다.**

- 158개가 깨져 떨어져 나온 파편이라면 → 유물의 일부이므로 **버리면 안 된다**
- 등위면 추출이 남긴 계산 부산물이라면 → **버려야 한다**

문화유산 데이터에서 이 구분을 잘못하면 실제 형상을 삭제하게 된다.

### 해결 — 짐작하지 않고 측정하기

각 껍데기의 정점을 주 표면에 대해 **부호거리 질의**로 샘플링했다.

```text
결과: 158개 껍데기의 샘플 100%가 주 표면 내부
     벽면에서 바운딩 대각선의 0.001 ~ 0.003 안쪽
```

**전부 표면 아래에 묻혀 있었다.** 떨어져 나온 파편이라면 바깥에 있거나 최소한 표면과 교차해야 한다. 100% 내부는 등위면 추출 파편의 특징이다.

제거 후 검증도 양방향으로 했다.

| 항목 | 제거 전 | 제거 후 |
|---|---:|---:|
| shells | 159 | **1** |
| faces | 1,051,288 | 993,572 |
| χ | +284 | −30 |
| genus | 17 | 16 |
| 표면적 | 5.529 | 5.090 |
| 크기 | 21.03 MB | 19.87 MB |

- 같은 6면 렌더의 **픽셀 차이 0**
- 바운딩 박스 소수점 4자리까지 불변

외부는 전혀 건드리지 않았다는 증거다.

![제거된 158개 내부 껍데기](./images/제거된-내부껍데기.png)

버려진 껍데기만 따로 렌더하면 위와 같다. 유물의 형태를 전혀 이루지 못한다.

### 배운 것

**"수치가 이상하다"와 "삭제해도 된다" 사이에는 검증 단계가 하나 더 있어야 한다.** genus가 17에서 16으로 준 것도 그냥 넘길 일이 아니었다 — 파편 하나가 자체 손잡이(handle)를 갖고 있었다는 뜻이다. 원본 메시를 덮어쓰지 않고 `mesh_clean.glb`로 따로 저장한 것도 같은 이유다.

## 6. 시행착오 4 — 면 수가 만든 착시

### 문제

4모델 비교를 마치고 나온 인상은 "SAM 3D Objects가 가장 좋다"였다. 그런데 표를 다시 보고 이 결론을 의심하게 됐다.

| 모델 | faces |
|---|---:|
| TRELLIS | 14,642 |
| SAM 3D Objects | 993,572 |

**68배 차이다.** SAM 3D가 더 선명한 것이 재구성 능력 때문인지, 단순히 면이 68배 많아서인지 구분할 수 없다. 이 상태의 비교는 공정하지 않다.

### 해결 — 같은 예산으로 내리기

SAM 3D 메시를 TRELLIS와 **같은 면 수**로 데시메이트하고 다시 비교했다. 위험한 것은 굽다리의 관통 구멍이었다. 데시메이션이 작은 구멍을 닫아버리면 비교 자체가 무의미해진다.

그래서 짐작하지 않고 양쪽에서 측정했다.

| 항목 | 993,572면 | 100,000면 |
|---|---:|---:|
| 정점 | 496,756 | 49,970 |
| shells | 1 | 1 |
| χ | −30 | −30 |
| **genus** | **16** | **16** |
| 크기 | 19.87 MB | 2.00 MB |

**16개 관통 구멍 중 하나도 닫히지 않았다.** 표면 편차는 30만 점 양면 샘플링에서 바운딩 대각선의 평균 0.12%, p95 0.24%, 최악 0.48%. 6면 렌더 차이는 지오메트리 1.78%, 색 1.21% 픽셀.

![데시메이션 전후 검증](./images/데시메이션-검증.jpg)

### 결과 — 결론이 바뀌었다

14,642면으로 맞춰 다시 비교하자 판정이 갈라졌다.

![동일 면 수 정면 대결](./images/동일면수-정면대결.png)

- **지오메트리는 SAM 3D Objects가 우위** — 같은 예산에서도 굽다리 투창과 구연부 융기선을 더 또렷하게 붙든다. 재구성 능력 자체가 나은 것이 맞았다.
- **색은 TRELLIS가 압도** — SAM 3D는 정점 색뿐이라 면 수를 낮추자 색 정보가 함께 소실되어 회백색으로 날아갔다. TRELLIS는 텍스처 맵을 싣기 때문에 면 수와 무관하게 색이 유지된다.

면 수를 통제하지 않았다면 **"SAM 3D가 전반적으로 낫다"**는 잘못된 결론에 도달했을 것이다. 실제로는 **지오메트리와 텍스처가 서로 다른 모델의 손을 들어준다.**

### 배운 것

이것은 `2026-08-28` 작업의 LOD 경험과 이어진다. 당시에도 정점 색이 메시 해상도에 종속되어 경량 LOD에서 색이 소실되는 문제를 한계로 적었다. **정점 색 방식은 경량화가 필요한 VR 파이프라인과 근본적으로 상성이 나쁘다.** 이번에 그 대가가 구체적인 수치로 확인됐다.

## 7. 시행착오 5 — 하드웨어가 먼저 무너졌다

### 문제

작업 도중 노트북이 두 번 꺼졌다. 처음에는 Blender나 세션이 죽은 줄 알았다.

### 원인 규명

이벤트 로그를 확인하니 단순 종료가 아니라 **블루스크린 두 건**이었다.

| 시각 | 버그체크 | 의미 |
|---|---|---|
| 15:50:53 | `0x101` CLOCK_WATCHDOG_TIMEOUT | CPU 코어가 인터럽트 응답 실패 |
| 16:07:43 | `0x116` VIDEO_TDR_ERROR | GPU 드라이버 리셋 실패 |

진단에 결정적이었던 세 가지 신호:

1. **서로 다른 버그체크 2종** — 드라이버 버그 하나면 같은 코드가 반복된다. 종류가 갈리는 것은 전압 강하 패턴이다.
2. **WHEA 하드웨어 오류 0건** — 메모리/CPU 자체 고장이 아니다.
3. **크래시 직후마다 펌웨어 스로틀링(Event 37)** — 부팅 71초 만에 "시스템 펌웨어가 프로세서 속도를 제한 중".

그리고 전원 상태를 확인하니 `PowerOnline: False` — **어댑터가 빠져 있었다.**

### 해결

Core Ultra 9 185H + RTX 4070 Laptop 조합에서 `decode/mesh` 단계는 8GB 카드의 **84%**를 짚는다. 이걸 배터리로 돌리면 전력 공급이 못 버틴다. 어댑터를 연결한 뒤 재발하지 않았다.

### 배운 것

**실행 환경은 결과의 일부다.** 처음에는 이 사건을 작업과 무관한 잡음으로 취급했지만, 결국 리포트의 VRAM 표 아래에 기록했다. 같은 실험을 재현하려는 사람에게 "이 단계는 8GB의 84%를 쓰므로 유선 전원이 필요하다"는 정보는 파라미터만큼 중요하다.

부수적으로, 커밋을 자주 해둔 것이 작업 손실을 막았다. 크래시 6분 전 커밋이 마지막 작업 지점이었고 잃은 코드가 없었다.

### 8.1 형질별 판정의 근거

처음에는 Stable Fast 3D를 `부분 / 부분 / 부분`으로 적었다. 이는 세 개의 판정이 아니라 **하나의 종합 인상을 세 칸에 복사한 것**이었다. 전체 그림에서는 함몰과 관통이 같아 보여 형질별 판정이 불가능했기 때문이다.

판정이 갈리는 부위만 잘라 같은 시점에서 다시 비교했다.

![형질별 판정 근거](./images/형질별-판정근거.png)

크롭해서 보자 SF3D의 한 줄이 세 개로 갈라졌고, TripoSR의 판정 근거도 하나 바뀌었다.

**Stable Fast 3D — 투창 `6/16`**
굽다리가 사실상 **민면 원뿔**이다. 2단 구조도, 단 사이 융기대도 남지 않았다. genus 6이 세는 관통부는 이 시점에 보이지 않는 다른 면에 흩어져 있다. 위상 지표는 6개가 뚫렸다고 말하지만, 유물의 특징인 "2단 사각 투창"이라는 형태는 사라졌다.

**Stable Fast 3D — 물레흔 `소실`**
`부분`이 아니었다. 몸통에 융기선이 **하나도 없다**. 표면이 매끈한 다면체 덩어리다.

**Stable Fast 3D — 구연부 `재현`**
반대로 이것은 `부분`보다 나았다. 파손부가 실제 결실로 남아 있다. 파단면이 거칠고 어수선하긴 하지만, 아가리를 온전한 원으로 메우지 않았다.

**TripoSR — 물레흔 `소실` (판정은 유지, 근거는 수정)**
TripoSR 몸통에는 촘촘한 가로 줄무늬가 있어서, 축소된 대조표에서는 오히려 물레흔을 가장 잘 살린 것처럼 보인다. 확대하면 아니다.

> **축을 도는 수평선이라면 서로 나란해야 한다. 그런데 이 줄무늬는 중앙에서 등고선처럼 겹쳐 접힌다.**

등위면 추출의 **계단(terracing) 아티팩트**다. 실제 융기선을 재현한 것이 아니라 오히려 덮어버린다. 판정은 `소실`이 맞지만, 이유는 "밋밋해서"가 아니라 "가짜 줄무늬가 진짜를 가려서"다.

**TripoSR — 구연부 `소실` (확인)**
아가리가 **완전한 원으로 닫혀 있다.** 결실을 복원해 버린 것으로, 유물 기록으로는 가장 위험한 실패 유형이다.

### 8.2 형질별 판정에서 배운 것

**"종합 인상"을 형질 수만큼 복제해 적으면 표는 채워지지만 정보는 없다.** SF3D는 실제로 한 형질을 살리고(구연부), 한 형질을 통째로 잃고(물레흔), 한 형질을 절반만 붙들었다(투창). `부분/부분/부분`은 이 셋 중 어느 것도 말하지 못한다.

**그리고 축소된 그림은 아티팩트를 디테일로 오인하게 만든다.** TripoSR의 계단 무늬가 그 사례다. 대조표는 개요를 보여줄 뿐이고, 판정은 판정이 갈리는 부위를 확대해서 내려야 한다.

`results/_scripts/trait_crops.py`로 이 도판을 생성하도록 만들어, 판정이 주장이 아니라 검증 가능한 형태로 남게 했다.

### 8.3 물레흔 정량화 — 눈이 아니라 자로

8.1의 판정은 크롭을 확대해서 봤을 뿐 여전히 육안이었다. 물레흔은 그럴 필요가 없다. **물레 성형흔은 벽을 도는 일정한 깊이와 간격의 띠**라는 물리적 정의가 있으므로 측정 가능하다.

**측정 방법**

1. 표면을 면적 균일 샘플링한다 (14,642면과 993,572면을 같은 관측 수로 재기 위해)
2. 공분산에서 회전축을 검출한다 — 회전체는 반경 방향 고유값 둘이 거의 같으므로, 슬라이스가 가장 둥글게 나오는 고유벡터가 축이다
3. 몸통 벽을 잘라낸다 — 그릇은 허리에서 만나는 두 개의 나팔이고, 이 유물은 바리가 굽다리보다 넓으므로 최대 반경 슬라이스가 몸통, 최소가 허리다
4. 벽을 펼쳐 `(높이 × 방위각)` 반지름 지도로 만든다
5. 방위각마다 4차 다항식을 빼서 그릇 자체의 곡률을 제거한다
6. 남은 기복을 공간 주파수로 분해한다

**대역은 입력 사진에서 정했다.** 사진 벽면의 밝기 프로파일이 표본 구간에서 7주기를 보이고, 이는 측정 구간 기준 6~7주기다. 답을 미리 정해두지 않도록 대역은 그 둘레로 넉넉히 **4~18주기**를 잡았다. 그 아래는 그릇의 형태, 그 위는 패싯과 계단 아티팩트다.

**결과**

| 모델 | 진폭 (% 지름) | 형태 &lt;4 | 융기선 4–18 | 미세 &gt;18 | 간격 | 판정 |
|---|---:|---:|---:|---:|---:|---|
| SAM 3D Objects | **0.828** | 8% | **77%** | 15% | 5주기 | 최선명 |
| TRELLIS | **0.441** | 28% | 40% | 32% | 4주기 | 재현 |
| TripoSR | 0.225 | 55% | 38% | 7% | — | 소실 |
| Stable Fast 3D | 0.202 | 55% | 38% | 7% | — | 소실 |

![물레흔 정량화](./images/물레흔-정량화.png)

왼쪽이 벽을 펼친 기복 지도다. 세로가 높이, 가로가 둘레, 붉은 띠가 부푼 곳, 푸른 띠가 꺼진 곳이다. **SAM 3D Objects만 전폭을 가로지르는 띠가 5~6줄 뚜렷하고**, TRELLIS는 같은 띠가 패싯에 끊겨 있으며, 나머지 둘은 거의 백지다.

수치로 정리하면:

- SAM 3D Objects는 TRELLIS의 **약 2배 깊이**로 융기선을 새기고, 기복의 **77%가 융기선 대역**에 몰려 있다
- 나머지 둘은 그 **1/4 깊이**에, 기복의 절반 이상이 그릇 자체 형태다 — 잃을 융기선이 애초에 없다

**그리고 TripoSR이 눈을 속인 이유가 밝혀졌다.** 계단 무늬는 기하학적으로 거의 없다 — 미세 대역 기복이 지름의 **0.07%**에 불과하다. 그런데도 렌더에서 선명한 이유는 계단이 **표면 법선을 꺾어 음영을 과장**하기 때문이다. 깊이가 아니라 각도를 바꾸는 결함이라, 눈에는 크게 보이고 자에는 잡히지 않는다.

**실패한 두 접근**

`results/_scripts/ridge_metrics.py` 문서화 주석에 남겨 재시도를 막았다.

- **가우시안 추세 제거는 실패했다.** 허리로 급강하하는 끝단이 그대로 남아 분산을 지배하고, 융기선이 최저 주파수에 묻힌다. 방위각마다 4차 다항식을 빼는 방식으로 바꿔 해결했다.
- **방위각 평균은 실패했다.** 처음에는 "진짜 융기선은 θ에 무관하다"는 성질로 결맞음도를 재려 했는데, 손물레 성형흔은 둘레를 돌며 높이가 조금씩 흔들리고 재구성이 그 흔들림을 그대로 물려받는다. 평균을 내면 진짜 융기선까지 지워진다. 위 도판에서 띠가 완만한 아치를 그리는 것이 그 흔들림이다. 방위각별 스펙트럼을 **합산**하는 방식으로 바꿔 해결했다.

### 8.4 TripoSR의 genus 0

가장 인상적인 결과다. 면은 189,376개로 TRELLIS의 **13배**지만 관통 구멍이 **하나도 없다**. 굽다리의 창은 표면에 찍힌 음영으로만 남았다.

**면 수는 해상도이지 구조가 아니다.** 만약 육안 렌더만으로 판정했다면 TripoSR을 "그럭저럭 쓸 만함"으로 분류했을 가능성이 높다. 위상 지표가 이를 막았다.

## 9. 한계

1. **유물 1점으로만 검증했다.** 굽다리바리는 투창이라는 명확한 위상 형질을 가진 특수한 사례다. 구멍이 없는 유물(발, 완, 병)에서는 genus 기준이 작동하지 않으므로 다른 판정 지표가 필요하다.
2. **구연부 판정만 아직 육안이다.** 투창은 genus로, 물레흔은 주파수 분석으로 측정되지만(8.3), 파손 재현 여부는 여전히 크롭을 보고 정한다. "결실을 메우지 않았는가"를 재는 지표가 필요하다 — 구연부 높이의 방위각 분산 같은 것이 후보다.
3. **입력이 정면 1장뿐이다.** 뒷면은 전적으로 모델의 추정이며, 그 추정이 맞는지 검증할 근거가 없다. 실물이나 다시점 사진과 대조하지 않았다.
4. **정량 오차를 측정하지 않았다.** 네 모델의 결과가 실제 유물 치수와 얼마나 다른지 계산하지 않았다. 유물의 공개 실측치를 확보하지 못했다.
5. **텍스처 품질을 정량화하지 않았다.** "TRELLIS의 색이 낫다"는 육안 판정이며 색차(ΔE) 같은 지표로 재지 않았다.
6. **재현 시간을 측정하지 않았다.** SAM 3D만 321초로 기록했고 나머지 3종의 추론 시간은 남기지 않았다. 파이프라인 설계에는 이 값이 필요하다.
7. **시드를 1개만 썼다.** seed 42 단일 실행이라 결과의 분산을 모른다.

## 10. 다음 작업

### 우선순위 1: 깨진 것과 온전한 것

`Compairs_broken`(백자발편)과 `Compairs_unbroken`(백자발) 쌍이 이미 준비되어 있다. **파손된 유물을 재구성할 때 무엇이 무너지는지**를 온전한 대응물과 비교해 확인한다. 이것이 프로젝트의 본 목적에 가장 가깝다.

### 우선순위 2: 형질 일반화

- 나머지 유물 2점(바리, 심발형토기)을 돌려 굽다리바리 결론이 다른 기형에도 적용되는지 확인한다.
- 구멍 없는 유물용 판정 지표를 정한다 (곡률 분포, 회전 대칭성 잔차 등).

### 우선순위 3: 두 모델의 장점 합치기

지오메트리는 SAM 3D, 색은 TRELLIS가 낫다는 결과에서 자연스럽게 나오는 방향이다.

- SAM 3D 메시를 UV 언랩하고 정점 색을 텍스처 맵으로 베이크한다.
- 경량화 후에도 색이 유지되는지 확인한다.
- 가능하면 원본 사진을 직접 투영해 텍스처 품질을 올린다.

### 우선순위 4: 파이프라인화

- 4종 추론 시간을 측정해 처리량을 산정한다.
- 마스크 생성 → 재구성 → 껍데기 정리 → 데시메이션 → 검증을 한 스크립트로 묶는다.
- 위상 검증을 자동 게이트로 만들어 genus 0 결과를 자동 기각한다.

## 12. 결론

사진 한 장에서 문화유산 유물을 3D로 복원하는 모델 4종을 같은 카메라·같은 면 수로 맞춰 비교했다.

**방법론에서 얻은 것**이 개별 모델 순위보다 중요하다.

1. **비교 실험은 측정 장치를 먼저 고정해야 한다.** 각 모델의 데모 스크립트로 뽑은 그림은 모델이 아니라 데모 스크립트를 비교한다.
2. **육안 판정은 구조를 놓친다.** TripoSR은 189,376면을 쓰고도 관통 구멍이 0개였다. 오일러 지표가 아니었다면 걸러내지 못했을 것이다.

3. **육안으로 판정해야 하는 형질은 판정이 갈리는 부위를 확대해야 한다.** 전체 그림에서는 함몰과 관통이 같아 보이고, 계단 아티팩트가 물레흔처럼 보인다. 축소된 대조표만 보고 적었던 Stable Fast 3D의 `부분/부분/부분`은 사실 `6/16 · 소실 · 재현`이었다.

4. **형질을 물리적으로 정의하면 육안을 벗어날 수 있다.** "물레흔이 있다"는 인상이지만 "벽을 도는 일정 간격의 띠가 지름의 몇 %만큼 깊다"는 측정이다. 정의를 내리자 SAM 3D가 TRELLIS의 2배 깊이라는 것과, TripoSR의 계단 무늬가 지름의 0.07%뿐인 **법선만 꺾는 결함**이라는 것이 함께 드러났다. 눈을 속인 이유까지 설명된다.
5. **면 수를 통제하지 않은 비교는 결론을 뒤집는다.** 68배 차이를 없애자 "SAM 3D 우세"가 "지오메트리는 SAM 3D, 색은 TRELLIS"로 갈라졌다.
6. **수치가 이상한 것과 삭제해도 되는 것 사이에는 검증이 필요하다.** 159개 껍데기를 부호거리로 검증하고 나서야 버릴 수 있었다.
7. **요구 사양은 대개 가장 무거운 한 단계의 요구치다.** 단계별 계측으로 병목 한 곳을 찾아 CPU로 내리자 32GB 모델이 8GB에서 70초 추가 비용으로 돌았다.

**실무에서 얻은 것**은 실행 환경도 결과의 일부라는 점이다. `decode/mesh` 단계가 8GB의 84%를 짚는다는 사실과, 그것을 배터리로 돌려 두 번 블루스크린이 났다는 사실은 파라미터만큼이나 재현에 필요한 정보다.

다음 단계는 이 방법론을 **파손 유물**에 적용하는 것이다. 온전한 유물에서 확립한 판정 기준이 결손이 있는 대상에서도 작동하는지가 프로젝트의 실제 관문이다.
