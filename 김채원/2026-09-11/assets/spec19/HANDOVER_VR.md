# VR 트랙 전달 — 인왕제색도 복원 지형 v0.11

- 전달: 김채원 (AI) → VR 트랙
- 날짜: 2026-09-11
- **v0.10에서 실기 임포트로 드러난 결함 3개를 고친 판이다.** 아래 "v0.10에서 바뀐 것" 참조.

---

## 0. v0.10에서 바뀐 것 (먼저 읽어 주세요)

2026-09-11에 UE 5.8.2로 직접 넣어 보고 세 가지를 고쳤다.

| # | v0.10의 문제 | v0.11 |
|---|---|---|
| 1 | **자산이 90° 누워 들어옴.** glTF 규격(+Y up)을 어기고 Z-up으로 내보냈는데, 임포터가 Y→Z 변환을 한 번 더 걸었다 | **glTF 규격대로 +Y up.** 임포트 시 **회전 보정 불필요** |
| 2 | **런타임 지형에 원화가 거의 없었다.** 평면(위에서 본) UV를 써서, 시점을 향한 급사면이 위에서 보면 면적이 0에 가까워 먹이 뭉개졌다 | **카메라 투영 UV + 아틀라스 1장.** 보이는 사면 정점 28%에 원화가 그대로 붙는다 |
| 3 | 나무·집·운무가 회색 덩어리 | 정점색은 그대로. **머티리얼 만드는 법을 5절에 적었다** (한 번만 만들면 됨) |

그리고 실기로 확인된 것:

- **`Import Uniform Scale = 100` 은 필요 없다.** 임포터가 meter→cm 를 자동으로 한다
  (측정: `크기 근사치 250,200 x 53,460 x 285,000` = 2502 x 534.6 x 2850 m)
- **`MeshScale`·`MeshRollFix` 는 이제 정말 필요 없다.** 보정값을 넣어야 한다면 그건 이 파일의 결함이다

## 1. 무엇을 넣으면 되나

`runtime/` 7개 파일. 한 장면에 **지형 1 + 나무 + 기와집 + 운무**를 놓는다.

| 파일 | 면 수 | 역할 |
|---|---:|---|
| `runtime/terrain_jeong.glb` | 10,000 | **정선의 지형** (과장 적용) — 기본으로 이걸 쓴다 |
| `runtime/terrain_real.glb` | 10,000 | 실측 지형 — 토글용. 위와 **같은 좌표·pivot** |
| `runtime/trees.glb` | 10,271 | 나무 168그루 (동양 소나무 167 · 버드나무 1) |
| `runtime/house.glb` | 32 | 기와집 2동 — **저폴리 자리표시** |
| `runtime/fog.glb` | 1,130 | 운무 (반투명) |
| `runtime/inscription.glb` | 2 | 화제·인장 (공중에 뜬 판, 알파 텍스처) |
| `runtime/base.glb` | 2,682 | 디오라마 받침 — 1:1 몰입에서는 숨겨도 됨 |

**한 단계 표시 시 장면 면 수 = 24,117** (명세 20장 임시 기준 30,000 이내)
**텍스처 1장** — 지형 아틀라스 1024×1024. 나머지는 정점색.

`master/` 는 줄이지 않은 원본이라 **VR에는 넣지 않는다** (지형 396,150면).

## 2. 좌표·단위 계약

| 항목 | 값 |
|---|---|
| 단위 | **meter** (임포터가 cm로 자동 변환) |
| 파일 안 상하축 | **+Y** (glTF 2.0 규격) |
| 임포트 뒤 상하축 | **+Z** (언리얼이 자동 변환) |
| pivot | **바닥 중심** (7개 파일 전부 동일) |
| 포맷 | glTF 2.0 GLB |
| 단계 정렬 | `terrain_real` ↔ `terrain_jeong` 동일 변환 |

> 명세 19.3은 `up_axis: Z` 라고 적고 있는데, **그건 '엔진에 들어간 뒤'를 가리키는 말**이다.
> conformant 한 glTF 파일 안은 +Y 일 수밖에 없다. 문구 정정은 `AMEND-19.md` 2-5에.

**임포트 요령**

1. `.glb` 7개를 콘텐츠 브라우저로 드래그 (기본 옵션 그대로)
2. 레벨에 놓고 **위치 (0,0,0) · 회전 (0,0,0) · 스케일 1** — 그게 전부다
3. pivot이 전부 같아서 **같은 값만 넣으면 알아서 맞물린다**

축척을 바꿀 때(축소 디오라마)는 **7개 전부에 같은 배율**. 3 m 폭 디오라마 ≒ 1:830.

## 3. 1:1 몰입 — 관람자가 설 자리

`records/entry_point.json`. 스카이라인 정합으로 구한 **정선의 시점** 그 자리다.

| | 에셋 로컬 (glTF, meter) | 언리얼 예상 (cm) |
|---|---|---|
| 눈 위치 | X −1.0 · **Y 154.3** · Z 1175.0 | X −117,500 · Y −100 · **Z 15,433** |
| 바라보는 방향 | **−Z** | **+X** |
| 위쪽 | +Y | +Z |

- 눈높이 1.6 m (발밑 바닥은 에셋 로컬 Y = 152.7)
- 진북 기준 방위 288.93° · 수평화각 45.0°
- **언리얼 값은 예상치다.** 임포트 후 한 번 확인해 주면 문서를 확정하겠다

> 발밑은 아직 평지다. 근경 0~200 m 기복이 4.6 m뿐 (수치지형도가 서촌 시가지를 평탄화).
> 임시로 절차적 잔결층(최대 1.15 m)을 얹어 뒀고, 나무 밑동 역산이 끝나면 지형만 교체된다.

## 4. 머티리얼 — Unlit 으로 해 주세요

모든 색이 **원화(먹그림)에서 나온 값**이다. PBR 라이팅을 걸면 먹의 농담이 조명에 덮여 화풍이 깨진다.

- **Shading Model: Unlit**
- **지형** : Emissive Color 에 임포트된 `baseColorTexture` (아틀라스) 연결
- **나무·기와집·받침** : Emissive Color 에 **Vertex Color** 연결 (5절)
- **운무** : 위와 같되 `Blend Mode: Translucent` + Vertex Color 의 **Alpha**
- **화제(`inscription`)** : 알파 있는 RGBA 텍스처다 (`alphaMode: BLEND`, 투명 화소 59.6 %).
  `Blend Mode: Translucent` (또는 `Masked`) + 텍스처의 **알파를 오파시티**에 연결.
  안 하면 **검은 사각형**으로 나온다

> 런타임에는 노멀맵을 넣지 않았다. Unlit 에서는 접선공간 노멀이 작동하지 않고,
> 아틀라스 UV 와 평면 UV 를 한 메시에 동시에 물릴 수 없기 때문이다.
> `tex_terrain_normal_1k.png` 는 나중에 Lit 경로를 쓸 때를 위해 번들에 남겨 뒀다.

## 5. 정점색 머티리얼 만들기 (한 번만)

나무·기와집·운무·받침은 텍스처가 없고 **메시에 색이 박혀 있다**(정점색). 언리얼 기본
머티리얼은 정점색을 무시하므로 회색으로 나온다. 아래 머티리얼 하나를 만들어 4개에 물리면 된다.

1. 콘텐츠 브라우저 빈 곳 **우클릭 → 머티리얼** → 이름 `M_InwangVertexUnlit`
2. 더블클릭해서 열고, 왼쪽 **디테일** 패널에서 **`셰이딩 모델` → `Unlit`**
3. 빈 곳 우클릭 → `VertexColor` 검색해서 노드 추가
4. `VertexColor` 의 **RGB 출력**을 결과 노드의 **`이미시브 컬러`** 에 연결
5. **적용 → 저장**
6. 레벨에서 `trees`·`house`·`base` 선택 → 디테일 **머티리얼 → 엘리먼트 0** 에 이 머티리얼 드래그

운무는 반투명이라 하나 더 만든다 — 위와 같게 만들되:
- **`블렌드 모드` → `Translucent`**
- `VertexColor` 의 **A 출력**을 **`오파시티`** 에 연결
- 이름 `M_InwangFogUnlit`

## 6. 이번에 확인하고 싶은 것 (우선순위)

1. **임포트가 무보정으로 되는가** — 회전 0 / 스케일 1 로 똑바로 서는가
2. **1:1 스케일이 산으로 느껴지는가** — 사람 키 1.7 m 기준. 대조군: 기와집 본채 폭 22.3 m
3. **먼 능선이 그림처럼 납작해 보이는가** ← **1:1 몰입(B안)의 최대 리스크.**
   양안시차가 10~30 m 밖에서 사실상 사라진다. 그렇다면 축소 디오라마를 테마관에 같이 두는 걸 검토
4. **프레임** — 24,117면 + Unlit 에서 `stat fps` 얼마.
   **장면 전체 면 수·목표 fps 는 명세 20장에 아직 "미확정"** 이니 이 값을 같이 기록해 D-29 에 올리자
5. **정점색이 살아 있는가** — 5절대로 했는데도 회색이면 알려 주세요
6. **운무 알파가 나오는가**
7. 가능하면 Quest 2 내부 빌드에서도 1~6
   - ⚠️ **나나이트는 반드시 끄고** 빌드할 것. 모바일에서 지원되지 않는다
     (임포트 시 기본으로 켜진다. 메시 선택 → 우클릭 → 나나이트 → 비활성화)

## 7. 알려진 한계 (이 단계에서는 고치지 않음)

- **전경 지형이 평평하다.** 근경 0~200 m 기복 4.6 m. 그 자리가 서촌 시가지라 2024년
  수치지형도에서 평탄화돼 있다. 원화에서 역산해 복원할 예정이며, 결과가 나오면 지형 파일만 교체된다
  (좌표 계약은 그대로). 그때까지 **절차적 잔결층(최대 1.15 m)** 을 얹어 뒀다 — 측정값이 아니다
  (`records/micro_relief.json`)
- **런타임 지형의 원화는 보이는 사면(정점 28%)에만 붙는다.** 화면 밖·가려진 면·스침각 구역은
  평면 베이스컬러(음영기복 + 원화 하단 지면 톤)다. 원화 해상도도 아틀라스 1024 폭이라
  원본 3000 폭 대비 3배 손실이 있다
- 나무·기와집이 아직 **저폴리 자리표시**다. 위치·크기는 측정값이고 형상은 임시다
  (기와집은 32면 — 지붕면 + 기둥)
- 전경 나무의 실물 높이가 2~4 m로 작다. 전경 지형 문제와 같은 원인이다
- 기와집 본채 폭 22.3 m는 지붕선 획 2개를 한 채로 합친 값이라 두 채일 가능성이 있다
- **원화 이미지의 소장기관 표기·이용조건 미확인.** 대외 공개물에는 아직 쓰지 말 것
