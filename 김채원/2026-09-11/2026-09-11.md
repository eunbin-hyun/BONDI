## 3. 발견된 결함 3개 — **전부 AI 트랙(내) export 쪽**

### 3-1. 축이 90° 누워 들어온다 ★ 가장 중요

**증상.** 크기 근사치가 `X 2502 / Y 534.6 / Z 2850`. **높이(534.6 m)가 Y축에 가 있다.** 산이 옆으로 누웠다.

**원인.** glTF 2.0 규격은 **+Y 가 위**로 정해져 있다. 그런데 `export_spec19.py` 에서 팀 좌표 계약(`up_axis: Z`)에 맞춘다고 회전 `R = X축 +90°` 을 적용해 **Z-up 으로 내보냈다.**
언리얼 임포터는 "glTF니까 Y-up이겠지" 하고 **한 번 더 Y→Z 변환을 걸어** 결과적으로 90° 틀어졌다.

**의미.** 이것이 바로 `MeshScale`·`MeshRollFix` 같은 **임포트 보정 필드가 생기는 전형적 원인**이다.
그리고 명세 19.3의 `up_axis: Z` 라는 표현 자체가 glTF 규격과 모순된다 —
**conformant 한 glTF 파일은 Y-up 일 수밖에 없고, Z-up 은 "언리얼에 들어간 뒤의 상태"를 가리켜야 한다.**
19장 개정안(`AMEND-19.md`)에 이 문구 정정을 추가해야 한다.

**조치.** `R` 을 제거하고 Y-up 을 지켜 재수출한다. `records/entry_point.json` 좌표와
`check_coordinate_contract.py` 도 같이 고친다.

**임시 회피.** 액터 회전 X(롤)에 ±90 을 넣으면 선다. 정본에서는 불필요해진다.

### 3-2. 런타임 텍스처에 원화가 거의 없다 ★

**증상.** `라이팅제외`(언릿)로 봐도 지형이 **밝은 베이지 한 톤**이다. 먹그림이 안 보인다.
조명 문제가 아니라는 게 언릿으로 확정됐다.

**측정.**

```
tex_terrain_basecolor_1k.png
평균 RGB 154 / 141 / 127
어두운 화소(밝기 120 미만) 비율 20.8 %
```

**원인.** 지형 텍스처가 두 벌인데 내용이 다르다.

| | 텍스처 | 원화 비중 |
|---|---|---|
| `master/` (396,150면) | 카메라 투영 아틀라스 2048×3219 | 먹그림 그대로 |
| `runtime/` (9,999면) ← VR에 넣는 것 | 위에서 내려다본 평면 UV 1024 | **5.1 %** |

감면(폴리곤 줄이기) 뒤에도 UV가 살아남게 하려고 평면 UV로 바꾼 것이, **화풍 손실**로 이어졌다.
09-10에 넣은 스침각 보정(전경 검은 띠 제거)이 이를 더 키웠다.

블렌더 렌더가 먹그림으로 나왔던 것은 **master 를 썼기 때문**이다. 두 화면이 달랐던 이유가 이것이다.

**조치.** 런타임 평면 베이스컬러에 원화 투영을 제대로 굽는다. 스침각 보정은 유지하되
**시점에서 보이는 사면에는 원화가 진하게 남도록** 가중치를 다시 잡는다.

### 3-3. 정점색을 읽는 머티리얼이 없다

나무·기와집·운무는 텍스처가 아니라 **정점색(vertex color)** 으로 색을 갖는다.
언리얼 기본 머티리얼은 정점색을 무시하므로 회색 덩어리로 나온다.

**조치.** 정점색을 Emissive 로 읽는 Unlit 머티리얼 1개를 만들어 번들에 동봉하거나,
`HANDOVER_VR.md` 에 노드 구성을 그림으로 적는다.

### 9-1. 머티리얼 — 왜 필요했나

| 파트 | GLB 안의 색 정보 | 언리얼 임포트 결과 |
|---|---|---|
| terrain_jeong · terrain_real · inscription | `baseColorTexture` | 머티리얼 자동 생성 — 그대로 보임 |
| base · house · trees · fog | `COLOR_0` (정점색) 만, 머티리얼 없음 | **`WorldGridMaterial`(회색 격자)** |

fog 는 정점색 평균 RGB 0.92(거의 흰색) · 알파 0.07~0.91 이라 **Translucent + 알파→Opacity** 가 없으면 흰 안개가 아니라 회색 판이 된다.
inscription 도 알파 텍스처라 Translucent 가 필요하다.

만든 머티리얼 (전부 Unlit, Emissive 에 색 연결):

| 머티리얼 | 입력 | 블렌드 | 배정 |
|---|---|---|---|
| `M_InwangVertexUnlit` | VertexColor RGB | Opaque | base · house · trees |
| `M_InwangFogUnlit` | VertexColor RGB + A→Opacity | Translucent, 양면 | fog |
| `M_InwangTerrainJeong` / `…Real` | 텍스처 RGB | Opaque | terrain_jeong / terrain_real |
| `M_InwangInk` | 텍스처 RGB + A→Opacity | Translucent, 양면 | inscription |

### 9-2. 시점 — entry_point.json 의 언리얼 좌표는 추정이었고 틀렸다

`records/entry_point.json` 의 `unreal_예상` (`UE_X=-gZ, UE_Y=gX, UE_Z=gY`, 정면 +X) 로 카메라를 보내니
**산이 정면에 없었다.** 파일에 "임포트 후 확인할 것" 이라고 써 둔 그대로, 임포터 축 변환을 내가 추정한 값이었다.

고친 방법: 추정을 버리고 **측정**한다. `ue_goto_entry.py` 가 `trees` 액터의 언리얼 바운딩 박스(중심·폭)를
glTF 원본 바운딩 박스와 축별로 대조해 어느 축이 어느 축으로, 어떤 부호로 갔는지 결정한 뒤 눈 위치를 변환한다.
로그에 `매핑 [측정]: UE_X = …` 로 찍힌다. → **v0.12 에서 `entry_point.json` 의 `unreal_예상` 을 이 측정값으로 교체한다.**

### 9-3. 삽질 기록 (같은 실수 방지)

- **SkySphere 에 머티리얼이 떨어졌다.** 뷰포트 빈 곳에 머티리얼을 드래그하면 화면 전체를 덮는 `SM_SkySphere` 가 받는다.
  하늘이 검게 되고 갈색 줄이 생긴 원인. 스크립트로 액터에 직접 배정하면 생기지 않는다
- **VertexColor 노드의 RGB 출력 핀 이름은 `""`(빈 문자열)** 이다. `"RGB"` 는 TextureSample 용. `connect_material_property(vc, "RGB", …)` 는 조용히 `False` 를 돌려준다
- `EditorActorSubsystem.get_all_level_actors_of_class` 는 **없다.** `get_all_level_actors()` + `isinstance`
- 드래그로 놓은 액터는 커서 자리에 떨어진다. 파트 7개를 전부 (0,0,0) 으로 맞추는 걸 스크립트 첫 단계로 넣었다

## 10. VR 첫 착용 — ALVR + SteamVR (기기 4)

팀 PC VR 경로는 Meta Horizon Link 가 아니라 **ALVR + SteamVR** 이다
([공세민 — quest2-alvr-steamvr-setup.md](../../공세민/quest2-alvr-steamvr-setup.md)). Meta 계정 작업 없음.

```
언리얼 VR 프리뷰 → OpenXR → SteamVR(활성 런타임) → ALVR 드라이버 → ALVR Streamer(PC) ─Wi-Fi─▶ ALVR 앱(Quest 2)
```

- SteamVR 홈이 헤드셋에 뜬 뒤에도 언리얼 **VR 프리뷰가 회색**이었다. **언리얼을 껐다 켜니 바로 활성화.**
  언리얼은 에디터를 켤 때 헤드셋을 찾으므로, SteamVR 이 언리얼보다 늦게 켜졌으면 재시작이 필요하다.
  → 순서는 **SteamVR 홈 확인 → 그 다음 언리얼 실행** (공세민 문서 7절 표에 이 항목 추가할 만함)
- **공세민 문서 7절 "언리얼 VR Preview 미검증" 항목 → 오늘 기기 4에서 검증됨.** 양손 컨트롤러도 보였다 (= `BP_XRPawn` 이 잡힘)
- 착용 소감: 보이는 것 자체는 좋았다. 정량 확인 4항목(11절)은 **배터리 방전으로 못 했다**
- 시작점 바꾸기: ⋮ → "다음 위치에 플레이어 스폰… → 현재 카메라 위치" (임시) 또는 `ue_start_here.py` (저장)

## 12. 오후 후반 — 나무·기와집 품질 보강 (v0.11.1)

VR 은 됐으니 "디테일이 부족하거나 움직임이 필요한 부분" 을 손봤다. 대상은 나무·기와집·운무.

### 12-1. 나무 v4 (`assets/scripts/build_trees4.py`)

런타임 번들의 나무가 버섯처럼 보인 이유: `export_spec19.py` 가 **LOD 버전**(줄기 2마디·수관 2층·5각형)을 런타임에 넣고 있었다.
v4 는 굽은 줄기 5마디 + 수관 3~4층 + 가지 끝 덩어리, 거리별 LOD(근 9각형·4층 / 중 7각형·3층 / 원 6각형·2층). 면 10,271 → 37,724.
정점 알파는 255 고정, 흔들림 마스크(밑동 0 → 꼭대기 1)는 **TEXCOORD_0.x** 에 담았다.

**그래도 "팽이버섯" 이다.** 절차 생성으로는 먹점 덩어리 흉내가 한계고, 이 세션엔 블렌더도 없다. → 15절로 방향 전환.

### 12-2. 색 — 원화 팔레트로 통일 (`records/ink_palette.json`)

기와집 지붕이 갈색으로 보여 원화의 본채 지붕 영역을 재 봤다: 평균 sRGB (128,120,112). 종이(184,168,149)보다 **R-B 차가 35 → 8** 로 줄어드는
차가운 회색 담묵이다 — "물빠진 남색" 으로 느껴지는 게 이것. 그래서 색은 전부 **마스크된 원화의 밝기 분위별 평균**으로 뽑아 통일했다.

| 톤 | sRGB | 쓰임 |
|---|---|---|
| 진묵 (0~5 %) | 56 · 52 · 52 | 처마선 · 용마루 · 나무 어두운 면 |
| 중묵 (5~25 %) | 71 · 67 · 65 | 기둥 |
| 담묵 (25~55 %) | 108 · 101 · 96 | **지붕면** · 나무 위쪽 번짐 |
| 옅은담묵 (55~80 %) | 157 · 146 · 131 | 기단 · 벽 |
| 종이 (85~95 %) | 186 · 170 · 150 | 원경 바램 |

### 12-3. 기와집 v2

기단 + 기둥 + 처마 곡선(모서리 들림) 우진각 지붕 + 용마루, 면 32 → 784. 배치·크기·방향은 v0.11 `house.glb` 에서 그대로 복원.
지붕면 담묵, 처마는 **얇은 진묵 띠**, 벽이 옅은담묵이 되면서 기둥만 선 **정자**처럼 읽힌다 — 원화의 그 집이 실제로 그 형태라 맞는 방향.
다음 버전에서 벽을 빼고 안쪽을 어둡게 하면 더 가깝다.

### 12-4. 삽질 — 오늘 오후 두 번째 묶음

- **회색 나무의 원인은 내 색 값이었다.** 정점색은 잘 들어와 있었는데(한 머티리얼에서 줄기·수관 밝기가 달랐다 = 정점색 표시 중)
  "위쪽을 밝게" 한다고 종이색 28 % 를 섞은 값이 화면에선 sRGB 112(중간 회색). 옛 나무는 62.
- 그걸 못 알아본 이유: **내 미리보기 렌더(`render_runtime.py`)가 리니어 정점색을 감마 변환 없이 찍어** 실제보다 새까맣게 보였다.
  → `render_runtime_srgb.py` 로 고침. 이후 밝기는 **숫자(sRGB 백분위)로 같이 적는다**
- 그 전에 "정점 알파 ≠ 255 면 5.8 임포터가 정점색을 버린다" 고 진단했는데 **틀렸다.** 철회. (알파를 안 쓰는 건 도구별 해석 차 때문이지 임포터 버그가 아님)
- 콘솔 모드 혼동: **Cmd 모드는 `py "경로"`, Python 모드는 경로만.** 반대로 치면 각각 "파일 못 찾음" / 아무 일도 안 일어남
- `StaticMesh.get_num_triangles(0)` 은 Nanite 대체 메시 면 수라 원본 면 수와 다르다. 새 파일인지 확인은 `asset_import_data.get_first_filename()` 이 확실

## 15. 방향 전환 — 나무·버드나무·정자는 AI 생성으로

절차 생성 나무는 원화의 먹점을 흉내내는 데서 끝났다. AI 트랙이 "Fab 에서 받아왔다" 로 끝나는 건 맞지 않으니 **원화에서 만드는 파이프라인**으로 간다.

```
원화 크롭 (images 아래 ai3d_inputs/: pine_1~3 · willow_1 · pavilion_main)
  → ① 이미지 생성 모델로 '정선 화풍 한 그루, 정면, 단색 배경' 컨셉 이미지   ← 원화 크롭은 겹침·안개 때문에 직접 못 씀
  → ② image-to-3D (glb)
  → ③ 후처리: Y-up · pivot · 스케일, 먹 팔레트 정점색 굽기 → runtime 규격
  → ④ ue_place_trees.py 로 168곳 배치 (소나무 167 · 버드나무 1) + 정자 교체
```

도구 후보 (09-11 검색, 라이선스 원문 재확인 필요): **TRELLIS.2** — MIT, GLB, HF Space (로컬은 VRAM 24 GB) / **TripoSR** — MIT, 6 GB, 정점색만 (먹색 덮으니 무관) /
**Hunyuan3D 2.1** — 커뮤니티 라이선스가 **한국 제외** → 쓰지 않음.

제약: 이 작업 세션엔 GPU 가 없다 → ①·② 는 HF Space 나 팀 PC, ③·④ 는 내 쪽. 실패 시 대비책: Fab 무료 소나무 + `M_InwangInkWash` (스크립트는 메시 출처를 안 가림).
첫 실험 범위: 소나무 1종으로 한 바퀴(크롭 → 컨셉 → glb → 언리얼) 3시간. 되면 버드나무·정자.

**원화 이미지 이용조건 미확인** — 크롭·생성물은 팀 내부 개발용에 한정. 대외 공개물엔 확인 전까지 넣지 않는다.

## 16. 저녁 — AI 생성 소나무 첫 바퀴 (TRELLIS.2 → 수묵 자산 → 언리얼)

15절 파이프라인을 바로 돌려봤다. 결과: **소나무 2그루 자산 확보.** 정자·버드나무는 실패.

| 단계 | 결과 |
|---|---|
| 입력 | `images/ai3d_inputs/pine_4_isolated_nobg.png` (원화 크롭, 종이→알파. 단, 종이 질감이 반쯤 남음) |
| 생성 | `microsoft/TRELLIS.2` 허깅페이스 Space (ZeroGPU). **로그인 안 하면 하루 한도가 120초 미만이라 한 번도 못 돌림** → HF 로그인 후 실행. 몇 번 돌리면 한도 소진 |
| 원본 출력 | 29만 면 · 15 MB · 조각 3.4만 개. 나무가 아니라 **크롭 장면 전체가 부조**로 나옴 — 종이 시트(z≈-0.42 평면에 정점 10만 개) + 그 앞에 나무 2그루 |
| 정자 · 버드나무 | 이상하게 나옴 (버드나무는 가는 선 다발, 정자는 선화라 부피 단서 없음) → **선으로 된 건 절차 생성, 부피 있는 것만 AI** 로 역할 분담 |

### 16-1. 후처리 (`assets/scripts/build_pine_ai.py`)

```
종이 시트 제거 (z 히스토그램으로 평면 위치 찾음) → 얇은 카드·틀 막대 제거 → 오른쪽 나무 영역 → 앞뒤 2그루 분리
→ 복셀 300칸 → 팽창 2 → 닫힘 → 마칭큐브       ← 흩어진 붓 자국 조각을 잇는 핵심
→ Taubin 스무딩 12회 (복셀 계단 제거) → 감면 ~13.5k 면
→ 바닥 중심 pivot, 높이 1 m 정규화 (Y-up)
→ 먹 팔레트 정점색: 원 텍스처 밝기 + 위를 보는 면 → 담묵, 저주파 노이즈로 번짐 얼룩, 위로 갈수록 엷게
→ runtime/pine_ai_1.glb, pine_ai_2.glb (각 350 KB)
```

파라미터 이력: 110칸·팽창2 = 솜뭉치 / 170칸·팽창1 = 층은 살지만 계단 자국 / 200칸 + 스무딩 = 붓 느낌 / **300칸·팽창2 = 채택** (300칸·팽창1 은 다시 성글어짐).

### 16-2. 배치

`ue_place_trees.py` v2: `pine_ai_1`·`pine_ai_2` 를 번갈아 167곳에 심고(스케일 = 원화 측정 높이 m, 메시가 1 m 정규화라 곱셈 하나), 머티리얼은 검증된 `M_InwangVertexUnlit` (색이 정점에 구워져 있음). 버드나무 1곳은 메시 없어 건너뜀.

### 16-3. 남은 한계

- 형태가 **서양 침엽수 원뿔형**. 정선의 우산형 소나무는 다음 입력(이미지 생성 모델로 만든 컨셉 이미지)에서 잡아야 함
- 입력의 종이 질감 제거가 덜 됐던 게 "장면 부조" 출력의 원인 → 다음엔 알파를 0/255 로 확실히 자르고 한 그루만
- 언리얼에서 심은 결과 확인은 아직 (12일로 이월)
