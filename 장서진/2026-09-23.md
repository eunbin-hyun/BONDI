## 1. 프리뷰 창 프레임 저하 — 미해결

### 1.1 무엇을 재야 하는지부터 틀렸다

처음엔 ALVR `session_log.txt` 의 `[GRAPH]` 간격을 쟀다. 그런데 그건 **헤드셋으로 가는 스트림**이다.
시연에서 관객이 보는 것은 **PC 프리뷰 창**이고, 그건 언리얼이 직접 그린다.
ALVR 은 프레임을 재탕해 71 fps 처럼 보이게 만들기 때문에 프리뷰 창 상태를 과대평가한다.

| 같은 구간 | 헤드셋 스트림 | 프리뷰 창 |
| --- | --- | --- |
| 좋을 때 | 14 ms / 끊김 19~22% | **14 ms / 끊김 0.3~1.7%** |
| 나빠진 뒤 | 16~18 ms / 33~37% | **19~21 ms / 33~64%** |

프리뷰 창 프레임은 언리얼 로그 줄머리의 프레임 번호로 셌다.
`BP_PortalInwang` 이 매 틱 `PrintString` 을 찍고 있어서 그걸 프레임 표지로 썼다.

### 1.2 증상

세션 시작 후 1~5분 사이에 **14 ms(71 fps) → 17~20 ms(50~59 fps)**, 끊김 0.3% → 30~50%.
중앙값이 밀리기 전에 끊김 빈도가 먼저 오른다(0.2% → 3.9% → 10% → 32%).
**재현 7회.** 토글을 멈춰도 회복되지 않는다.

### 1.3 배제한 것

| 후보 | 어떻게 배제했나 |
| --- | --- |
| 네트워크 | 패킷 손실 0, 전송 지연 8~10 ms |
| HEVC 설정 풀림 | `session.json` 15개 항목 전부 `[OK]` 확인 |
| 스폰 누수 | PIE 액터 236개 고정 |
| FX 머티리얼 복구 실패 | 런타임에서 매번 정상 복구 확인 |
| 셰이더 컴파일 | 하루 누적 39개, 해당 세션엔 2개뿐 |
| 스펙테이터 고정 비용 | 첫 1분이 이미 스펙테이터 켠 상태로 14 ms |

### 1.4 세 번 틀린 기록

**(1) "인왕이 원인이 아니다"** — 14:40 세션이 인왕 없이 악화돼서 그렇게 말했다.
그런데 11:53·15:25 세션은 **FX 없이 인왕만으로** 악화됐다. 일반화가 틀렸다.

**(2) "토글 FX 가 원인으로 확정"** — 대조군 두 개(15:49 2.9분, 16:09 3.0분)가 깨끗해서 그렇게 말했다.
그런데 16:16 세션은 **토글도 인왕도 없이** 4.5분 지점에서 20 ms / 47.8% 로 무너졌다.
**대조군이 악화 시점 전에 끝난 것**이었다.

**(3) "PIE 재시작 때 이전 상태가 넘어온다"** — 16:09 세션이 17 ms 로 시작해서 그렇게 추측했다.
그 세션은 이어서 **15 ms 로 좋아졌다.** 워밍업이었다.

### 1.5 스스로 오염시킨 것

`probe_fx.py` 가 존재하지 않는 프로퍼티를 2초마다 조회해서
`LogScript: Warning: GetObjectProperties ... could not be read` 를 로그에 쏟고 있었다.
**15:57 부터 계속이었고, 그 뒤 세션이 전부 측정 대상이었다.**

> 교훈: 관찰 도구가 관찰 대상과 같은 자원(여기서는 로그와 게임 스레드)을 쓰면 측정이 오염된다.
> 실시간 관찰이 꼭 필요한 게 아니었다. 로그는 나중에 읽어도 되므로 처음부터 사후 집계를 했어야 했다.

### 1.6 남은 후보

- 메모리/오브젝트 누수 — 감시에 프로세스 메모리 기록을 넣었으나 오염 없는 표본을 못 모았다
- 텍스처 스트리밍 풀 포화
- **GPU 발열로 인한 클럭 저하** — 노트북 4070 이고 "몇 분 뒤 일정하게 나빠지고 잠깐 쉬면 회복" 패턴과 맞는다

### 1.7 다음에 할 것

**관찰 스크립트 없이** 6분 이상 한 세션. 토글·인왕 없이.
6분 내내 14 ms 면 트리거가 원인, 4~5분에 무너지면 시간이 원인이고 조사 방향을 바꿔야 한다.

## 2. 컨트롤러 입력 소실 — 원인 규명, 미해결

### 2.1 증상

유물방에서 조이스틱 이동과 유물 집기가 동시에 안 됐다. **손은 화면에서 정상적으로 움직였다.**

### 2.2 처음엔 프레임 탓으로 봤다 (틀림)

그 시간대 프레임의 81~96% 가 20 ms 를 넘겨서 "판정 반경을 프레임 사이에 통과했다"고 설명했다.
사용자가 지적했다 — **손을 가만히 들고 여러 번 시도했다면** 43 fps 로 초당 43번 판정한 셈이라 실패할 이유가 없다.
맞는 지적이었다. 그 설명은 손이 빠르게 지나갈 때만 성립한다.

### 2.3 실제 원인

SteamVR 로그가 답을 줬다.

```
[Remapping] oculus_touch → svl_hand_interaction_augmented
[Input] testproj.unrealeditor.exe (svl_hand_interaction_augmented)
```

장치 활성 이력이 결정적이다.

| 시각 | 장치 |
| --- | --- |
| 16:26:37 | `VRLINKQ_Hand_Left/Right` — **손만** |
| 16:28:15~26 | `Controller_Right` 가 붙었다 떨어졌다 반복 |
| 16:28:27 | `Controller_Left/Right` 활성, **동시에 `Hand_*` 제거** |

증상 시간대에는 **컨트롤러 장치 자체가 없었다.** 손 렌더링이 멀쩡했던 것과 완전히 일치한다.

### 2.4 `multimodal_tracking` 은 답이 아니었다

손과 컨트롤러를 동시에 쓰라고 ALVR 에서 켰는데(10:57), 켠 상태에서도
**컨트롤러가 붙자 손이 빠졌다.** Quest 2 에서는 기대대로 동작하지 않는 것으로 보인다.

게다가 **ALVR 대시보드가 종료할 때 자기 메모리 설정으로 `session.json` 을 덮어써서** 이 값이 `False` 로 되돌아갔다.
문서(`docs/vr-streaming-setup.md`)에 적혀 있는 함정인데 대비하지 않았다.

### 2.5 선택지

| 방법 | 대가 |
| --- | --- |
| 손 추적 끄기 | 컨트롤러 안정. **연수전 줄 당김이 죽는다**(손 추적 전용) |
| 컨트롤러 내려놓고 손만 | 줄 당김·유물 집기 가능, **스틱 이동 불가**. 텔레포트가 이미 구현돼 있어 확인 가치 있음 |
| 구간별로 나누기 | 연수전만 컨트롤러 내려놓기 |

## 3. B방 포탈 앞에서 스틱 이동이 막힌 건

`BP_XRPawn` 의 이동 구현이 원인이다.

```
IA_Move / IA_MoveStick
  → ContinuousMove
      → ClampMoveByWallTrace_0   (CapsuleTraceByChannel, 반경 20)
      → AddActorWorldOffset(bSweep = true)
```

**`bSweep=true` 라 캡슐이 막히면 이동이 0 이 된다.** 물리적으로 걷는 것은 HMD 가 움직일 뿐이라
스윕을 안 거친다 — 그래서 "스틱은 안 되는데 걸어서는 통과"가 설명된다.

`BP_XRPawn` 에 `CheckFloorRecovery` 함수가 이미 있는 것으로 보아 이 폰은 전에도 비슷한 문제를 겪었다.

단(`SM_RoomB_Platform`) 크기는 못 쟀다. `get_actor_bounds` 가 전부 0 을 돌려줬다(응답 형식 미확인).

## 5. 스펙테이터(프리뷰 창) 구조

### 5.1 미러와 스펙테이터는 다른 그림이다

같은 화면을 다르게 자른 게 아니라 소스가 다르다.

| | 스펙테이터 끔 | 스펙테이터 켬 |
| --- | --- | --- |
| 모드 | `SingleEyeCroppedToFill` (5) | `Texture` (6) |
| 소스 | 헤드셋이 렌더한 **한쪽 눈 버퍼** | **별도 카메라**가 그린 렌더타겟 |
| 원본 크기 | 2752×1536(양눈) → 한 눈 1376×1536 | `RT_VRSpectator` 1920×1080 |
| 비율 | **0.90:1 (세로가 김)** | **16:9** |

헤드셋 미러가 세로로 긴 것은 렌즈 시야 모양 때문이라 못 바꾼다.
스펙테이터의 16:9 는 렌더타겟 설정이라 바꿀 수 있다.

### 5.2 FOV 는 수평 기준이다

`SetFOVAngle` 은 수평 FOV 다. 수직은 화면비에서 따라온다.

| 렌더타겟 | 115° 수평일 때 수직 |
| --- | ---: |
| 1920×1080 (16:9, 현재) | 83° |
| 1920×1440 (4:3) | 99° |
| 1440×1440 (1:1) | 115° |

"좌우는 넓은데 상하가 좁다"는 여기서 온다.

### 5.3 카메라 스냅 — 판정을 두 번 고쳤다

포탈로 방을 옮기면 카메라가 `VInterpTo`(속도 2)로 천천히 날아가 빈 하늘과 떠 있는 담장이 보였다.

**1차(틀림):** `Distance(카메라, 목표) > 500cm` 이면 스냅.
`VInterpTo` 의 뒤처짐은 **속도에 비례**한다(뒤처짐 ≈ 속도 ÷ InterpSpeed).

| 상황 | 속도 | 뒤처짐 |
| --- | ---: | ---: |
| 걷기 | 220 cm/s | 110 cm |
| **비행** | **5000 cm/s** | **2,500 cm** |

비행 중 내내 임계를 넘어 스냅이 매 프레임 걸렸고, 보간이 꺼져 HMD 흔들림이 그대로 나왔다.
사용자가 "화면에서 끊긴다"고 한 게 이것이다.

**2차(채택):** **목표가 한 프레임에 튄 거리** > 1000 cm.

| | 프레임당 목표 이동 |
| --- | ---: |
| 걷기 | 3.1 cm |
| 비행 | 69.4 cm |
| **포탈 (최소, 메인↔B)** | **4,180 cm** |

포탈만 두 자릿수 떨어져 있어 깨끗하게 갈린다.

## 8. 환경 관련

- **MCP 서버는 커맨드라인 플래그로만 뜬다.** `Config/DefaultEditor.ini` 의 `bAutoStartServer=True` 는 읽히지 않는다.
  `UnrealEditor.exe "<uproject>" -ModelContextProtocolStartServer` 로 띄워야 한다.
  플래그 없이 띄웠다가 10분 허비하고, 09-20 로그의 `LogInit: Command Line:` 과 대조해 찾았다.
- `save_assets` 가 `False` 를 돌려주는 것은 대개 **읽기 전용 `*_BuiltData.uasset`** 때문이고, 레벨 자체는 저장돼 있다.
  `git status` 와 파일 mtime 으로 확인할 것.
- **PIE 가 켜진 상태에서 액터를 고치면 `UEDPIE_` 런타임 사본을 건드리게 된다.** PIE 를 끄고 `UEDPIE` 를 걸러낸 뒤 작업할 것.
- LFS 는 **미커밋 변경이 있는 파일의 잠금 해제를 거부**한다. `--force` 가 필요하다.
