## 3. 9/17 — 저장소 등록과 언리얼 반입

### 3.1 자산 번들 생성 (10:37)

`assets/gounsa-yeonsujeon/` 을 명세 19.1 계약대로 만들었다.

| 단계 | 파일 | 크기 | `provenance` |

| ② 현재 (화재 후) | `master/2-current-after-fire.glb` | 34.4 MB | `ai_inferred` |

**토글 방향이 기존 유물과 반대다.** 유물은 손상이 관측이고 복원이 추정인데, 연수전은 **원형이 관측이고 소실이 추정**이다.
기본 표시는 ②이고 토글하면 ①이 같은 자리에 올라온다.

라이선스는 국가유산청 회신으로 **공공누리 제1유형**을 확인했다(9/14). glb 외 사진·영상은 유형 미확인이라 제작 대조 근거로만 쓰고 전시에 넣지 않는다.

> 배경 지형은 파이썬으로 메시를 만들고 **정점 색만** 입힌 것이라 한계가 분명하다. 트라이플래너로 스캔 텍스처를 입혀도 "언덕 모양 판떼기"다.

## 4. 9/18 — 마당 잔디 제거

②(화재 후)의 마당이 합성 모래빛이라 ①의 실제 흙·길·낙엽을 가져오는 작업이다. **네 번 걷어냈다.**

### 4.1 정사영으로 펴서 같은 마당의 흙으로 덮기

① 마당을 위에서 정사영으로 펴고(지면 삼각형 89,297개), 그 안의 잔디 픽셀만 **같은 마당의 흙 타일**로 덮었다.
흙은 마당 한가운데 닳아서 풀이 벗겨진 구역에서 떼왔고, 나무 그늘 같은 큰 음영은 저주파 성분을 곱해 유지했다.

초록 **33.2 % → 2.5 %**. 이 결과를 ②의 두 지면 아틀라스에 **월드 좌표 기준으로 재베이크**했다.

### 4.2 해상도를 올려 다시 (184 → 480 px/m)

첫 판에 뭉개진 사각 블록이 남아 다시 구웠다. 정사영이 8846 × 11573(307 MB)이라 메모리에 못 올려
**디스크 memmap + 1024행 밴드(48 px 겹침)** 로 처리했다.

| | 1차 | 2차 |
| --- | --- | --- |
| 정사영 해상도 | 184 px/m | **480 px/m** |
| 덮은 잔디 텍셀 | — | 15,828,723 (지면의 31.6 %) |
| `site_surviving` 재기록 텍셀 | 4,550,376 | **4,573,687** |
| `terrain_and_gatecap` | 3,444,818 | 3,444,969 |

초석 8개와 기단 윤곽, 흙길이 선명해졌다. 마당 초록 0.61 %.

### 4.3 담장 밑동이 두 번 남았다

지면을 고를 때 **수평면만**(`|n·up| > 0.75`) 잡아서 담장 밑 경사진 지면이 통째로 빠져 있었다.

| 회차 | 기준 완화 | 남아 있던 초록 텍셀 |
| --- | --- | ---: |
| 3차 | 법선 0.75 → **0.40**, 높이 −1.9 → **−1.6** | **612,706** (마스크의 8.93 %) |
| 4차 | 높이 −1.6 → **−1.0** | **892,656** |

3차부터는 정사영 커버리지에 의존하지 않고, 마스크 안의 초록 텍셀을 **명암은 유지하고 색만** 마당 흙색으로 직접 치환했다.
최종본은 `T_Site_NoGrass5` / `T_Terr_NoGrass4` 이고 마스크 내 초록 0.000 %다.

### 4.4 마지막에 남은 초록은 메시가 아니었다

에디터에 여전히 초록이 보였다. 같은 카메라에서 재보니 답이 나왔다.

| | 초록 |
| --- | ---: |
| 기록본(①) + 현재본(②) 둘 다 표시 | **1.064 %** |
| 기록본만 숨김 | **0.047 %** |

**보이는 초록의 96 %가 ① 때문이다.** ①과 ②가 같은 자리에 겹쳐 있고, 대문·담장 밑동에서 ①의 지면이 미세하게 위에 있어 깊이 테스트를 이긴다.
②의 텍스처는 이미 깨끗하다. VR 프리뷰로 실행하면 `BP_StageToggle` 이 한쪽을 숨기므로 **에디터에서만 보이는 현상**이다.
