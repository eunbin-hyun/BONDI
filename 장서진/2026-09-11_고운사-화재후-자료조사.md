### 왜 중요한가 — 방위가 미확정이다

드론 부감 사진에 **북침·스케일바·유구 명칭이 전혀 없다.** '남측/동남쪽' 같은 방위는 전부 판독자의 추론이다.
VR 토글은 원형 glb와 '현재'를 **회전까지 정합**시켜야 하는데 우리는 드론이 어느 방향에서 찍었는지 모른다.
**25 cm 정사영상의 담장 사각 윤곽 하나로 이 문제가 끝난다.** 초석은 원형 glb에서 나온다.

## 4. 소실/잔존 분할 방안 — 우선순위 순

### (a) 기존 AI 모델 편집·사용 — 최우선

#### a-0. 모든 AI 방안의 공통 0단계 (건너뛸 수 없음)

원형 glb는 **완전 통합 삼각형 수프**다. `POSITION 2,071,830 = 690,610 × 3`으로 **정점 공유가 전무**하고,
메시·머티리얼·텍스처가 각 1개, NORMAL·COLOR_0 없음.

→ **face adjacency·connected components·PartField의 agglomerative clustering·SUMS의 manifold 요구가
전처리 없이는 전부 무너진다.** 좌표 해시 정점 병합 → 비다양체 수리 → 인접성 재구성 → 법선 계산 →
UV·face 매핑 확정 → 담장 밖 지형 바운딩 절단. trimesh/pymeshlab/Open3D, GPU 불필요, **0.5~1일.**

좋은 소식: 실측 미터 스케일이 정확히 맞다(18.43 × 24.11 m, Y-up).

#### a-1. GeoSAM2 — 1순위

메시를 12뷰(color/depth/normal) 렌더 → 한 뷰에 클릭/마스크 프롬프트 → 전 뷰 전파 → 역투영해
**per-face 3D 파트 라벨** 출력.

| 왜 1순위 | 위험 |
| --- | --- |
| **`GEOSAM2_BUILD_CUDA=0`으로 nvcc 없이 동작** — 이 노트북 최대 제약을 문서로 우회하는 유일한 최신 모델 | 학습 도메인이 오브젝트 파트 — 18.4×24.1 m 건물+지면+담장은 검증 범위 밖 |
| 출력이 per-face라 **690,610 삼각형을 다운샘플 없이 그대로 자른다** (Point-SAM 100k·PartField 100k점·SAMPart3D 15k점의 정보 손실이 없다) | depth/normal 헤드리스 렌더 미검증 (Workbench는 성공했지만 패스가 다르다) |
| **Apache-2.0** — 배포 자유 | 메시별 `--postprocess-pa` 튜닝 필요 |
| 클릭 프롬프트라 **사진 근거로 판단한 경계를 그대로 지정**할 수 있다 | "텍스처 안 쓰고 normal 기반"은 README에 없는 가설 — 파일럿에서 확인 |

설치·파일럿 **1~2일.** WSL Ubuntu-22.04 보유, Blender 5.2 로컬 확인.

#### a-2. SUMS (TU Delft) — 2순위

대규모 야외 **텍스처 메시를 직접** 입력(텍스처 PLY + JPG — 우리 데이터와 동일 형태).
**Windows 사전 빌드 exe, GPU 불필요, 0.5~1일.**

클래스가 Terrain/Vegetation/Building/Water/Vehicle/Boat 6개뿐이라 **목조/석재는 못 가른다.**
그러나 우리가 색·높이로 실패한 **'건물 vs 지면 vs 식생' 분리는 바로 해준다** — 문제의 절반.
`Mesh_feature_extraction` 모드가 과분할 초안을 만들어 a-7의 입력이 된다.

위험: manifold 필수(a-0에서 수리 실패 시 탈락) / **GPL-3.0 → 우리 코드에 링크 금지. 별도 프로세스로 PLY만 주고받을 것.**

#### a-3. SAM 3 (+SAM 2) + 자체 멀티뷰 역투영 — 3순위

텍스트 프롬프트(`wooden building`, `stone platform`, `roof tiles`)로 **의미를 지정할 수 있는 유일한 경로.**
나머지는 전부 무명(class-agnostic) 파트 조각만 준다. 단 역투영·라벨 융합을 우리가 짜야 함, **3~5일.**
SAM 3 체크포인트는 승인제 + 커스텀 라이선스(Trade Controls 조항) → 배포 조건 검토 필요. 클릭·박스로 충분하면 **SAM 2(Apache-2.0)**가 안전.

#### a-4 ~ a-6. 환경·도메인 장벽

- **Point-SAM** (MIT, 10만점 초과 명시 지원, KITTI360 야외 평가) — `torkit3d`·`apex`를 `FORCE_CUDA=1`로 빌드해야 해 **nvcc 필수 → 이 PC에서 막힌다.** 데모 권장 상한 10만 면, 우리는 69만.
- **PartField** (`.glb` 직접 입력, 셰이프당 10초) — **NVIDIA License 비상업 연구·교육 전용** / 논문 Limitations가 **"object-scale only"** 명기 / 100,000점 샘플링으로 서까래·공포 소실 / face centroid 인접행렬 clustering이라 a-0 없이 실패.
- **Sonata / PTv3** (Apache-2.0) — 라벨 없이 점별 의미 특징 → 클러스터링. **색·높이 실패를 정면으로 우회하는 유일한 축**이지만 사전학습이 실내 중심이고 점군화·클러스터 수 결정이 필요. 공개 체크포인트에 '목조 구조부' 라벨 없음. **일정 안에서는 과투자.**

#### a-7. 반자동 확정 흐름 — 실제로 방어 가능한 구성

**완전 자동 분할은 목표가 아니다.** 어떤 모델도 "여기까지 타서 없어졌다"를 알려주지 않는다 —
전부 클래스 무관 파트 분할이거나 도메인이 어긋난 의미 분할이다.
**근거는 모델이 아니라 현장 사진·공식 기록에서 오고, AI의 역할은 그 판단을 69만 삼각형 위에 깔끔한 경계로 옮기는 것뿐이다.**

> GeoSAM2(또는 SUMS) per-face 과분할 초안 → **사진 근거로 사람이 조각 선택·확정**
> → 어느 face를 왜 제거했는지 근거와 함께 기록

어노테이션 도구: TU Delft **3D_Urban_Mesh_Annotator**(GPL-3.0, ascii PLY, non-manifold 미지원, 2021년 이후 방치).

### (c) 현장 사진으로 3D 생성 — 현재 자료로는 불가. **단 판정 보류**

실무 기준은 오브젝트 **100~200장**, 인접 프레임 중첩 **70~80%**, 특징 하나가 3~5장에 출현.
우리는 **고유 5장**이고 카메라·날짜·조명이 전부 다르며 촬영 위치가 한쪽에 몰린다 —
**SfM이 요구하는 co-visibility가 구조적으로 없다.** 간극이 두 자릿수다.

소수뷰 모델(VGGT / MapAnything / Fast3R / MASt3R)은 10장 미만에서 COLMAP 대비 완전성이 좋지만
**어느 것도 메시를 출력하지 않는다.** 라이선스: **VGGT-1B-Commercial**·**map-anything-apache**(metric 스케일 직접 출력)는 깨끗,
**MASt3R는 CC BY-NC-SA** → 전시 불가, **Hunyuan3D는 한국 제외**. `vggt-low-vram` 포크가 8GB에서 150장 처리 — 이 PC의 유일한 경로.

> **판정 보류 이유: 최상덕TV 11:08(2026-08) 항공 프레임을 아직 추출하지 않았다.**
> 연수전 담장 구획을 궤도로 돌았다면 수백 프레임이 나온다. **프레임 추출 전에 '불가'를 확정하면 안 된다.**

**건축물 규모 생성형은 배제.** TRELLIS는 SLAT 64³ 격자로 "reasonably good 3D buildings … but fails to capture
realistic building geometries" — 18.4×24.1 m 터 전체를 넣으면 안 된다. 이 저장소 자체 평가도 같은 방향
(SF3D·SPAR3D가 유물 1장에서 깊이/폭 0.35~0.5의 납작한 카드 생성, TripoSR Chamfer 10.1 mm보다 나빴음).

**다만 재활용 지점은 명확하다** — 연수전에 남은 것은 **터와 석재, 즉 오브젝트 스케일**이다.
**TRELLIS.2 512는 이 PC 8GB에서 이미 검증됐다**(45초, 피크 3.2~3.6 GB, MIT) →
남은 석재 부재 개별 생성, 불탄 목재 잔해, 옹기·안내판 소품에 쓰는 것이 취지에 맞는 재활용이다.

### (d) 위성·거리뷰 — 방위·평면 정합 확정용으로 한정

25 cm급 정사영상(또는 카카오 스카이뷰)의 **담장 사각 윤곽**을 원형 glb 바운딩과 정합시켜
**회전(방위)과 원점을 확정.** 난이도 낮음 · **반일~1일**(획득 경로만 열리면).
**적합도 높다 — 아무도 안 했고 지금 미해결인 방위 문제를 단독으로 해결한다.**

### (f) 블렌더 MCP — 검증용으로만

`render.py`·`rsplit.py`로 **PNG 12장이 실제 출력됐다.** 용도는 ⓐ 감산 결과 눈 검증 ⓑ GeoSAM2용 12뷰 렌더
ⓒ 정점 병합·비다양체 수리 ⓓ decimate/LOD. **모델링 판단을 여기서 하면 근거 없는 형상이 들어간다 — 렌더·전처리·검증에만.**
depth/normal 패스는 Workbench가 아니라 Cycles CPU 또는 Compositor 경로가 필요할 수 있다(미검증).
