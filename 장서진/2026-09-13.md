## 1. 감산 — 상자 2개로 끝났다

### 1.1 풋프린트를 평면도로 읽음

5 cm 격자에 셀별 최대 '지면 위 높이'를 넣어 평면도를 그렸더니 배치가 한눈에 나왔다.

| 요소 | XZ 범위 | 크기 |
| --- | --- | --- |
| 연수전 지붕(처마 포함) | X −4.8 ~ 3.9 / Z −6.6 ~ 2.1 | 8.7 × 8.7 m |
| 문간채 지붕 | X −3.5 ~ 2.9 / Z 5.6 ~ 10.4 | 6.3 × 4.6 m |
| 담장 | 대지 테두리 | — |

> 처음엔 `h > 3.0 m`인 면의 XZ 바운딩으로 풋프린트를 잡으려 했는데 **대지 전체로 퍼졌다.** 식생과 문간채가 같이 잡혀서다. 평면도를 그려 눈으로 읽는 쪽이 빨랐다.

### 1.2 절단 결과

```
연수전 : X -4.8~3.9 , Z -6.6~2.1 , centroid Y > -1.30  →  275,095 tri / 488.5 m² 제거
문간채 : X -3.5~2.9 , Z  5.6~10.4, centroid Y > -2.88  →   98,378 tri / 248.7 m² 제거
합계 373,473 제거 / 317,137 잔존 (48.0%)
```

**면 중심(centroid) 기준일 때만 이 수치가 나온다.** 정점 any/all 기준은 373,935 / 373,036으로 어긋난다.

담장 4면·석축 계단·마당·석축은 그대로 남았다. 남은 건 **사각 구멍 두 개** — 마루에 가려 기단 상면이 스캔되지 않은 자리다.

### 1.3 이 감산이 맞다는 독립 검증

SAM2 멀티뷰 역투영으로 좌표 상자를 검증했다(방법 E).

| 지표 | 값 |
| --- | --- |
| 풋프린트 IoU | **0.9655** (연수전) / 0.9362 (문간채) |
| 가시면 per-face precision | **0.9862** |
| per-face recall | 0.60 |
| 독립 추정 절단 높이 | −1.283 / −2.800 |

낮은 recall은 불일치가 아니라 **가시성** 문제다 — A-only 면 147,670개 중 82%가 어느 뷰에서도 안 보이는 지붕 밑 기둥·마루다. 마젠타 배경 관통 픽셀 카운트(원본 2,721 px → 결과 2,730 px)가 '구멍 없음'의 객관 지표가 됐다.

## 2. 초석 격자 역산 — 사진 없이 나온다

난간 위 높이대(마루 위 1.2~2.0 m)에서 수직면만 골라 XZ로 투영하고 연결성분을 잡았다.

```
X 기둥열 :  -3.23    -1.78     0.88     2.34      (간격 1.45 / 2.66 / 1.46 m)
Z 기둥열 :  -4.90    -3.43    -1.08     0.39      (간격 1.47 / 2.35 / 1.47 m)
```

**4×4 = 16기.** 기둥 직경 0.32~0.40 m. 양끝 1.45 m 퇴칸 + 가운데 어칸 2.66 × 2.35 m
= **정면 3칸 × 측면 3칸에 사면 퇴를 두른 平面**. 공식 기술의 *"回자형 평면, 사면 각각 퇴 설치·개방, 헌함 둘림"*과 정확히 맞는다. 드론 사진 판독치 "약 17기"와도 일치.

건물 본체 5.6 × 5.3 m / 지붕 8.7 × 8.7 m → **처마 내민 길이 약 1.55 m**도 부수적으로 확정.

> 낮은 높이대(마루 위 0.15~0.9 m)에서는 **난간이 기둥을 연결해 버려** 덩어리 2개로 뭉쳤다. 헌함 위로 올라가야 기둥이 분리된다.

문간채 초석은 B·C·F가 독립으로 역산해 0.03 m 이내로 수렴 — 4×2 격자 X {−2.63, −1.16, 0.61, 2.10} × Z {6.88, 8.91}.

## 3. 6개 방법 비교

| 방법 | 점수 | 결과 |
| --- | --- | --- |
| **F-하이브리드** | **21.0** | 드론 사진 호모그래피 정사투영. 유일하게 사진처럼 읽힘 |
| C-Blender bpy | 19.5 | 기하 가장 정직(캡이 림 안 안착). 텍스처는 돗자리, 초석은 녹색 이끼 |
| A-순수 numpy | 18.0 | 외부 의존 0, 빌드 1초. 결과는 가장 인공적 |
| E-SAM2 | 17.5 | 메시보다 검증 장치로 값짐 |
| B-trimesh | 17.0 | 가장 값진 건 반증 |
| D-TRELLIS.2 | 17.0 | 색 매칭 최고, 형상 실패 |

**목조 제거는 6개 전부 만점.** 제거량이 373,473으로 정확히 일치했고 그루터기·처마 조각이 하나도 안 남았다. 변별이 안 되는 항목이다.

### 3.1 B의 반증 — `fill_holes()`는 원리적으로 못 쓴다

| 설정 | 결과 |
| --- | --- |
| `use_fan=False` | 321정점 루프에 손도 못 댐. **0.001 m² / 41 m²** |
| `use_fan=True` | 스캔 바깥 테두리(9,934정점)를 메우려다 길이 10 m 삼각형으로 부지를 가로질러 **1,002.9 m²** 생성 |

**한 겹 스캔 셸에서는 "구멍"과 "메시 바깥 테두리"가 위상적으로 구별되지 않는다.**
→ 구멍을 위상이 아니라 **기하(2D 점유격자 또는 절단 경계 루프)로 정의**해야 한다. 이 한 문장이 나머지 다섯의 설계를 정당화한다.

덤으로 B가 잡아낸 것: 기단 상면 Y≈−1.22의 대형 평탄면이 **기단이 아니라 우물마루**였다(§5 참조).

### 3.2 D의 실측 — TRELLIS.2는 되지만 입력이 문제

8 GB에서 1024 cascade가 **94.6 s / 4,382 MB**, VRAM 정상 반납. 그러나 **드론 부감으로는 초석 생성 불가** — 초석 1기가 16~24 px라 납작한 원반이 나온다. 출력도 닫힌 솔리드가 아닌 열린 셸이고 깊이가 1.00:0.61로 눌려 있어 높이장 재샘플링이 필요했다. **지상 사진이 있어야 쓸 수 있다.**

### 3.3 C의 유용한 실패 보고

`grid_fill`은 에지 321개(홀수)라 0면, `holes_fill`은 소구멍 236곳 중 62면만. 성공한 조합은
`extrude_edge_only`로 림 생성 → `triangle_fill` → 격리 bmesh에서 `subdivide + beautify_fill`, 열린 림 0개.

치명적 한계: **tex.jpg가 삼각형 1개당 차트 1개인 아틀라스**라 평면 UV 투영이 원리적으로 불가능하다. 그래서 실제 스캔 삼각형의 UV를 이식했더니 돗자리 무늬가 됐다.

## 5. 내가 준 수치가 틀렸다 — 기단 상면 높이

`Y = -1.27`을 기단 상면이라고 6개 방법에 배포했는데 **그건 우물마루였다.**

수직 단면(|X| < 0.15 m)을 직접 그려 읽은 값:

| 요소 | Y |
| --- | --- |
| 마당(기단 바깥) | **−1.45** (−1.35~−1.50 완만한 경사) |
| 기단/마루 상면 평탄면 | **−1.22** |
| 기단 높이(마당 대비) | 약 **0.25 m** |
| 문간채 바닥 | −2.80 ~ −2.85 |

기둥 격자 안쪽 수평면은 −1.22(우물마루), 바깥 고리는 −1.53으로 나왔는데 **후자는 마당을 포함해서 생긴 오차**였다. 에이전트 3개의 독립 측정(−1.32 / −1.324 / −1.386)도 이 사이에 있다.

그 결과 A·D·F는 **캡이 떠서 '쟁반'처럼 보인다.** F 근접 렌더에서 사방 10~20 cm 수직 테두리가 보이고 우측으로 넘친다.

**해법**: 캡 윤곽을 사각형으로 만들지 말고 **절단으로 생긴 열린 경계 루프를 그대로 캡 외곽으로** 쓴다. 기단 실제 형상과 자동으로 일치하고 넘치지 않는다. 최종본 3전략(R1 rimloop / R2 shrinkwrap / R3 photofirst)으로 검증 중.
