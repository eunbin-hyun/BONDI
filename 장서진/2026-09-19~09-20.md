## 1. 스트리밍 — 11 fps 에서 71 fps

시연을 이틀 앞두고 VR 화면이 초당 11 프레임이었다. 같은 씬·같은 헤드셋에서 잰 값이다.

| | 이전 | 이후 |
| --- | ---: | ---: |
| Client FPS | 11 | **71** (72 Hz 상한) |
| Total latency | 467 ms | **59 ms** |
| game_time (렌더) | 41.3 ms | **2.69 ms** |
| packet loss | 다수 | **0** |

비교 기준값은 김소영이 9/17 에 측정해둔 것을 썼다.

### 1.1 두 가지 방법으로 따로 셌다

대시보드 Statistics 값만 믿지 않고, ALVR `session_log.txt` 의 프레임 이벤트 **69,779 건(16분 18초)** 을 직접 집계했다.
두 결과가 **71.4 / 71** 로 일치했다. 로그에는 `[GRAPH]` / `[STATS]` 마커에 타임스탬프만 있고 수치 페이로드가 없어서,
숫자를 읽는 대신 **이벤트 간 간격의 중앙값**(14.0 ms)을 냈다.

> 71.4 는 최댓값이 아니라 중앙 간격의 역수다. 상한이 72 Hz 이므로 **사실상 프레임을 하나도 안 흘리고 있다**는 뜻이다.

### 1.2 효과는 거의 전부 ALVR 쪽에서 나왔다

| 설정 | 값 | 왜 |
| --- | --- | --- |
| `preferred_codec` | HEVC | H.264 대비 같은 화질을 절반 비트레이트로 |
| `bitrate.mode` | ConstantMbps 15 | Adaptive 가 요동치며 프레임 큐를 쌓았다 |
| `transcoding_view_resolution` / `emulated_headset_view_resolution` | 1400 | 원본 2752 를 이 GPU 인코더가 못 따라간다 |
| `entropy_coding` | CABAC | CAVLC 보다 압축률이 높다 |
| `foveated_encoding` | 0.4 / 0.35 | 시야 주변부 비트 절약 |
| `position_recentering_mode` | Local, view_height 1.6 | Local **floor** 면 플레이어가 공중에 뜬다 |

문제는 **이 설정들이 저장소에 없다**는 것이다. 다른 PC·다른 헤드셋에서 그대로 재현할 수 없으니,
절차를 `docs/vr-streaming-setup.md` 로 남기고 `session.json` 을 직접 고치는 `tools/alvr/apply_alvr_settings.py` 를 함께 뒀다.

**스크립트는 대시보드가 켜져 있으면 실행을 거부한다.** 대시보드가 종료할 때 자기 메모리의 설정으로 `session.json` 을
덮어쓰기 때문이다. 이걸 모르고 작업하다 설정이 두 번 되돌아갔다.

### 1.3 ini 에 박은 cvar 하나는 효과가 없었다

`DefaultEngine.ini` 의 `xr.SecondaryScreenPercentage.HMDRenderTarget=75` 는 **작동하지 않는다.**
PIE 가 시작될 때마다 100 으로 되돌아가는 것을 에디터에서 cvar 을 직접 읽어 확인했다.
해상도를 실제로 낮춘 것은 ALVR 의 `emulated_headset_view_resolution` 이다.
줄은 지우지 않고 "효과 없음" 을 주석으로 적어 남겼다 — 지우면 다음 사람이 또 넣는다.

### 1.4 `r.ScreenPercentage 75` 는 음의 결과였다 (기록용)

렌더 해상도를 더 낮추면 여유가 생기리라 보고 75 로 내려 재봤다.

| | 100 | 75 |
| --- | ---: | ---: |
| Client FPS | 71 | 71 |
| Total latency | 59 ms | 54 ms |
| **비트레이트** | 3.5 Mbps | **1.3 Mbps** |
| **Encoder latency** | 3.64 ms | **8.80 / 9.18 ms** |

**프레임은 이미 상한에 붙어 있어서 더 얻을 것이 없었고**, 비트레이트만 3분의 1로 떨어져 화질을 손해봤다.
인코더 지연이 오히려 오른 것은 두 번 재현됐으므로 잡음이 아니다. 렌더가 예산 13.9 ms 중 2.69 ms 만 쓰고 있으니
방향은 **해상도를 낮추는 쪽이 아니라 올리는 쪽**이다. 다만 인코딩·네트워크 부담은 현장 망에 좌우되므로 시연장에서 다시 잰다.

같이 한 것: `T_Gounsa_OutBare` / `T_Gounsa_Platform` 8192 → **MaxTextureSize 2048**.
VR 에서 이 크기는 스트리밍 풀만 차지하고 화면에서 구분되지 않는다.

## 2. 줄 당김 토글 — 증상 하나, 원인 셋

좌대 앞 버튼 대신 마당에 걸린 줄을 당겼다 놓으면 연수전이 현재본 ↔ 전소 전 원형으로 바뀐다.
"천천히 하면 잡힐 때도 있고 안 잡힐 때도 있다" 는 증상 하나를 쫓았는데 원인이 세 개였다.

### 2.1 잡기 판정 — 반경 안에 있기만 하면 잡은 것으로 봤다

처음에는 검지 끝이 반경 36 cm 안에 있으면 잡았다고 판정했다.
그러니 **손이 줄 옆을 스치며 내려가기만 해도 줄이 당겨졌다.**

| 판정 | 기준 |
| --- | --- |
| 핀치 | 엄지 끝(keys[5]) ↔ 검지 끝(keys[10]) < **5 cm** |
| 주먹 | 검지 끝(keys[10]) ↔ 손바닥(keys[0]) < **8 cm** |

둘 중 하나 + 반경 안, 을 모두 만족해야 잡힌 것으로 본다.

### 2.2 기준 높이가 들어온 첫 프레임에 박혔다

당김 깊이를 `잡은 순간의 손 높이 − 지금 손 높이` 로 쟀다. 그런데 당기고 나서 손을 다시 올릴 때
**낮은 위치에서 기준이 박혀** 다음 당김이 0 으로 측정됐다. 기준을 고정하지 않고
**잡고 있는 동안 손이 도달한 가장 높은 지점으로 계속 갱신**하도록 바꿨다.

```text
GrabStartHandZ = Max(GrabStartHandZ, 지금 손 높이)
trav           = Min( Clamp(GrabStartHandZ − 지금 손 높이, 0, 15), BestTravel + 6 )
```

### 2.3 한 프레임짜리 손 좌표 튐이 최댓값에 박제됐다

추적 로그를 보니 실제 당김은 4 cm 를 넘지 않는데 `PeakTravel` 만 15 로 차 있는 경우가 있었다.
핸드 트래킹이 한 프레임 튄 것이 최댓값에 박힌 것이다. **한 프레임에 늘 수 있는 양을 6 cm 로 묶어**,
15 cm 에 닿으려면 3 프레임 연속 깊게 읽히도록 했다.

발동은 **놓는 순간**이다. 잡고 있는 동안 도달한 최대 깊이가 15 cm 를 넘었고 손을 떼면 그때 토글한다.

### 2.4 고친 뒤의 추적 로그

```text
69.20s  핀치 10.1 cm   HandNear = false
69.52s  핀치  3.6 cm   잡힘, PeakTravel 0.7
70.24s                 PeakTravel 14.7
70.56s                 PeakTravel 15      (손이 34 cm 내려감)
70.89s  핀치  8.4 cm   놓음
71.22s                 ShowRecord = true,  ShowRestored = true
```

### 2.5 줄 메시는 직접 만들었다

Fab 스캔 에셋은 평면 스캔이라 **끝이 풀린 형태를 옮길 수 없었다.** 절차적으로 생성했다.

| | |
| --- | --- |
| 길이 | 14.00 m, 3로브 꼬임, 피치 22 cm |
| 버텍스 / 삼각형 | 19,061 / 32,012 |
| 끝 처리 | 아래 2.2 cm 불규칙하게 깎고 표면 섬유 170 + 늘어진 올 18 = **188 가닥** |

OBJ 로 넘겼더니 언리얼이 탄젠트를 직접 만들면서 본체가 검게 렌더돼,

## 3. 눈높이 — 리센터 불연속을 상쇄한다

스폰 직후 관람자의 눈높이가 **바닥 위 300 cm** 였다. 메인 홀 천장이 320 cm 라 천장을 뚫고 하늘이 보인다.

| 시점 | 눈높이 |
| --- | ---: |
| 스폰 직후 (폰은 바닥 z=0 에 정확히 있음) | **300 cm** |
| 메타 핀치로 리센터 한 번 뒤 | **155 cm** |

ALVR 의 시야높이 1.6 m 설정은 맞게 걸려 있으나 **리센터를 한 번 해야 적용된다.**
세션 시작 시점에는 헤드셋 자체 원점이 쓰인다.

시도한 것과 결과:

| 방법 | 결과 |
| --- | --- |
| 스폰 Z 를 상수만큼 깎기 | **실패.** 리센터 전후로 값이 145 cm 달라지는데 상수는 한쪽만 맞춘다 — 전에는 뜨고 후에는 바닥에 묻혔다 |
| `ResetOrientationandPosition` 을 BeginPlay 에 | **무효.** 86 초 동안 눈높이가 300 cm 그대로였다 |
| **불연속 상쇄** | 채택 |

채택한 방식은 이렇다. 처음 한 번 눈높이를 `바닥 + EyeHeight` 에 맞추고, 그 뒤로는
**눈높이가 한 프레임에 30 cm 이상 튀면 그만큼 폰을 반대로 옮긴다.**
리센터는 한 프레임에 145 cm 가 튀고 사람이 앉거나 서는 것은 프레임당 몇 cm 라,
**리센터만 걸러지고 실제 자세 변화는 그대로 남는다.**

미러 창을 전체 시야로 바꾸는 `vr.SpectatorScreenMode 1` 도 여기서 실행한다.
이건 cvar 이 아니라 **콘솔 커맨드**라 ini 에 박을 수 없다.

> 아직 끝나지 않았다. 라이브 추적에서 191~194 cm 가 우세하게 나와 `EyeHeight` 를 160 → 130 으로 내렸는데 **아직 못 써봤다.**
> 기준선 자체가 세션마다 164~167 로도 흔들린다. 티켓은 진행 중으로 둔다.

## 4. 정보 패널 — UMG 에서 걸린 것들

기존 유물 패널(`WBP_ArtifactInfo_Damaged`)과 같은 구성으로 두 장(현재 / 원형)을 만들었다.
제목 · 근거 · 본문 · 출처 · 힌트 다섯 슬롯에 Border + VerticalBox.

### 4.1 네 번 헛짚었다

| 증상 | 내가 고친 것 | 실제 원인 |
| --- | --- | --- |
| 투명도가 안 먹는다 | `TintColorAndOpacity` (글자까지 흐려진다) | **Border 의 `BrushColor` 알파** |
| 그래도 안 먹는다 | — | WidgetComponent `BlendMode` 기본값이 **`Masked`** 라 알파가 0/1 로 뭉개진다. `Transparent` 로 |
| 폭을 넓혔는데 줄바꿈이 그대로 | 위젯 폭 | **`WrapTextAt` 이 원본 700 폭 시절의 680 에 얼어 있었다** |
| 아랫줄이 잘린다 (3회 연속) | 줄 높이 계수를 추정해 고정 높이 | **`bDrawAtDesiredSize = true`** — CSS `height: auto` 와 같다 |

마지막 건은 내가 세 번 연속 틀렸다. 사용자가 "css 처럼 height 자동 계산하는 건 안 되냐" 고 물어서 찾았다.
**폭만 `WrapTextAt` 으로 정하고 높이는 엔진이 잡게 한다.**

최종: `WrapTextAt` 1096, `BlendMode` Transparent, `bIsTwoSided` true, `BrushColor` 알파 0.62,
글자 그림자 오프셋 (3,3) 검정 알파 1.0, `RelativeScale3D` 0.09, 관람자 쪽으로 40° 틀었다.

### 4.2 문안은 지어내지 않았다

연혁은 국가유산청 **건축문화유산분과 회의자료** 원문에서만 가져왔다.

- "고종의 기로소 입소를 기념하는 유교건축 형식인 사당형식"
- "연수전은 조선 후기 왕실의 어첩(御帖)을 봉안했던 곳"
- "回자형 평면 … 사면에 각각 퇴를 설치하여 개방하고 헌함을 두르고 있는"

건립 연도는 이 자료들에 없어 **쓰지 않았다.** 지정번호도 쓰지 않는다 (2021년 제도 폐지).
지상 사진·언론사 사진은 공공누리 유형을 확인받지 못해 제작 대조에만 쓰고 전시에는 넣지 않는다.

**출처는 두 장 모두에 넣었다.** 기본 표시가 현재본이라 원형에만 넣으면 줄을 당기지 않은 관람자는 출처를 보지 못하고,
현재본은 원형 스캔의 파생물이라 공공누리 제1유형 출처 표시 의무가 그대로 따라온다.

연수전은 기존 유물과 **관측·추정 방향이 반대**다. 유물은 손상이 관측이고 복원이 추정인데,
연수전은 3D 기록화가 남아 있어 **원형이 관측이고 화재 후가 추정**이다.
그래서 추정 고지는 현재 패널의 근거 줄에만 둔다 (NFR-ETH-003).

## 5. 두 번 이상 걸린 함정

### 5.1 인스턴스 편집 가능 변수는 CDO 기본값을 안 물려받는다

블루프린트 변수를 `Instance Editable` 로 만들면, **이미 레벨에 배치된 액터는 그 값이 0 에 얼어붙는다.**
나중에 CDO 기본값을 바꿔도 반영되지 않는다. 같은 걸로 두 번 당했다.

| 변수 | 증상 |
| --- | --- |
| `LateralLimit` = 0 | 버튼이 안 눌렸다 |
| `PinchDist` = 0 | "분명 주먹 쥐었는데 안 잡힌다" — 핀치 판정이 영원히 거짓 |

### 5.2 레벨 스트리밍 좌표와 이름 충돌

`L_Room_C` 는 `L_Museum` 에 **(+5000, +6000)** 오프셋으로 스트리밍된다.
같은 액터가 **어느 레벨을 열었느냐에 따라 다른 좌표로 읽힌다.**
로컬 좌표 −45 와 합성 좌표 4955 를 비교해 "패널이 엉뚱한 데 있다" 고 잘못 경보를 울렸다.

거기에 `Actor_1` 이라는 이름이 `L_Room_B` 와 `L_Room_C` 양쪽에 있다.
`load_level` 은 **이전 월드의 액터가 사라지기 전에 반환**하므로, 이름만 보고 잡으면 다른 방의 액터를 건드린다.
실제로 Room B 패널을 한 번 움직였다 (저장 전이라 리로드로 폐기됨).

> **이름으로 액터를 찾지 말고 소속 레벨 + 컴포넌트 구성으로 식별한다.**

### 5.3 멈춘 값을 실측으로 읽었다

헤드셋을 벗어 바닥에 둔 상태에서 카메라 z 가 같은 값을 21번 반복하는 것을 보고
"핀치조차 고정 높이를 안 준다" 고 결론냈다.
그 전에도 연결이 끊긴 상태의 236.6 을 실측으로 믿고 스폰 Z 를 −76.6 보정했다가 사용자가 바닥에 묻혔다.
**같은 실수를 두 번 했다. 값이 안 변하면 먼저 살아 있는 값인지 확인한다.**

### 5.4 편집기 도구 쪽

- 이 빌드의 `write_graph_dsl` 은 **exec 링크를 만들지 않는다.** 노드와 데이터 링크만 생기고 조용히 성공한다.
  `create_node` / `connect_pins` 만 쓴다.
- 만든 노드의 타입 ID 와 읽히는 타입 ID 가 다르다. `유틸리티|연산자|작음(<)` 으로 만들면
  `수학|플로트|float<float` 로 읽히는데 **이건 생성 불가 ID** 다.
- 와일드카드 핀은 타입이 정해지기 전까지 **리터럴을 거부한다.**
- float 용 `Abs` 노드가 없다. 비교 두 개 + OR 로 만든다.
- 위젯 컴포넌트는 **에디터 뷰포트 캡처에 안 나온다.** 런타임에만 보인다 (Room B 기존 패널로 대조 확인).

### 5.5 셸·git

- `git switch -f dev` 가 작업 트리를 56 커밋 전 상태로 되돌렸다.
  막고 있던 미추적 파일 21개를 옮겨 pull 을 마치고 전부 바이트 동일하게 복구했다.
- `a | tail && b` — 파이프라인의 종료 상태는 **`tail` 의 것**이라 `&&` 가 앞 명령을 지켜주지 않는다.
  `git switch` 가 실패했는데 `git pull` 이 실행됐다.
- `MSYS_NO_PATHCONV=1` 을 켜면 네이티브 git 에 넘기는 `/tmp` 경로가 깨진다.
- PowerShell 5.1 은 BOM 없는 `.ps1` 을 ANSI 로 읽어 **한글이 들어간 스크립트 파일은 파싱 에러**가 난다.
  인라인 명령은 괜찮다.
