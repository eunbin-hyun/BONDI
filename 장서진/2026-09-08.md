## 2. PoC 11건 회귀

기준선: PoC 보고서의 `refinish_target_Lab`(8비트 → a·b − 128)과 `protected_dark_ratio`. 자산은 WSL `~/temp`에서 `C:\ai\poc_inputs\`로 복사(MTL 절대경로 → 상대경로 재작성). 8K 텍스처 1건 3~6분.

| 유물 | 재질 | 목표 Δ(v1.1 vs PoC) | 보호 v1.1 / PoC | 판정 |
| --- | --- | --- | --- | --- |
| duk006294 철화백자 | whiteware | 0.4 | 59.5 % / 59.3 % | 일치 (고정 임계 필요) |
| don000498 ①②, gae000001 ①② 청자 | celadon | 0.1 ~ 0.5 | 0.1~0.6 % / 0.0~0.6 % | 일치 |
| ssu022891 빗살무늬토기 | earthenware | 0.8 | 균열 3.8 % / 6.6 % | 목표 일치, 균열은 채움 방식이 달라 참고만 |
| bon004740 금 | gold | 7.0 → **1.3** | 5.0 % / — | 재질별 임계 후 일치 |
| bon009435 금동 관모 | gilt_bronze | 7.4 → **0.5** | 19.1 % / 20.4 % | 재질별 임계 후 일치 |
| duk003312, bon002789 금동 | gilt_bronze | 9.8, 11.8 | 34 % / — | 건전부가 프리셋에서 27·35 → 프리셋. PoC는 녹청 혼합 |
| lkh000002 청동 | bronze | 27.3 | 22 % / — | 건전부 거리 36 → 프리셋. PoC 목표 (5.7, 27.1)은 녹청 쪽 |

**배운 것.**

- PoC 결과를 재현하려면 코드가 아니라 **유물별 설정**(`batch_run.py`)을 먼저 봐야 했다. 철화백자 6.4 %p 차이를 "4K 축소·페더링 탓"으로 추정했는데 틀렸고, 실제는 고정 임계 하나였다.
- "건전부 상위 15 %"는 부식된 청동에서는 밝은 녹청을 잡는다. PoC는 그걸 항상 0.38 섞었기 때문에 청동 목표색이 녹색으로 끌려갔다(청동검에서 ΔE 49). v1의 타당성 관문이 이를 막는데, 금·금동은 녹청으로 변하지 않으므로 임계를 넓혀도(25) 안전하고 PoC 회귀에서 실제 원표면이 15.2·20.1 떨어져 있었다. 그래서 단일 15가 아니라 재질별로 갔다.
- 재질별 임계와 "전체 25"는 현재 16건에서 결과가 같다. 차이는 앞으로 들어올, 건전부가 15~25 떨어진 청동·철에서만 난다. 데이터 없이 넣은 안전장치라는 점을 설계 문서에 적어 두었다.

## 3. 뷰어 — `out_restore/viewer.html`

PoC 11건을 좌(원본)·우(복원)로 같은 카메라에서 돌려 본다. 조명 끄기(텍스처 원색), 스페이스로 원본/복원 전환. 8K GLB는 브라우저에 무거워 `make_viewer_copies.py`로 2K 축소 복사본(`out_restore/viewer/`, 4~16 MB)을 만든다. 메시는 동일(회귀는 `--no-smooth`).

```bash
python -m http.server 8765   # 저장소 루트에서
# http://localhost:8765/ai/3d-to-3d-color/out_restore/viewer.html
```
