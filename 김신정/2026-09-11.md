# 2026-09-11 학습 정리 — Unreal Engine 5에서 Quest 2 썸스틱 연속 이동 입력을 복구하는 과정

- 작성자: 김신정
- 주제: Unreal Engine 5 Enhanced Input · OpenXR · SteamVR · ALVR 환경에서 Quest 2 Touch 컨트롤러의 아날로그 썸스틱 입력을 VR Pawn 이동으로 연결하기
- 대상: `BP_XRPawn`, `IA_MoveStick`, `IMC_Move`, `DefaultInput.ini`, `IA_Turn`, `DA_Comfort_Default`
- 테스트 경로: Quest 2 → ALVR → SteamVR(OpenXR Runtime) → Unreal VR Preview

## 이번 학습의 결과 요약

| 구분 | 내용 |
| --- | --- |
| 한 일 | Quest 2에서 SteamVR까지는 동작하지만 Unreal VR Preview에서만 멈추던 왼쪽 썸스틱 이동을 단계별로 추적했다. |
| 문제 | `IA_MoveStick` 2D 입력 자체보다, `IMC_Move`가 런타임 기본 Mapping Context로 등록되지 않아 OpenXR/SteamVR 바인딩에 이동 액션이 생성되지 않았다. |
| 해결 | `DefaultInput.ini`에 `IMC_Move` 자동 등록을 복구하고, TESTPROJ 전용 SteamVR 생성 binding cache를 초기화한 뒤 ALVR → SteamVR → Unreal 순서로 재실행했다. |
| 완료 | SteamVR의 왼쪽 조이스틱 2D 축이 `IA_MoveStick`까지 전달되고, Quest 2 실기기에서 왼쪽 썸스틱 연속 이동을 확인했다. |

## 1. 목표

전시실 내부에서는 실제 걷기와 왼쪽 썸스틱 연속 이동을 함께 제공한다. 방과 방 사이의 전환은 포털 순간이동으로 분리한다.

이번 학습의 1차 목표는 **Quest 2 컨트롤러가 SteamVR에서는 인식되지만 Unreal VR Preview에서만 이동하지 않는 문제**를 입력 전달 단계별로 분리해 해결하는 것이었다.

## 2. 입력 경로를 나눠서 확인한 이유

VR 입력 문제는 한 화면에서 "스틱이 안 된다"고 보이지만, 실제 경로는 여러 단계다.

```text
Quest 2 Touch 컨트롤러
  → ALVR 에뮬레이션(Quest 2 Touch)
  → SteamVR/OpenXR 인터랙션 프로파일
  → SteamVR가 생성하는 앱별 binding JSON
  → Unreal Enhanced Input Mapping Context
  → Input Action
  → BP_XRPawn 이동 로직
```

SteamVR Home에서는 스틱이 동작하고 버튼도 Unreal에서 동작했으므로, 컨트롤러 하드웨어나 ALVR 연결 자체보다 **OpenXR 바인딩과 Unreal 입력 액션/매핑 컨텍스트**를 우선 확인했다.

## 3. 실제로 진행한 해결 절차

### 3-1. 컨트롤러 고장이 아닌지 먼저 분리

1. SteamVR Home에서 썸스틱 이동을 확인했다.
2. Unreal VR Preview에서 버튼·손 추적은 동작하는 것을 확인했다.
3. 따라서 Quest 2 컨트롤러, ALVR 연결, SteamVR의 기본 인식은 정상이고, **SteamVR → Unreal 입력 액션** 구간으로 범위를 좁혔다.

### 3-2. 성공했던 사본과 최신 작업본을 비교

작동했던 `vr-work` 사본과 최신 dev 기반 작업본을 비교했다. `BP_XRPawn`, `IA_MoveStick`, `IMC_Move` 에셋을 단순히 비교하는 데서 끝내지 않고, 런타임 입력 등록을 결정하는 `Config/DefaultInput.ini`도 확인했다.

그 결과 성공본에만 `IMC_Move` 자동 등록 설정이 있는 것을 발견했다.

### 3-3. Mapping Context 자동 등록 복구

최신 작업본의 `DefaultInput.ini`에 아래 줄을 복구했다.

```ini
+DefaultMappingContexts=(InputMappingContext="/Game/XRFramework/Input/IMC_Move.IMC_Move",Priority=100,bAddImmediately=True,bRegisterWithUserSettings=False)
```

이 설정은 게임 시작 시 Enhanced Input Subsystem에 `IMC_Move`를 추가한다. 등록된 Mapping Context 안의 `IA_MoveStick`이 있어야 OpenXR가 해당 액션을 인식하고 SteamVR도 앱별 입력 바인딩을 생성한다.

### 3-4. 기존 SteamVR 캐시를 새 설정으로 재생성

Unreal Editor와 SteamVR를 종료한 뒤, 아래 위치의 **TESTPROJ 전용** 생성 바인딩 파일만 백업·삭제했다.

```text
C:\Program Files (x86)\Steam\config\openxr\
system.generated.openxr.testproj.unrealeditor.exe_*_binding.json
```

그 뒤 반드시 `ALVR → SteamVR → Unreal VR Preview` 순서로 실행했다. SteamVR가 이전의 비어 있던 이동 액션 대신 새 `IMC_Move / IA_MoveStick` 바인딩을 생성하도록 하기 위해서다.

### 3-5. 생성된 바인딩과 실제 이동을 다시 검증

생성된 Oculus Touch binding JSON에서 아래 연결을 확인하고, Quest 2 실기기에서 왼쪽 스틱 연속 이동까지 확인했다.

```text
/user/hand/left/input/joystick
  → /actions/imc_move/in/ia_movestick
```

## 4. 핵심 원인: 2D 아날로그 입력과 Mapping Context 등록

처음에는 이동 액션이 축을 따로 다루는 방식으로 구성되어 있었다. SteamVR/OpenXR가 TESTPROJ용 바인딩을 생성할 때 이를 Quest 2의 2D 조이스틱 입력으로 안정적으로 해석하지 못하면 Unreal에는 이동값이 `(0, 0)`으로 들어온다.

해결에는 두 조건이 모두 필요했다.

1. 이동 액션 `IA_MoveStick`을 **Axis2D**로 두고, Quest 2 Touch의 2D 썸스틱 키를 사용한다.
2. 이동 매핑 컨텍스트 `IMC_Move`를 게임 시작부터 등록한다.

특히 성공한 사본과 최신 작업본을 비교했을 때, 최신 `Config/DefaultInput.ini`에 아래 설정이 빠져 있었다.

```ini
+DefaultMappingContexts=(InputMappingContext="/Game/XRFramework/Input/IMC_Move.IMC_Move",Priority=100,bAddImmediately=True,bRegisterWithUserSettings=False)
```

이 한 줄이 없으면 `IMC_Move`가 런타임에 등록되지 않고, SteamVR가 생성한 바인딩에도 `IA_MoveStick` 액션이 나타나지 않는다. 에셋 파일이 존재해도 입력은 동작하지 않는 이유다.

## 4. SteamVR 생성 바인딩 확인

SteamVR는 실행 중인 Unreal Editor 앱에 대해 PC 로컬 바인딩 파일을 생성한다.

```text
C:\Program Files (x86)\Steam\config\openxr\
system.generated.openxr.testproj.unrealeditor.exe_oculus_touch_1_binding.json
```

이 파일은 Git에 올리는 프로젝트 에셋이나 로그가 아니라, **해당 PC에서 SteamVR가 재생성하는 입력 캐시**다.

확인 결과, 이동 복구 뒤 생성된 Oculus Touch 바인딩에는 다음 연결이 들어갔다.

```text
/user/hand/left/input/joystick
  → /actions/imc_move/in/ia_movestick
```

따라서 왼쪽 컨트롤러의 아날로그 2D 입력이 `IMC_Move`와 `IA_MoveStick`까지 도달함을 확인했다.

바인딩이 과거 설정을 계속 쓰는 경우에는 Unreal Editor와 SteamVR를 종료한 뒤, **TESTPROJ 이름이 포함된 생성 binding JSON만** 백업·삭제하고 ALVR → SteamVR → Unreal 순서로 재실행한다. 이 캐시는 각 개발자의 로컬 환경에서만 초기화한다.

## 5. 왼쪽 스틱 연속 이동 결과

`IMC_Move` 등록, `IA_MoveStick` 2D 입력, SteamVR 바인딩 재생성 후 Quest 2 실기기에서 왼쪽 스틱 연속 이동이 확인됐다.

이 과정에서 배운 점은 다음과 같다.

- 버튼이 동작한다고 아날로그 축도 Unreal에 전달되는 것은 아니다.
- `Input Action` 에셋만 수정해도 충분하지 않고, `Input Mapping Context`가 실제로 활성화돼야 한다.
- Unreal `.uasset`는 이진 파일이므로 전체 `BP_XRPawn`을 다른 사본으로 덮어쓰면 포털·손 관련 변경과 충돌할 수 있다. 입력 에셋, 설정, 로컬 SteamVR 캐시를 분리해 원인을 확인해야 한다.

## 6. 오른쪽 스틱 회전 실험

오른쪽 스틱은 `IA_Turn`에 연결해 회전 방식을 실험했다.

- SteamVR Oculus Touch 바인딩에서 오른쪽 조이스틱 X축 → `IA_Turn` 연결을 확인했다.
- `IA_Turn`의 데드존과 발동 기준을 0.2로 낮춰 작은 축 입력도 인식하도록 조정했다.
- `DA_Comfort_Default`에는 연속 이동, 회전 모드, 회전 속도/각도 등 VR 편의 설정이 모여 있다.

다만 팀 결정 문서의 D-46은 전시실 내부 회전을 **헤드셋의 실제 물리 회전**으로 두고 스냅턴을 사용하지 않는다고 명시한다. 오른쪽 스틱 회전은 UX 실험 상태로 유지하며, 최종 반영 전 팀 합의와 실기기 재검증이 필요하다.

## 7. 협업 시 주의할 점

- `BP_XRPawn`의 `HandLeft`, `HandRight`, 모션 컨트롤러 컴포넌트 이름·구조는 다른 Blueprint가 참조할 수 있으므로 임의 변경하지 않는다.
- `BP_XRPawn.uasset`는 바이너리라 Git 자동 병합이 어렵다. 기능별로 작업 시점과 반영 범위를 공유하고, 필요하면 Git LFS 잠금을 사용한다.
- SteamVR의 `system.generated...binding.json`은 개발 PC별 캐시이므로 커밋하지 않는다.
- 팀 공유 에셋을 수정할 때는 `git lfs lock <경로>`로 해당 파일만 잠그고, 반영 완료 후 잠금을 해제한다.

## 8. 다음 확인 항목

1. 왼쪽 스틱의 전·후·좌·우 및 대각선 이동을 여러 차례 실기기에서 재검증한다.
2. 방 경계를 넘어가지 않도록 콜리전/이동 안전 영역을 검증한다.
3. 오른쪽 스틱 회전은 D-46 팀 결정과 사용성 테스트 결과를 반영해 유지 여부를 결정한다.
4. 포털 이동 뒤에도 `IMC_Move`가 활성 상태인지 통합 테스트한다.

## 9. 한 줄 회고

썸스틱은 버튼처럼 켜짐/꺼짐이 아니라 **방향과 세기를 동시에 보내는 아날로그 2D 축**이므로, `IA_MoveStick`을 2D 액션으로 두는 것만으로 끝나지 않고 `IMC_Move`를 런타임에 등록해 OpenXR·SteamVR 바인딩까지 생성되게 해야 Unreal 이동값이 실제로 전달된다는 것을 배웠다.
