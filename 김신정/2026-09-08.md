## 1. D-46이 요구하는 것

| 항목 | 이전(VR 템플릿 기본) | D-46 |
| --- | --- | --- |
| 이동 | 텔레포트 | 걸어다니듯 **연속 이동** |
| 회전 | 스냅 턴(우썸스틱) | **헤드셋을 돌린다** (스틱 회전 없음) |
| 멀미 대책 | — | 이동 가속 최소화, 이동 범위 제한, 비네트, 리허설 다인 검증 |

전시실이 10×11 m 단일 공간이라 물리 회전만으로 방향 전환이 되고, 시작 위치를 유물에서 2 m로 두면 관람 대부분이 제자리라 연속 이동 노출 시간이 짧다(`21.1.1`, `21.5`).

## 2. 데이터 모델 — `S_ComfortSettings`

컴포트 관련 값을 구조체 하나로 묶었다. 폰이 하드코딩하지 않고 이 값들을 읽어서 동작하게 한다.

| 필드 | 타입 | 기본값 | 용도 |
| --- | --- | --- | --- |
| `LocomotionMode` | `E_LocomotionMode` (Continuous/Teleport) | Continuous | 이동 방식 분기 |
| `TurnMode` | `E_TurnMode` (Physical/Smooth/Snap) | Physical | 회전 방식 분기 |
| `MoveSpeed` | float | 220 (cm/s) | 연속 이동 속도. 걷기보다 약간 느림 — 안정성 우선 시작점 |
| `bUseVignette` | bool | true | 이동 비네트 on/off |
| `VignetteStrength` | float | 0.7 | 비네트 세기 |
| `SmoothTurnRate` | float | 90 (°/s) | Smooth 회전 시 속도 |
| `SnapTurnAngle` | float | 30 (°) | Snap 회전 시 1회 각도 |

- `_Gameplay/Types/` 에 이넘 2개 + 구조체.
- `_Gameplay/Data/DA_Comfort_Default` = 위 기본값을 담은 데이터에셋. 실기 테스트 후 이 파일의 값만 바꿔서 튜닝한다.
- 데이터에셋 클래스는 `PrimaryDataAsset` 상속으로 만들었다(플레인 `UDataAsset`은 이 프로젝트에서 블루프린트 부모로 지정 불가). 폰이 이름으로 직접 로드하는 용도라 기능 차이는 없다.

## 3. `BP_XRPawn` 변경

### 3-1. BeginPlay에서 컴포트 로드 (4단계)

- 폰에 `Comfort`(구조체) 변수 + `ComfortData`(오브젝트 레퍼런스, 기본값 `DA_Comfort_Default`, Instance Editable) 추가.
- `BeginPlay`: `Get ComfortData → Get Settings → Set Comfort` 를 기존 BeginPlay 체인 **앞에** 삽입.
- 검증: PIE 실행 중 폰의 `Comfort`가 `Continuous / Physical / 220 / vignette on / 0.7 / 90 / 30` 으로 채워짐 확인.

### 3-2. 텔레포트 비활성 (5단계)

VR 템플릿의 텔레포트는 `IA_Move`의 exec 출력 3개가 각각 함수로 간다:

```
IA_Move.Started    → StartTeleportTrace   (조준선 시작)
IA_Move.Triggered  → TeleportTrace        (매 프레임 조준선 갱신)
IA_Move.Completed  → EndTeleportTrace      (놓으면 이동 실행)
```

세 경로 각각 앞에 `Branch`를 넣고, 조건을 `Comfort.LocomotionMode == Teleport` 로 건다.
- True → 기존 텔레포트 함수 (그대로 유지)
- False → 아무것도 안 함

기본값이 `Continuous`라 조건이 항상 false → 텔레포트가 실행되지 않는다. 기존 노드는 지우지 않고 분기로 우회만 했다(되돌릴 수 있게, `21.5` 및 안정성 규칙).

### 3-3. 스냅 턴 비활성 (6단계)

`IA_Turn.Triggered → SnapTurn` 사이에 `Branch(Comfort.TurnMode == Snap)` 삽입. 5단계와 같은 패턴. 기본값이 `Physical`이라 스냅 턴이 호출되지 않는다. `Get Comfort → Break S_ComfortSettings` 노드는 5단계 것을 재사용.

## 4. 배운 점 / 판단

- **기존 노드를 지우지 않고 enum 분기로 우회**하는 방식이 안정성에 유리하다. 한 단계 = 한 커밋 = 되돌릴 수 있는 상태. 5·6단계가 문제되면 `DA_Comfort_Default`의 값만 바꿔도 원래(텔레포트/스냅턴) 동작으로 되돌아온다.
- 컴포트 값을 폰이 아니라 데이터에셋에 두니 실기 튜닝이 파일 한 개 편집으로 끝난다. 7·8단계의 속도·데드존도 이 구조에 얹는다.
- 회전을 스틱에서 빼는 건 코드보다 합의가 먼저다 — D-46이 스냅을 명시적으로 폐기했으므로 스냅 로직은 `TurnMode == Snap` 분기 안에만 남겨 두고 기본 경로에서 제외.
- 퍼시스턴트 레벨(`L_Museum.umap`)은 여러 명이 건드리는 파일이라(`CONTRIBUTING` 10절), 서브레벨을 실제로 채우는 9·12단계와 묶어서 반영하기로 하고 이번 커밋에서는 뺐다.

## 6. 다음 행동

1. VR 프리뷰로 실제 확인 — 우썸스틱 밀어도 텔레포트/회전 안 되는지.
2. **7단계 연속 이동**: `IA_Move.Triggered` 의 `Branch` False 경로에서 —
   - 입력 Vector2D → 크기 < 0.15 데드존
   - 카메라 월드 회전에서 **Yaw만** 꺼내 Forward/Right 벡터
   - `Dir = Forward*Y + Right*X`, Z=0, Normalize
   - `AddActorWorldOffset(Dir * MoveSpeed * DeltaSeconds, sweep=true)`
3. **8단계**: 데드존/속도 상한 확정(가속 0 — 관성은 멀미 요인).
4. 9단계(이동 범위 벽)·12단계(PlayerStart)와 함께 `L_Museum` / `L_Museum_Gameplay` 반영.
