## 6. 이동 모델 — 팀 내부 협의로 확정

| 상황 | 방식 |
| --- | --- |
| 입장 | 메인 홀 스폰 |
| 홀 → 전시실 / 전시실 ↔ 전시실 | 포털 순간이동 |
| 전시실 내부 | 실제 걷기 + **컨트롤러 조이스틱** (조이스틱만) |
| 회전 | 헤드셋 물리 회전 (스냅 없음) |
| 손 추적 | 이동 아님 — 관찰·근접 UI용 |

- 중간에 "손 추적 모드는 방 안에서 핀치 텔레포트"를 넣었다가, 팀 확인 결과 **조이스틱 전용**으로 되돌렸다. `docs/DECISIONS.md` D-46 커밋 2개 + revert 1개로 끝. **블루프린트로 만들었으면 훨씬 비쌌다** — 문서에서 먼저 정하는 게 싸다는 걸 체감.

- **계획(문서)과 결정(`DECISIONS.md`)이 어긋나면 결정이 소스 오브 트루스.** 계획을 결정에 맞춘다.

- **며칠에 한 번 `dev`를 브랜치로 당기면** 나중 MR이 깔끔.
- 다른 사람 코드가 내 폰의 컴포넌트를 이름으로 참조하니 **함부로 이름·구조 안 바꾼다**.
